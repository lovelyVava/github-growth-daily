8. **综合排序**：综合 24h/7d Star、相对增速、Fork、提交、讨论质量、许可证与部署风险，不是 GitHub Trending 原始顺序。

## 项目分析

### 1. obra/superpowers

- **主要用途**：用可组合 Skills 为编码 Agent 建立从头脑风暴、规划、实现、测试到评审的软件开发方法论。
- **技术栈**：Shell、Markdown/Agent Skills、插件命令、测试脚本及多客户端适配；MIT。
- **近期增长及口径**：约 **+2,028 Star/24h**，11 月 17 日以来快照净增约 +3,072；当前 322,298 Star、28,644 Fork，Fork +67，由第五升至第一。
- **贡献与讨论**：近七日默认分支 0 次提交、16 个新议题；讨论涉及预演失败、子 Agent 修复循环、提示缓存与 OpenCode 隐藏运行。
- **爆发原因（推断）**：技能化开发纪律适配多个编码 Agent，传播门槛低；在 Agent 用户扩张期，成熟方法论容易反复进入热榜。
- **亮点**：把计划、测试、审查和任务边界变成可复用流程，强调工程约束而不只是生成速度。
- **潜在风险**：涨星与零提交明显背离，短期热度主要由传播驱动；不同客户端的提示注入和上下文压缩可能造成行为漂移。
- **适合人群与关注程度**：个人开发者、团队规范、Skill 设计与编码 Agent 研究者；**★★★☆☆**。

### 2. elementalsouls/Claude-BugHunter

- **主要用途**：为 Claude Code 提供漏洞挖掘与外部红队 Skill 包，覆盖 24 类漏洞、企业身份和基础设施攻击矩阵。
- **技术栈**：Python、Shell/PowerShell、Claude Code Skills、漏洞模式库、命令行引擎与报告模板；MIT。
- **近期增长及口径**：约 **+1,349 Star/24h**，11 月 14 日以来快照净增约 +7,127；当前 12,958 Star、1,619 Fork，重新上榜第二。
- **贡献与讨论**：近七日约 80 次提交、10 个新议题；问题集中在误判、报告泄露本机用户名、Windows Unicode 与 PowerShell 兼容。
- **爆发原因（推断）**：将大量已披露漏洞模式包装成 Agent 可调用技能，契合安全团队希望快速建立侦察、验证和报告工作流的需求。
- **亮点**：漏洞类别覆盖广，提供命令、矩阵和报告模式，适合形成结构化检查清单。
- **潜在风险**：具备攻击性能力，只能在明确授权范围内使用；规则数量不等于准确率，误报、漏报、敏感信息写入日志及平台封禁风险都需要控制。
- **适合人群与关注程度**：经授权的渗透测试、Bug Bounty、AppSec 与红队研究人员；**★★★★☆**。

### 4. google-research/paper-orchestra

- **技术栈**：Python、多 Agent 编排、LaTeX、Semantic Scholar、LLM Provider API 与绘图模板；Apache-2.0。
- **近期增长及口径**：Python 日榜约 **+1,196 Star/24h**，11 月 16 日以来快照净增约 +3,789；当前 5,159 Star、646 Fork，Fork +81，由第一降至第四。

### 5. HKUDS/CLI-Anything

- **主要用途**：为桌面软件和专业工具生成统一 CLI，使 Agent 能以命令方式调用原本只有 GUI 的能力。
- **技术栈**：Python、Click/CLI、软件适配器、测试与文档生成、Hub 包管理；Apache-2.0。
- **近期增长及口径**：约 **+898 Star/24h**；7 天直接值缺失，11 月 18 日以来快照净增约 +1,149。当前 60,776 Star、5,514 Fork，新上榜第五。
- **贡献与讨论**：近七日默认分支 0 次提交、10 个新议题；反馈涉及 3MF 几何、LibreOffice 导入、模型单位与数值边界。
- **爆发原因（推断）**：Agent 操作 GUI 易受布局和视觉误差影响，把软件能力转成确定性 CLI 可以提高可重复性和自动化密度。
- **亮点**：目标通用，适配器可把设计、文档、3D 等工具纳入 Agent 工作流，并便于测试和审计。
- **潜在风险**：最近代码推送停在 9 月且七日零提交，传播与维护节奏脱节；自动生成 CLI 很难完整覆盖 GUI 语义，文件覆盖和数值边界需沙箱验证。
- **适合人群与关注程度**：Agent Tool、桌面自动化、CLI 设计和专业软件集成团队；**★★★☆☆**。

### 6. firecrawl/firecrawl

- **主要用途**：为 Agent 提供搜索、抓取、结构化抽取、浏览器交互及 550 多个数据源的统一知识入口。
- **技术栈**：TypeScript/Node.js、爬虫与浏览器、队列、PDF/HTML 转 Markdown、REST API、SDK 与自托管组件；AGPL-3.0。
- **近期增长及口径**：约 **+825 Star/24h**；7 天直接值缺失，11 月 19 日以来快照净增约 +474。当前 204,523 Star、10,719 Fork，新上榜第六。
- **贡献与讨论**：近七日约 81 次提交、10 个新议题；问题聚焦阿拉伯语 PDF、扫描页判断、Sitemap 深度、重定向重复和私网目标错误返回成功。
- **爆发原因（推断）**：Agent 的瓶颈正从模型本身转向新鲜、可解析且可引用的数据摄取；统一搜索、抓取和 Provider 接口具有直接平台价值。
- **亮点**：覆盖网页、PDF、浏览器与结构化抽取，并同时提供托管服务和开源自托管路径。
- **潜在风险**：AGPL 对网络服务部署有源码义务；抓取受 robots、版权、站点条款和隐私约束，私网地址防护、SSRF、队列成本与数据保留策略必须审计。
- **适合人群与关注程度**：RAG、Agent 知识摄取、搜索、数据管道和自托管平台团队；**★★★★★**。

- **近期增长及口径**：24 小时直接值缺失，相邻总 Star 快照净增约 +112；约 **+4,492 Star/7d**。当前 54,471 Star、4,511 Fork，Fork +24，由第十升至第七。

- **亮点**：模型小、链路完整，便于观察数据、Tokenizer、训练、对齐和推理之间的真实关系。
- **潜在风险**：教学模型效果不能外推到大模型生产系统；数据许可、复现实验、依赖版本和硬件差异需要单独核验。
- **适合人群与关注程度**：LLM 初学者、课程、训练流程研究与低成本实验团队；**★★★★☆**。

## 当天技术趋势

1. **Skill 从内容包走向完整工程层**：`Superpowers` 提供方法论，`Claude-BugHunter` 提供安全领域知识，`stitch-skills` 提供设计工作流；增长很快，但更新频率和权限风险差异巨大。
2. **Agent 的数据入口成为核心基础设施**：`Firecrawl` 与 `last30days-skill` 分别代表通用网页摄取和近期社区信号，两者共同说明“获取新鲜、可引用数据”已成为模型之外的关键竞争点。
3. **专业工具正在被 CLI/MCP 化**：`CLI-Anything` 和 `ffmpeg-skill` 都把复杂软件能力变成可测试工具；真正的工程难点在文件权限、参数边界和输出验证。
4. **企业落地仍围绕质量门禁**：`Open Code Review` 的七日增长与持续提交说明，代码审查、失败语义和可审计评论比单纯生成更多代码更接近企业付费价值。
5. **热度与维护度继续分化**：`Superpowers`、`CLI-Anything` 日增很高但七日零提交；`ffmpeg-skill` 日增直接值缺失，却有 ≥100 次提交和 +2,998 周增。只看 Star 会得出相反结论。

## 最值得深入研究的 3 个项目

1. **[Firecrawl](https://github.com/firecrawl/firecrawl)**：81 次周提交与强日增同时存在，直接命中 RAG/Agent 的网页、PDF、浏览器和数据源摄取问题；值得重点研究自托管、SSRF 防护、数据授权与结构化抽取质量。
2. **[Open Code Review](https://github.com/alibaba/open-code-review)**：约 +4,492 Star/7d，且有持续提交和真实失败语义问题，特别适合研究如何把 LLM Review 变成可信 CI 门禁。
3. **[ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill)**：提交达到读取上限、议题密集，能观察机器可读工具契约如何处理时间基、编解码器和参数边界，是本地多媒体 Agent 的高价值样本。
