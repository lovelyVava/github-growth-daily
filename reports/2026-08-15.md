## 数据口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 日榜页面在观察时刻显示的 `stars today`，为滚动窗口近似值，不等同于自然日 00:00—24:00 的精确差值。
2. **7 天新增 Star**：项目出现在周榜时使用 `stars this week`；未进入周榜可见范围时标记“缺失”。对连续两期项目，报告可给出两个相邻日榜窗口之和作为近两日下限估算，但它不是完整 7 天值。
3. **Fork**：GitHub Trending 只稳定展示累计 Fork，不提供 24 小时或 7 天 Fork 增量。报告列出观察时刻累计值；**Fork 增量统一标记缺失**。
4. **贡献者活跃度**：公开仓库页可稳定读取累计提交数、开放 Issue/PR 和 Discussions 是否启用，但无法无认证地稳定取得所有项目“过去 24 小时新增贡献者”同口径数据。因此这些指标仅作活跃度代理，不等于独立贡献者人数。
5. **讨论热度**：以 Discussions 是否开放、开放 Issue/PR 规模及近期仓库更新作为代理；无法可靠取得统一的 24 小时讨论新增量时明确标记缺失。
6. 数据会在抓取后继续变化，表中累计 Star/Fork 与 Trending 的 `stars today` 可能有数分钟时间差。

## 项目分析

### 1. [diagram-design](https://github.com/cathrynlavery/diagram-design)｜持续热门：1 → 1

- **主要用途**：为 Claude Code、Codex、Pi 等编码 Agent 提供编辑风格的图表设计 Skill，可从需求或 Mermaid/draw.io 源生成架构图、流程图、时间线、状态机等 HTML + SVG 图表。
- **技术栈**：HTML、CSS、SVG、Markdown、Agent Skills/插件目录结构；静态输出默认不依赖构建步骤。MIT License。
- **近期增长**：24h 约 **+3,651 Star**，累计约 **17,177 Star / 1,023 Fork**；相对日增 **21.25%**。周榜精确值缺失；两期相邻日榜合计约 **8,155**，仅作近两日下限估算。24h/7d Fork 增量缺失。
- **活跃与讨论代理**：约 **100 次提交**、2 个开放 Issue、10 个开放 PR；未启用 Discussions。提交历史仍短，但 PR 相对仓库年龄较活跃。
- **爆发原因**：把“Agent 能生成图，但视觉质量不稳定”的痛点打包成可安装 Skill；同时支持 Claude Code 与 Codex，且成果可直接在浏览器打开，传播门槛很低。
- **亮点**：27 类编辑风格图表、品牌配色配置、静态优先、支持导入 Mermaid/draw.io；项目把视觉约束写进 Agent 工作流，具有较强可复用性。
- **潜在风险**：热度高度集中且连续两日爆发，短期回落概率高；输出质量依赖提示与内容结构；在团队品牌和无障碍场景仍需人工验收。
- **适合人群**：技术写作者、架构师、独立开发者、经常用编码 Agent 产出说明文档的团队。
- **值得关注程度**：★★★★★。增长最强、落地直接，但应观察热度能否转为稳定贡献者生态。

### 5. [needle](https://github.com/cactus-compute/needle)｜持续热门：3 → 5

- **主要用途**：面向手机、可穿戴、智能家居和机器人等小设备的 45M 参数工具调用模型；单文件约 14MB，可离线运行和进行 LoRA 微调。
- **技术栈**：Python 包、自研推理引擎、CQ2-bit 量化、结构化 JSON/语法约束、LoRA。MIT License。
- **近期增长**：24h 约 **+661 Star**，7d 约 **+1,377 Star**；累计约 **5,583 Star / 372 Fork**，相对日增 **11.84%**。日增较上一期约 **-13.9%**；Fork 增量缺失。

- **爆发原因**：端侧 Agent 需要低内存、离线、结构化输出和可控置信度；14MB 的明确指标非常具传播力，也贴合隐私和低延迟需求。
- **亮点**：模型极小、离线推理、工具调用直接返回结构化数据、置信度门控，适合做“低风险动作自动执行、高风险动作升级”的边缘系统。
- **潜在风险**：45M 参数能力边界明显，复杂推理与多语言泛化需独立评测；基准结果由项目方提供，生产使用前应做设备端延迟、功耗、误调用和拒答测试。
- **适合人群**：嵌入式/IoT/机器人开发者、隐私敏感应用、希望学习模型量化和端侧工具调用的团队。
- **值得关注程度**：★★★★★。体积、部署形态与 Agent 工具调用结合独特，研究价值高。

## 当天技术趋势

### 1. Agent 工程从“能力插件”走向“规范与上下文基础设施”

`spec-kit` 把需求、规范、计划和任务变成 Agent 可执行流程；`semantica` 管理长期上下文、知识关系和决策溯源；`holaOS`、`macro` 则争夺统一工作空间与共享记忆入口。热点重心已从“再做一个 Agent”转向“让多个 Agent 可控、可复用、可审计地协作”。

### 2. Skills 仍热，但市场开始筛选可直接交付成果的技能

`diagram-design` 连续第一，说明用户愿意为可见、可交付、低配置的 Agent Skill 投票。相比单纯的 Prompt 集合，带资产、样式规则、安装机制和跨 Agent 兼容的技能更容易持续增长。

### 3. 本地 AI 分成两条路线：极小模型与重型创作工具

`needle` 代表 14MB 端侧工具调用模型，追求离线、低延迟和确定性；`unsloth`、`modly` 则利用本地 GPU 完成模型训练或 3D 资产生成。两者共同驱动力是隐私、成本可控和摆脱云端队列，但硬件兼容与部署体验仍是关键门槛。

### 4. 成熟 RAG 平台仍有需求，但增长叙事已转向“上下文层”

`ragflow` 继续稳定上榜，表明完整 RAG 平台仍是企业刚需；而 `semantica` 的更快增长显示市场正在寻找知识关系、来源追踪、记忆和治理的一体化上下文层。

### 5. 安全工具的传播热度不等于维护活跃度

`holehe` 24 小时上榜但主分支更新较旧，提醒我们必须把 Star 动量与工程活跃度分开判断；对安全工具还要额外考虑合法授权、隐私和站点条款。

## 最值得深入研究的 3 个项目

### 1. [semantica](https://github.com/semantica-agi/semantica)

**理由**：同时具备 24h 高增、7d 高增、2,000+ 提交、开放 Discussions 和明确基础设施价值。它不是单一 Agent 应用，而是解决长期记忆、知识关系、来源追踪与治理问题，适合做企业级 AI 架构研究对象。

**建议研究路径**：先跑最小 GraphRAG/Memory 示例，再验证数据模型、检索质量、来源追踪、权限隔离和在真实数据量下的性能；与传统向量库 + RAG 管道做同数据集对照。

### 2. [spec-kit](https://github.com/github/spec-kit)

**理由**：Agent 编码质量越来越取决于规范和流程，而不是单次提示。该项目适合用来建立“需求澄清—计划—实现—审查”的统一入口，也能作为评估 AI 代码审查前置质量的基线。

**建议研究路径**：选择一个中等规模功能，分别用自由提示和 Spec Kit 流程实现，对比返工次数、PR 大小、测试覆盖、审查意见数量和需求偏离率；避免一开始全仓推广。

### 3. [needle](https://github.com/cactus-compute/needle)

**理由**：14MB、离线、结构化工具调用和置信度门控的组合很少见，代表端侧 Agent 的实用方向。它也提供了研究超小模型、量化、约束解码和边缘风险控制的紧凑样本。

**建议研究路径**：在目标手机/树莓派/嵌入式设备上测首 Token 延迟、内存、功耗、工具选择准确率和误调用率；针对复杂、多语言和异常输入建立独立评测，不只采用仓库自报基准。

## 结论

今日榜单总热度与上一期基本持平，但结构更加多元。`diagram-design` 仍是最强流量中心，`semantica` 则是增长质量最佳项目；`spec-kit` 的上榜进一步确认“规范驱动的 Agent 工程”正在成为主线。本地 AI 继续向两个方向扩展：一端是 `needle` 的极小端侧模型，另一端是 `unsloth`、`modly` 的本地 GPU 工作流。对高 Star 项目仍应结合提交、Issue/PR、Discussions、许可证与安全边界判断，避免把短期传播直接等同于工程成熟度。
