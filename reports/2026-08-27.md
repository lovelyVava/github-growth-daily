## 统计口径与限制

1. **24 小时新增 Star**：直接采用 GitHub Trending 日榜的 “stars today”。它是滚动窗口指标，抓取时间差会使其与 API 当前累计 Star 无法简单相加校验。
2. **7 天新增 Star**：优先采用 GitHub Trending 周榜的 “stars this week”。未进入周榜的项目明确标为“缺失”，不使用累计 Star 反推。
3. **Fork 变化**：仅对 8 月 26 日报告中已有 API 快照的同项目，计算两次快照差；新上榜或重新上榜项目不伪造 24 小时 Fork 增量。
4. **提交与贡献者**：统计 2026-08-20 00:00 UTC 起约 7 天内 GitHub Commits API 返回的数据；最多读取 100 条提交，因此“≥100”为截断下限。独立作者按 GitHub 登录名或提交者标识去重，是近似值。
5. **Issue/PR 活跃度**：统计同一窗口内新建的 Issue 和 PR。它衡量讨论与协作流量，不等同于已解决问题数量或代码质量。
6. **Discussions**：GitHub 没有便于跨仓库统一比较的公开增量口径，本报告以新 Issue/PR、榜单连续性和仓库社区入口作为代理；无法量化时标为缺失。
7. **爆发原因**：根据 README、近期活动和榜单位置作出的分析判断，不代表项目维护者的官方结论。

## 项目分析

### 1. freestylefly/awesome-gpt-image-2

- **主要用途**：将 GPT Image 2 的提示词组织成可复用的“Prompt as Code”模板、案例与 Skills，面向批量化、可复现的图像生成工作流。
- **技术栈**：JavaScript、Markdown/提示词模板；MIT License。
- **近期增长**：日榜约 **+4,044 Star**，周榜约 **+5,329 Star**；相对日增约 **23.5%**。API 当前 21,264 Star、2,123 Fork；较昨日 Fork 快照约 **+301**。
- **活跃度与口径**：近 7 天 12 次提交、约 1 名独立作者、3 个新 Issue、4 个新 PR。Star/Fork 传播远高于提交和讨论增长，属于明显的内容与示例驱动爆发。
- **爆发原因**：GPT Image 2 热点、530+ 可直观看效果的案例、20+ 模板和一键复用式 Skills 共同降低了传播与试用门槛。
- **亮点**：案例覆盖面广；把提示词从一次性文本提升为可组织、可复制的工程素材；适合快速建立团队视觉生成规范。
- **潜在风险**：效果与特定模型版本强绑定；示例数量不等于系统评测；训练素材、风格模仿和生成内容的版权合规仍需单独审查。
- **适合人群**：AI 视觉设计、游戏美术原型、营销内容、提示词工程和图像工作流团队。
- **值得关注程度**：**★★★★★**。热度极强、上手价值高，但更应视为方法与素材库，而非稳定 API 或质量保证。

### 5. tt-a1i/archify

- **主要用途**：让 Agent 把代码库或系统描述转为可交互、可分享、可验证的架构图、工作流图、时序图、数据流图和生命周期图。
- **技术栈**：HTML/JavaScript、Node.js CLI、typed JSON IR、Agent Skill；MIT License。
- **近期增长**：日榜约 **+1,002 Star**；周榜数据缺失；相对日增约 **5.94%**。API 当前 17,868 Star、1,240 Fork；新上榜，24 小时 Fork 增量缺失。
- **活跃度与口径**：近 7 天 15 次提交、约 6 名独立作者、17 个新 Issue、18 个新 PR；同时具备增长、迭代和讨论。
- **爆发原因**：传统 Mermaid 或自动布局难以兼顾信息层级、审美和可信性；Archify 用类型化中间表示、确定性校验、Last-good 预览和多格式导出，回应了 Agent 生成图“好看但不可靠”的痛点。
- **亮点**：自包含 HTML；支持 PNG、SVG、WebM 与分享卡导出；校验失败返回机器可读修复凭据；可比较 Before/Delta/After 架构变更，并选择性绑定 Git 修订版本的源码证据。
- **潜在风险**：验证的是“已写入图中的事实与结构”，不是线上运行时真相；源代码分析仍可能遗漏动态依赖；分享自包含文件前要检查是否暴露内部拓扑、路径或信任边界。它也明确不是通用绘图编辑器。
- **适合人群**：架构师、代码审查与研发效能团队、需要图像辅助理解复杂系统的学习者，以及正在建设 Agent 证据链的团队。
- **值得关注程度**：**★★★★★**。把视觉表达、可复现 IR、校验和代码证据连在一起，对 Open Code Review 的架构变更审查尤其有借鉴价值。

- **潜在风险**：第三方插件会放大供应链、权限滥用和提示注入风险；官方组织镜像不等于每个插件都适合企业环境，仍需来源验证、锁版本和准入审计。
- **适合人群**：Claude Code/Cowork 用户、插件作者、企业 Agent 平台和代码审查安全团队。
- **值得关注程度**：**★★★★★**。相对增速和生态意义都很高，尤其适合研究插件权限声明、审核、撤回与企业白名单机制。

### 10. tinyhumansai/openhuman

- **主要用途**：本地优先的个人 AI 系统，组合长期记忆、Agent 编排、深度研究和个人工作流。
- **技术栈**：Rust 为主；GPL-3.0 License。

- **亮点**：记忆、编排和研究一体化；本地优先；工程迭代快速，适合观察个人 Agent OS 的数据模型。

## 今日技术趋势

1. **Agent 输出从“能生成”走向“可验证、可交付”**：`archify` 用类型化 IR、确定性校验、修复凭据和源码修订证据解决架构图可信度问题。这类“生成物 + 验证器 + 证据”结构很适合迁移到代码审查。
2. **垂直 Agent 工作流开始胜过通用聊天入口**：`ai-job-search` 把求职拆成画像、搜索、评分、写作、审稿和面试准备；价值来自流程和检查点，而不是单次回答。
3. **Skills 与插件正在成为 Agent 的包管理层**：`ponytail`、`archify`、`claude-plugins-community` 说明能力越来越多地以可安装组件传播。随之而来的关键问题是版本锁定、权限声明、来源签名和撤回机制。
4. **本地知识与长期记忆持续升温**：`claude-obsidian` 和 `openhuman` 分别从可追溯 Markdown 知识库、个人 Agent OS 切入；数据所有权、引用证据、写入事务和备份恢复成为核心差异。

## 最值得深入研究的 3 个项目

### 1. tt-a1i/archify

**理由**：它不是单纯让 Agent 画得更漂亮，而是把架构事实放入 typed JSON IR，经过布局与结构校验后再原子交付，并可绑定特定 Git 修订的源码证据。对于正在改造的 Open Code Review，可以借鉴为“提交前生成架构 Delta → 校验事实与信任边界 → 在 MR 中附图和机器凭据”的证据链。

**建议验证**：对真实多模块仓库的动态依赖召回率；Before/Delta/After 与 Git diff 的一致性；证据路径在重命名后的稳定性；敏感内部拓扑的脱敏；是否能把验证结果转成 GitLab MR 评论。

### 2. AgriciDaniel/claude-obsidian

**理由**：它与现有 Obsidian 学习 Vault 直接匹配，也切中了 RAG 幻觉治理的关键：原始资料不丢、声明必须回到来源、写入过程可控。它比“让 Agent 自动整理笔记”更值得研究的，是 claim/source ledger 和单写入者事务模型。

**建议验证**：中文长文与源码笔记的引用粒度；概念卡片如何回链原文；错误摘要如何撤回和重建；安卓端 Syncthing 同步冲突；将 Kimi K3 每日学习文档导入后的检索准确率与重复内容控制。

### 3. anthropics/claude-plugins-community

**理由**：Agent 插件市场会同时放大能力分发和供应链风险。对企业代码审查系统而言，最值得借鉴的不是插件数量，而是插件元数据、来源、版本、权限和下架流程应该如何进入组织准入策略。

**建议验证**：插件是否声明文件、网络、命令和外部服务权限；是否支持锁版本与校验哈希；更新和撤回如何通知；如何检测恶意提示、依赖投毒与越权工具调用；能否形成公司内网白名单镜像。
