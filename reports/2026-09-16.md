## 统计口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 日榜的 `stars today`，这是滚动窗口，不等于自然日或相邻累计快照差；页面顺序不严格按该值排序，本报告按数值重新排序。
2. **7 天新增 Star**：采用周榜的 `stars this week`。只有公开周榜直接展示的数值才写入；未进入周榜的项目标为“缺失”，不从累计 Star 反推。
3. **当前 Star/Fork**：采用 2026-09-16 08:02–08:14 的 GitHub 页面/API 快照；不同接口抓取时间存在分钟级差异。
4. **Fork 变化**：仅对连续进入前十的项目比较 9 月 15 日与 9 月 16 日相邻快照；新上榜或重新上榜项目不估算 24 小时 Fork 变化。
5. **工程活跃度**：统计 2026-09-09 00:00 UTC 起约 7 天的默认分支提交，单仓最多读取 100 条；触及上限写作“≥100”。
6. **贡献者活跃度**：按提交记录中的 GitHub 账号或作者邮箱去重估算，可能拆分同一人的多个身份或包含机器人；截断仓库写作下限，不等同累计 Contributors。
7. **讨论热度**：统计同一窗口新建 Issue，排除 PR。Issue 可能由机器人、模板、自动关闭策略或集中投稿产生，数量不等于有效人工讨论。
8. **许可证识别**：按 GitHub API 与根许可证文件判断；模型、插件、数据和下载内容仍可能保留独立条款。
9. **爆发原因**：根据 README、近期提交与榜单表现作分析推断，不代表维护者官方结论。

## 项目分析

### 1. alibaba/open-code-review

- **主要用途**：对工作区、分支、提交或完整目录进行 AI 代码审查，以确定性管线控制文件覆盖、规则匹配和评论位置，以 Agent 完成语义判断。
- **技术栈**：Go、Git、文件筛选与分组、隔离子任务、位置校正、反思模块、OpenAI/Anthropic 兼容模型、MCP、CLI、Agent Skills 与 CI/CD；Apache-2.0。
- **近期增长**：日榜约 **+2,756 Star**、周榜约 **+5,169 Star**；相对日增约 **10.7%**。当前 28,494 Star、2,043 Fork；较上期 Fork 约 **+183**，排名上升 2 位。
- **贡献与讨论**：近 7 天约 34 次提交、23 个作者身份、31 个新 Issue，协作广度为本期最高。最新提交修复 `code_search`/`code_comment` 路径规范化与路径穿越绕过，并保护分环境 `.env`。
- **爆发原因**：企业级规则、全量 Scan、Delegation、Session 恢复、GitLab CI 和本地模型兼容共同回应“Agent 审查必须可控、可追踪”的需求；安全修复强化了可信度。
- **亮点**：工程逻辑保证文件覆盖和行级定位；背景文件、路径规则、JSON 输出和可恢复会话适合内网落地；安全问题能被快速合并修正。
- **潜在风险**：官方基准偏高 Precision、较低 Recall，仍会漏报；路径、忽略列表、规则或背景文件配置错误会造成系统性盲区；外部模型可能接触源码；需要 Git ≥2.41。
- **适合人群**：内网 GitLab、提交前扫描、MR 自动评论、本地 `/v1` 模型和需要 `background.md`/`rules.json` 的研发团队。
- **值得关注程度**：**★★★★★**。增长、贡献者广度和实际安全加固都强，与现有 OCR 改造直接相关。

### 2. debpalash/VoiceStudio

- **主要用途**：本地完成声音克隆与设计、视频配音、听写、转录、故事和有声书生成，定位为自托管 ElevenLabs 替代方案。
- **技术栈**：Python 服务、Electron 桌面应用与旧 Tauri v2/Rust 路径、Web UI，多种 TTS/ASR 引擎；CUDA、Apple MPS/MLX、Linux ROCm、CPU 和远程 Worker；AGPL-3.0。
- **近期增长**：日榜约 **+2,072 Star**；周榜值缺失；相对日增约 **7.2%**。当前 30,912 Star、3,696 Fork；较上期 Fork约 **+148**，排名下降 1 位。
- **贡献与讨论**：近 7 天提交 **≥100**、作者身份 **≥2**、新 Issue 108；提交量高但作者集中，近期主要推进 Electron 桌面应用和运行时隔离。
- **爆发原因**：本地隐私、无订阅、646 种语言目录与克隆/转录/配音一体化持续吸引创作者。
- **亮点**：多引擎可切换、长音频工作流完整、远程 Worker 可把前端与算力分离。
- **潜在风险**：Beta 与桌面架构迁移可能破坏兼容；模型许可证各异；声音克隆涉及授权和冒充风险。RX 9070 XT 在 Windows 上仍主要走 CPU，官方 ROCm 加速限 Linux。
- **适合人群**：本地语音、多语言内容、配音/听写原型，以及愿意在 Linux 验证 AMD ROCm 的开发者。
- **值得关注程度**：**★★★★★**。增长强，但应把高提交量、低作者集中度和模型许可纳入风险评估。

### 3. JustVugg/colibri

- **主要用途**：把 VRAM、RAM 与 NVMe 作为统一层级，按路由流式加载 MoE 专家，使消费级或异构硬件运行超大模型。
- **技术栈**：纯 C、异步 I/O、专家 LRU/热缓存、CPU/CUDA/Metal/Vulkan、MLA KV 压缩、MTP/语法推测解码；Apache-2.0。
- **近期增长**：日榜约 **+2,026 Star**、周榜约 **+6,095 Star**；相对日增约 **6.4%**。当前 33,797 Star、3,541 Fork；较上期 Fork约 **+156**，排名下降 1 位。

- **爆发原因**：Kimi K3、Qwen3.8 等超大 MoE 的本地运行想象与 AMD RDNA4 Vulkan 支持继续带来传播。
- **亮点**：不静默改变精度和路由语义；按专家热度做内存放置；公开端到端基准与负结果。
- **潜在风险**：低内存能启动不等于可交互；Kimi K3 仍需约 1.6 TB 存储，SSD 随机读取和 RAM 带宽会成为瓶颈；RX 9070 XT 的实际 Vulkan 吞吐必须本机复现。
- **适合人群**：MoE、I/O 调度、本地推理、AMD GPU/Vulkan 和 Kimi K3 架构研究者。
- **值得关注程度**：**★★★★★**。对现有硬件和学习方向高度相关，但应先用较小 MoE 做基线。

4. **成熟工具靠真实维护重新上榜**：`Ghidra` 的 75 次提交和 `BrewUI` 的 43 次提交说明，工程活动能与短期涨星同时出现；这类项目的增长质量通常高于只有传播、没有代码变化的仓库。
5. **Agent Harness 的权限和供应链成为核心问题**：`pi` 明确不提供内置权限系统，却在依赖锁定和构建可复现上投入较多；宿主、沙箱和技能包需要分别建立信任边界。
6. **高 Issue 数必须解释生成机制**：`pi` 的新贡献者自动关闭策略、模板和机器人会放大计数；讨论热度应结合作者、提交与 Issue 内容，而不是把数量直接当社区质量。
