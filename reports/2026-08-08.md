### 1. [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)｜新上榜

- **主要用途**：面向代码与长时任务的自改进 RLM（递归语言模型）Agent。它把超长上下文作为可查询变量，通过子 Agent、Python 技能、后台守护进程和持续目标管理推进工作。
- **技术栈**：TypeScript 主体，配套 Python/IPython 执行环境；MIT License。
- **近期增长**：24h 新增 **2,271 Star**，当前约 6,306 Star、503 Fork；相对日增约 **36.0%**。GitHub 周榜未给出其精确周增，故 7 日数据标记缺失。仓库约 4,478 次提交、89 个开放 Issue、149 个开放 PR；未见 Discussions 入口。
- **爆发原因**：把“长上下文、持续记忆、自我改进、定时心跳和子 Agent”整合成可运行的工程系统，正好击中长周期 Agent 的可靠性痛点。
- **亮点**：Continual Harness 会保存提示词、记忆、技能描述和子 Agent，并以证据驱动更新、支持回滚；内置后台任务、计划任务和受限自治模式。
- **潜在风险**：官方明确提示它会以当前用户权限执行模型生成的 Python 与命令，Worker/Kernel 本身**不是沙箱**。对不可信仓库或输入，应放进一次性环境和外部沙箱，并配置人工审批与资源上限。
- **适合人群**：构建长时编码 Agent、研究 RLM、持续学习和多 Agent 编排的团队。
- **值得关注程度**：**★★★★★**。增长最快且工程理念新，但安全隔离必须先行。

## 今日技术趋势

1. **Agent 从短任务走向长时、持续和自改进**：`prime-agent` 把记忆、技能、子 Agent、心跳与回滚整合进 Continual Harness，说明竞争焦点正从模型调用转向长周期控制系统。
2. **Skills 正在形成 Agent 的“软件包层”**：`mattpocock/skills`、`agent-skills`、`superpowers`、`google/skills` 占据前十中的四席。下一阶段关键不再是技能数量，而是版本、权限、评测、来源和提示注入治理。
3. **Agent 运行时继续分层**：`cloudflare/computer` 提供远程执行环境，`celld` 探索分布式有状态对象。执行沙箱与持久状态正在成为 Agent 基础设施的两个独立层。
4. **身份与可观测性重新成为主角**：`authentik` 和 `witr` 的上榜说明，当 Agent 开始操作真实系统，SSO、最小权限、进程溯源和事故排查比“再加一个模型”更迫切。
5. **热度高度集中但总量回落**：前十 Star 增量下降 11.3%，但前三仍贡献近六成。今天是少数新项目爆发、成熟 Skills 持续吸流的一天。

## 最值得深入研究的 3 个项目

### 1. prime-agent

它提供了长时 Agent 最稀缺的结构：持续目标、证据驱动的自我更新、子 Agent、后台任务和回滚。对企业代码审查而言，可借鉴其 Harness 设计，把“发现问题—补充证据—修正规则—验证效果”做成闭环。研究时必须把沙箱、只读默认、人工审批和资源配额放在功能之前。

### 2. addyosmani/agent-skills

它最适合转化为企业代码审查的可执行规范：把架构、实现、测试、性能和评审规则拆成独立技能，再通过基准用例验证。相比直接复制提示词，更值得研究的是技能版本化、冲突消解、门禁和效果度量。

### 3. witr

它补足了 Agent 落地后经常被忽略的运行态追踪。对于部署在 Linux 服务器上的 OCR、推理和审查服务，能够从端口或进程追溯到 systemd、容器及父进程链，对故障定位、安全审计和误操作追责都有直接价值。

## 数据口径与可靠性说明

- **24h 新增 Star**：取自 [GitHub Trending 日榜](https://github.com/trending?since=daily) 在采样时显示的 “stars today”。GitHub 未公开该榜单的完整计算算法；它应视为滚动窗口近似值，不等同于自然日精确净增。
- **7 日新增 Star**：优先采用 [GitHub Trending 周榜](https://github.com/trending?since=weekly) 的 “stars this week”。今日前十未在本次抓取到的周榜结果中出现，因此没有臆造精确值；对连续上榜项目仅给出已有日报快照之和，明确标记为**下限**。
- **Fork 与社区活跃度**：当前累计值来自项目 GitHub 页面；持续上榜项目的 Fork 变化由相邻日报快照相减。提交、开放 Issue/PR、Discussions 只作为维护与讨论信号，不能直接解释 Star 增长。
- **爆发原因与趋势**：基于项目 README、仓库结构、近期增长与社区指标进行分析，属于推断，不是项目方声明。
- **局限**：GitHub Trending 会随语言、地区、采样时间和反滥用策略变化；Star 也可能受社交传播影响。生产采用前仍应核验许可证、最近 Release、安全公告、依赖供应链和真实工作负载表现。
