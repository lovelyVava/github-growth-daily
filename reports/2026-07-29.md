## 三、统计口径与限制

- **24 小时增长：** 来自 [GitHub Trending Daily](https://github.com/trending?since=daily) 页面显示的 `stars today`。
- **7 日增长：** 来自 [GitHub Trending Weekly](https://github.com/trending?since=weekly) 页面显示的 `stars this week`。
- GitHub 没有完全公开 Trending 的窗口边界与排序算法。本报告先收集当日候选，再按 `stars today` 重新排序，并用相对增速、Fork、Open Issues、Open PR、提交规模和讨论入口辅助判断。
- **相对日增：** `今日新增 Star ÷ 当前总 Star`，用于避免累计 Star 很高的老项目天然占优。
- 周榜只显示有限项目；每日项目表中的“—”表示无法从本次周榜可靠取得精确 7 日数据，不表示增长为零。
- Fork、Issues、PR 和提交数是仓库页面快照。对于新上榜项目，不能把累计数当成 24 小时新增。
- Open Issues/PR 是当前未关闭数量，净变化会同时受到新建与关闭影响，不能直接等同于当日贡献量。
- 上期与本期抓取时间均约为北京时间 08:00，因此持续项目的 Fork 与仓库状态差值近似 24 小时快照差；`stars today` 仍是滚动窗口，不能和两次总 Star 快照差直接等同。
- “爆发原因”若没有项目方明确说明，均为结合产品形态、近期讨论与增长结构做出的**分析推断**。

## 六、逐项分析

### 1. claude-video

- **链接：** https://github.com/bradautomates/claude-video
- **主要用途：** 下载视频、提取字幕或语音转写、抽取关键帧，再把结构化结果交给 Claude、Codex 等 Agent 分析。
- **技术栈：** Python、yt-dlp、ffmpeg、视频字幕、可选 Whisper；MIT。
- **近期增长：** 11,912 Star，24 小时 +989，Fork 1,204；较上期排名 ↑7，日增速度约 +140%。
- **爆发原因（推断）：** Coding Agent 长期擅长文本和图片，但无法方便地“看完整视频”。项目把复杂的视频预处理封装成单一技能，价值容易理解且演示效果强。
- **亮点：** 支持 50 多种 Agent Skill 宿主；有字幕时成本较低；非常适合分析教程、产品演示、测试录像和游戏录屏。
- **潜在风险：** 只有 11 次累计提交，却已有 63 个 Open PR，增长远快于维护能力；视频下载涉及平台条款与版权；无字幕视频可能产生 Whisper 成本和隐私问题。
- **适合人群：** AI 开发者、内容研究者、需要分析 Unity 游戏录屏或 Bug 录像的独立开发者。
- **值得关注程度：** **★★★★★**

### 2. AIRI

- **链接：** https://github.com/moeru-ai/airi
- **主要用途：** 自托管 AI 虚拟角色，组合实时语音、记忆、Live2D/虚拟形象以及 Minecraft、Factorio 等游戏控制能力。
- **技术栈：** TypeScript、Vue、Tauri/Rust、Godot、Web 音频与模型服务；MIT。
- **近期增长：** 44,672 Star，24 小时 +796，Fork 4,440；连续上榜，从第 5 升至第 2。
- **爆发原因（推断）：** AI Companion 从聊天框转向“持续存在、能说话、能记忆、能控制游戏”的角色系统，AIRI 正好覆盖这一完整叙事。
- **亮点：** Web、Windows、macOS 多端；角色、语音、记忆和游戏插件的架构对 AI NPC 很有参考价值；仓库持续有提交和 PR。
- **潜在风险：** 系统范围很大，部署和资源消耗高；语音、模型、角色资产存在多个依赖链；官方特别提醒不存在关联加密货币，需防范仿冒。
- **适合人群：** AI NPC、虚拟主播、陪伴应用、游戏 Agent 开发者。
- **值得关注程度：** **★★★★★**

### 3. ECC

- **链接：** https://github.com/affaan-m/ECC
- **主要用途：** 为 Claude Code、Codex、Cursor、OpenCode 等 Agent 提供 Skills、Memory、研究流程、安全扫描和工作规范。
- **技术栈：** JavaScript、Node.js、Python、Shell、各类 Agent 配置；MIT。
- **近期增长：** 234,657 Star，24 小时 +692，Fork 35,765；首次进入本报告。
- **爆发原因（推断）：** 用户开始意识到 Agent 的稳定性取决于上下文、规则、记忆、安全与验收流程，单纯更换模型不能解决全部问题。
- **亮点：** 覆盖多种 Agent；包含安全扫描、工作上下文、技能和流程模板；文档与多语言支持丰富。
- **潜在风险：** 配置和能力面非常宽，容易把简单项目复杂化；安装脚本和 Agent 指令会改变工作流，应先审计后启用；项目也提示 Codex 插件缓存存在上游限制。
- **适合人群：** 重度 AI 编程用户、多 Agent 团队、希望标准化 Codex 工作流的开发者。
- **值得关注程度：** **★★★★★**

### 4. superfile

- **链接：** https://github.com/yorukot/superfile
- **主要用途：** 现代化终端文件管理器，支持常用文件操作、主题、插件和快捷键。
- **技术栈：** Go、Bubble Tea 风格 TUI 生态；MIT。
- **近期增长：** 21,361 Star，24 小时 +660，Fork 691；排名维持第 4，日增继续提高 10%。
- **爆发原因（推断）：** 终端工作流随 AI Coding Agent 再次流行，视觉精致、单一职责明确的 TUI 工具容易传播。
- **亮点：** Go 单体工具、跨平台、交互直观、主题和插件丰富；连续两天高增长说明并非单日偶发。
- **潜在风险：** 仍有 183 个 Open Issues；文件管理属于高风险操作，批量移动、删除前需要备份；不同平台终端兼容性有差异。
- **适合人群：** 经常使用终端、SSH、服务器和 Agent CLI 的开发者。
- **值得关注程度：** **★★★★☆**

### 5. GeoLibre

- **链接：** https://github.com/opengeos/GeoLibre
- **主要用途：** 在浏览器、桌面、移动端和 Jupyter 中浏览、可视化与分析地理空间数据，并尽量保持数据本地化。
- **技术栈：** Tauri v2、React、TypeScript、MapLibre GL JS、DuckDB-WASM Spatial、deck.gl；MIT。
- **近期增长：** 3,270 Star，24 小时 +420，相对日增 **12.84%**，是今日相对增速第一。
- **爆发原因（推断）：** “浏览器端 DuckDB + WebAssembly + 本地隐私”降低了 GIS 使用门槛，跨端统一代码也具有工程吸引力。
- **亮点：** 本地优先、跨端、无需先建设重型 GIS 后端；898 次提交说明不是临时演示项目。
- **潜在风险：** 大数据集仍受浏览器内存和 GPU 限制；不同平台打包、移动端性能和地理数据格式兼容性需要实测。
- **适合人群：** GIS、数据可视化、城市规划、位置数据产品开发者。
- **值得关注程度：** **★★★★☆**

- **链接：** https://github.com/pascalorg/editor
- **主要用途：** 在 Web 中创建和分享 3D 建筑项目，提供墙体、楼层、区域、门窗、物件和插件化编辑能力。
- **技术栈：** React 19、Next.js 16、Three.js WebGPU、React Three Fiber、Zustand、Zod、Turborepo、Bun；MIT。

- **亮点：** 架构文档完整；场景状态、节点注册、空间检测、撤销重做和插件系统都有明确划分；可作为地图/建筑编辑器架构参考。
- **潜在风险：** WebGPU 兼容性和复杂模型性能仍需验证；这是建筑编辑器而非游戏关卡工具，直接用于 Unity 需要额外导出和数据转换层。
- **适合人群：** Web 3D、建筑可视化、关卡编辑器和场景工具开发者。
- **值得关注程度：** **★★★★☆**

### 8. book-to-skill

- **链接：** https://github.com/virgiliojr94/book-to-skill
- **主要用途：** 把技术书籍、文档目录或资料集合转换成可供 Agent 检索和使用的 Skill。
- **技术栈：** Python、PDF/文档解析、Agent Skill；转换器代码为 MIT。
- **近期增长：** 11,103 Star，24 小时 +366，Fork 1,318。
- **爆发原因（推断）：** Agent Skill 成为新的知识包装形式，用户希望让 Coding Agent 使用自己的书籍和内部文档，而不是每次重新上传。
- **亮点：** 目标明确，支持多来源文档；强调本地、私有化知识处理；仓库含测试、安全说明和完整文档。
- **潜在风险：** MIT 只适用于转换器，不适用于输入书籍；公开分享由受版权保护书籍生成的 Skill 可能侵权；文档切分质量会影响回答可靠性。
- **适合人群：** 技术学习者、企业知识库、需要定制 Agent 上下文的开发者。
- **值得关注程度：** **★★★★☆**

- **值得关注程度：** **★★★☆☆**

### 10. Hugging Face speech-to-speech

- **链接：** https://github.com/huggingface/speech-to-speech
- **主要用途：** 构建本地低延迟语音 Agent，将 VAD、STT、LLM 和 TTS 串成可替换的模块化管线，并提供 OpenAI Realtime 兼容的 WebSocket API。
- **技术栈：** Python、Hugging Face 模型、VAD/STT/TTS、WebSocket、本地 LLM；Apache-2.0。
- **近期增长：** 7,067 Star，24 小时 +177，Fork 942。
- **爆发原因（推断）：** 实时语音交互正在成为 AI 应用与游戏角色的关键入口，本地部署同时回应成本、隐私和延迟问题。
- **亮点：** 各模块可替换；可连接托管模型、vLLM 或 llama.cpp；接口兼容 OpenAI Realtime，便于集成。
- **潜在风险：** 端到端延迟受模型、GPU、音频设备和网络共同影响；中文识别与合成效果需要单独验证；本地全栈对硬件要求较高。
