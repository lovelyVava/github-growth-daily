## 统计口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 日榜的 `stars today`，这是滚动窗口，不等于自然日或相邻累计快照差；页面顺序不严格按该值排序，本报告按数值重新排序。
2. **7 天新增 Star**：采用周榜的 `stars this week`。只有公开周榜直接展示的数值才写入；未进入周榜的项目标为“缺失”，不从累计 Star 反推。
3. **开源范围**：主榜要求仓库有可识别的 OSI 开源许可证或明确的标准开源许可证文件；仅“公开源码”但采用商业/自定义条款的项目不计入主榜。
4. **当前 Star/Fork**：采用 2026-09-19 07:59–08:18 的 GitHub 页面/API 快照；不同接口抓取时间存在分钟级差异。
5. **Fork 变化**：对连续进入前十的项目比较 9 月 18 日与 9 月 19 日相邻快照；新上榜项目不估算 24 小时 Fork 变化。
6. **工程活跃度**：统计 2026-09-12 00:00 UTC 起约 7 天的默认分支提交，单仓最多读取 100 条；触及上限写作“≥100”。
7. **贡献者活跃度**：按提交记录中的 GitHub 账号或作者邮箱去重估算，可能拆分同一人的多个身份或包含机器人，不等同累计 Contributors。
8. **讨论热度**：统计同一窗口新建 Issue，排除 PR。Issue 可能由机器人、模板、集中投稿或维护者拆分产生，数量不等于有效人工讨论。
9. `OpenSpec` 的提交与作者接口在抓取时持续超时，故明确标为“缺失”；Issue 仅按可见页面给出下限，未使用旧数据填补。
10. **爆发原因**：根据 README、近期提交、Issue 内容与榜单表现作分析推断，不代表维护者官方结论。

## 项目分析

### 1. cloudflare/security-audit-skill

- **主要用途**：把编码 Agent 编排为多阶段安全审计器，覆盖侦察、覆盖账本、漏洞猎取、候选验证、结构化结论和独立复核。
- **技术栈**：Agent Skill/Markdown、JavaScript 零依赖验证器、JSON Schema、隔离子 Agent、机器可读 `findings.json` 与 `coverage-ledger.json`；MIT。
- **近期增长**：日榜约 **+3,006 Star**；周榜直接值缺失；相对日增约 **28.3%**。当前 13,629 Star、728 Fork；较上期 Fork约 **+164**，排名保持第一。
- **贡献与讨论**：近 7 天仅 1 次提交、1 个作者身份、10 个新 Issue；唯一提交仍是澄清指导模式与完整审计模式。
- **爆发原因**：Cloudflare 的漏洞发现 Harness 方法持续扩散，“覆盖可量化、结论可机读、发现者与验证者分离”形成强方法论传播。
- **亮点**：`confirmed`、`needs_validation`、`rejected` 三态清晰；覆盖账本避免把未验证区域默认为安全；多轮运行可复用已有证据并针对缺口继续审计。
- **潜在风险**：涨星明显快于维护和作者扩张；公开 Issue 指出覆盖验证器可能接受不存在的本地检查产物；效果高度依赖模型、预算、目标可构建性与沙箱。
- **适合人群**：获授权代码审计、AppSec、Agent 安全评估和希望建立可机读证据链的研发安全团队。
- **值得关注程度**：**★★★★☆**。方法论价值高，但必须先用已知漏洞基准和人工复核验证，不能把榜首当成熟度证明。

### 2. alibaba/open-code-review

- **主要用途**：对工作区、分支、提交或完整目录进行 AI 代码审查，以确定性管线控制文件覆盖、规则匹配和评论位置，以 Agent 完成语义判断。
- **技术栈**：Go、Git、隔离子任务、OpenAI/Anthropic 兼容模型、MCP、CLI、Agent Skills、IDE 插件与 CI/CD；Apache-2.0。
- **近期增长**：日榜约 **+2,704 Star**、周榜约 **+14,144 Star**；相对日增约 **8.0%**。当前 36,643 Star、2,611 Fork；较上期 Fork约 **+145**，排名保持第二。
- **贡献与讨论**：近 7 天约 61 次提交、31 个作者身份、32 个新 Issue，作者广度仍为本期最高。近期集中推进 JetBrains/IDEA 插件、审查结果 Viewer、Windows 更新器和许可证/英文规范门禁。
- **爆发原因**：企业规则、全量 Scan、可恢复 Session、GitLab/GitHub/IDE 集成和本地模型兼容，持续回应“Agent 审查必须可控、可追踪”的需求。
- **亮点**：文件分组、位置校正、Token 预算、重复评论去重和过期线程治理均由确定性逻辑约束；公开基准明确承认以 Recall 换 Precision，而非只展示单一优胜指标。
- **潜在风险**：Issue #1440 指出 Assurance 文档称 API Key 不落盘，但 CLI 可能写入 `config.json`，这一声明与实现差异应在接入真实密钥前核验；高 Precision 仍不等于高 Recall。
- **适合人群**：内网 GitLab、提交前扫描、MR 自动评论、本地 `/v1` 模型及希望把审查带入 IDE 的研发团队。
- **值得关注程度**：**★★★★★**。七日增长、作者广度和产品化速度兼具，但凭据持久化边界需列入上线门禁。

### 3. Tencent/BrowserSkill

- **主要用途**：让 Codex、Claude Code、Cursor 等 Shell 型 Agent 借用真实、已登录的 Chrome/Edge 标签页，在独立可见窗口中执行浏览器任务并支持人工接管。
- **技术栈**：TypeScript 浏览器扩展、Rust `bsk` CLI/本地守护进程、WebSocket、Chrome DevTools Protocol、Agent Skill 与 DeepSeek Harness 插件；MIT。
- **近期增长**：日榜约 **+1,306 Star**；周榜直接值缺失；相对日增约 **32.9%**。当前 5,281 Star、366 Fork；较上期 Fork约 **+75**，排名保持第三。
- **贡献与讨论**：近 7 天约 61 次提交、4 个作者身份、19 个新 Issue；近期修复后台标签截图、导航取消后的就绪状态、子进程退出后的输出排空和重复动作标签性能。
- **爆发原因**：复用真实登录态、跨 Agent Harness、独立 Agent 窗口和人机接管解决了无头浏览器难处理登录与验证码的问题。
- **亮点**：借用标签需要显式归还；确认与人工帮助由扩展设置控制；支持 Windows、Linux、macOS 和 Chrome/Edge；对沙箱 Agent 有持久守护进程方案。
- **潜在风险**：公开 Issue [#273](https://github.com/Tencent/BrowserSkill/issues/273) 仍为 Open：默认本地 WebSocket 未锁定官方扩展 ID，其他扩展可能借守护进程控制已登录浏览器；另有控制浮层阻断真实点击、跨 Profile 调试器卡死等开放问题。
- **适合人群**：浏览器 Agent 架构、安全边界、人机接管和跨 Harness 工具研究者；当前不适合含公司 GitLab、邮箱、网银等敏感登录态的日常浏览器。
- **值得关注程度**：**★★★☆☆（研究价值高，部署降权）**。只应在独立 Profile、测试账户和最少扩展环境中验证。

### 4. affaan-m/ECC

- **主要用途**：为 Claude Code、Codex、OpenCode、Cursor 等编码 Agent 提供 Skills、记忆、安全、研究优先开发和可验证工程流程。
- **技术栈**：JavaScript/Markdown、Shell、Python、跨宿主 Agent Skills、Capsule/记忆系统、Hooks、CI 验证；MIT。
- **近期增长**：日榜约 **+958 Star**、周榜约 **+5,877 Star**；相对日增约 **0.4%**。当前 262,047 Star、39,209 Fork；较上期 Fork约 **+116**，排名保持第四。
- **贡献与讨论**：近 7 天约 20 次提交、11 个作者身份、18 个新 Issue；近期补齐 Codex 镜像 Skill 的许可证声明、修复静默 Hook 路径和记忆认证边界。
- **爆发原因**：Agent 用户从“更多提示词”转向跨宿主流程、记忆治理、供应链和可审计控制回路。
- **亮点**：公开测试、独立复核、CI 与回滚方式；记忆读取的错误分类趋向 fail-closed；跨宿主适配覆盖面广。
- **潜在风险**：开放 Issue 指出 GateGuard 尚未覆盖 `git branch -D`、`stash drop/clear`、`reflog expire`、`git restore` 等破坏性命令；SessionStart 还可能跨 worktree 注入旧会话摘要。
- **适合人群**：需要在多个 Agent 宿主统一工程规范、验证和记忆治理的团队。
- **值得关注程度**：**★★★★☆**。适合提取安全与回顾控制点，不宜把文本规则当作宿主级强制隔离。

### 5. asciimoo/hister

- **主要用途**：在本机或自托管服务器中索引访问过的网页与本地文件，通过 Web、终端或 MCP 重新检索个人知识。
- **技术栈**：Go 服务端/CLI、浏览器扩展、Web UI、全文索引、可选 Embedding 语义检索、MCP、多用户模式；AGPL-3.0。
- **近期增长**：日榜约 **+889 Star**；周榜直接值缺失；相对日增约 **21.8%**。当前 4,958 Star、204 Fork；首次进入近期前十。
- **贡献与讨论**：近 7 天约 46 次提交、5 个作者身份、6 个新 Issue；近期修复 favicon 获取中的 XSS、无 HTML 页面预览转义，并加入 Prometheus 指标和 FreeBSD 构建支持。
- **爆发原因**：浏览器历史、文件、全文检索和 MCP 被组合成“自己的搜索引擎”，正好承接 Agent 长期记忆与数据主权需求。
- **亮点**：无强制云服务和默认遥测；索引正文而非只有标题/URL；支持浏览器自动采集、文件导入、TUI/CLI、字段查询和可选语义搜索。
- **潜在风险**：浏览器扩展会把页面正文发送至配置的 Hister 服务，可能包含内网页面和敏感数据；远程 Embedding 会进一步外发文本。多用户部署必须验证认证、租户隔离、备份加密与删除语义。
- **适合人群**：本地知识库、研究资料归档、个人搜索、Agent/RAG 记忆层和重视数据主权的团队。
- **值得关注程度**：**★★★★★**。产品定位清晰且修复安全问题及时，适合先用脱敏资料验证检索质量和权限边界。

- **爆发原因**：Skills 标准化后，团队更关心可迁移的工程流程、验收证据和宿主差异，而非单次提示词。
- **亮点**：生命周期完整、命令与技能职责清晰、支持渐进采用，并把测试、质量门禁和 Skill Lint 纳入默认流程。
- **潜在风险**：文本规则不能替代编译器、测试和静态分析；跨宿主语义并非完全一致；全量安装会扩大上下文和供应链面。

- **值得关注程度**：**★★★★☆**。近期重点从增加 Skill 转向减少注入冲突，成熟度信号较好。

### 7. TencentCloud/Octop

- **主要用途**：面向个人、家庭和小团队的自托管 AI 助手平台，以多用户、多 Agent、知识库、渠道、定时任务和外部编码 Agent 委派组成统一控制面。
- **技术栈**：Python 3.12、FastAPI/uvicorn、React 18/TypeScript/Vite/Ant Design、SQLite/PostgreSQL、APScheduler、ACP、MCP、S3/COS、CDP 浏览器自动化；MIT。
- **近期增长**：日榜约 **+569 Star**；周榜直接值缺失；相对日增约 **16.8%**。当前 3,947 Star、406 Fork；首次进入近期前十。
- **贡献与讨论**：近 7 天约 48 次提交、11 个作者身份、45 个新 Issue；发布 1.0.1，加入容器文件系统默认值、多 OAuth SSO、聊天 HITL/Skills UX 和模型搜索。
- **爆发原因**：单进程自托管、Web/IM/CLI/定时任务统一入口、可移植记忆、RAG、浏览器/终端/远程桌面和 ACP 委派，形成完整“数字助理操作系统”叙事。
- **亮点**：JWT 多用户隔离、工具批准、Shell Guardrail、PII 脱敏；每个 Agent 有独立工作区、Provider、渠道和 Cron；支持飞书、钉钉、企微、QQ、Discord。

- **适合人群**：愿意自托管、需要中文 IM 渠道、多 Agent、知识库和定时自动化的个人或小团队。
- **值得关注程度**：**★★★★☆**。增长与工程活动都强，但应先在隔离测试环境验证升级、权限和恢复路径。

### 8. coder/coder

- **主要用途**：在自有基础设施上提供云开发环境和 AI 编码 Agent，让工作区以 Terraform 定义，并通过安全隧道、自动休眠和集中控制面管理。
- **技术栈**：Go、TypeScript/React、Terraform、Kubernetes/Docker/VM、WireGuard、OIDC/OAuth、Web Terminal 与 Agent 控制面；核心 AGPL-3.0，另含 Enterprise 商业许可证。

- **爆发原因**：企业开始把 Agent 放进可复现、可关闭、可审计的云开发环境，而不是让模型直接运行在开发者长驻笔记本上。
- **亮点**：基础设施即代码、工作区自动停止、安全隧道、集中身份与网络控制；Agent Loop 可运行在自有控制面，避免把 API Key 放入工作区。
- **潜在风险**：部署涉及 Terraform、网络、容器/虚拟机、身份和成本治理；错误模板或过宽 Scope 会放大 Agent 权限。AGPL 与 Enterprise 功能边界必须在采购/分发前核对。
- **适合人群**：平台工程、DevSecOps、远程研发、大规模 ephemeral workspace 和企业 Agent 沙箱团队。
- **值得关注程度**：**★★★★★**。不是增速最猛的新项目，但活动和作者广度显示长期工程能力强。

## 当天技术趋势

1. **安全方法论继续占据流量中心，但工程质量出现分化**：`security-audit-skill` 与 `open-code-review` 合计约 +5,710 Star，占前十约 51.1%。前者只有 1 次近七日提交，后者有 61 次提交与 31 个作者；相同主题下，传播强度和交付强度必须分开评估。
2. **“个人搜索”正在成为 Agent 长期记忆的现实入口**：`hister` 把浏览器访问、文件全文、字段查询、MCP 和可选语义搜索合并。相比只存摘要，全文索引更可追溯；但它也把浏览器正文、内网材料和向量服务数据流变成新的隐私边界。
3. **自托管 Agent 从单用户工具升级为多用户控制面**：`Octop` 与 `coder` 分别从助手和开发环境两端进入。核心问题不再只是能否调用模型，而是身份、工作区、Shell、浏览器、渠道、Cron、网络和成本能否被集中治理。
4. **Skills/Plugins 正从提示词资产变成供应链资产**：`agent-skills`、`knowledge-work-plugins`、`ECC` 同时上榜。自动注入冲突、第三方连接器、许可证声明和 Hook 权限说明，正在成为比“Skill 数量”更重要的成熟度指标。
5. **规范驱动开发开始处理跨仓库依赖**：`OpenSpec` 的 Store、依赖顺序、命名空间和归档溯源 Issue，显示 SDD 已从个人 Markdown 模板进入团队级变更图谱阶段；校验器的正确性将直接决定规范能否成为真实控制面。
6. **严格开源与公开源码必须分开**：`Claude Code` 具有显著日增和工程活动，但缺少 OSI 许可证。本报告宁可用增长略低的 MIT 项目补位，也不把“代码可见”自动等同“可自由使用、修改和分发”。
