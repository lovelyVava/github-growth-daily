## 项目分析

### 1. meta/astryx

- **主要用途**：Meta 开源的企业级设计系统，为人类开发者与编码 Agent 提供统一组件、主题、模板、文档与 CLI。
- **技术栈**：React 19、TypeScript、StyleX、CSS 自定义属性、Storybook、pnpm Monorepo；MIT，当前 Beta。
- **近期增长及口径**：约 **+1,830 Star/24h**，7 天快照差约 +12,828。当前 26,876 Star、2,084 Fork，Fork +98，连续第一。
- **贡献与讨论**：近 7 天提交 **≥100**、60 个新 Issue。近期继续调整 CLI 表格、链接换行和组件最佳实践；问题涉及 Avatar 对 ASCII 名称也执行昂贵分词、禁用菜单项无法解释原因、Stepper 与 List 的无障碍状态。
- **爆发原因（推断）**：Meta 的规模背书、150+ 组件以及“人和 Agent 共用可预测 API/文档”的定位继续形成传播飞轮。
- **亮点**：组件、主题、模板、CLI、文档和可访问性测试形成完整交付链；预编译 CSS 降低消费者接入门槛。
- **潜在风险**：Beta API、React 19 依赖和持续高频变更会增加迁移成本；大量可访问性与性能 Issue 说明生产采用仍需自行回归。
- **适合人群与关注程度**：设计系统、前端平台、React、可访问性和 Agent UI 生成团队；**★★★★★**。

### 2. GoogleChrome/modern-web-guidance-src

- **主要用途**：把现代 Web API、性能、可访问性和兼容性实践以可检索 Skill 注入编码 Agent，并扫描遗留模式。
- **技术栈**：TypeScript、Node.js/npm CLI、静态分析器、评测 Harness、文档与可视化 Dashboard；Apache-2.0。
- **近期增长及口径**：约 **+739 Star/24h**，相对日增约 26%；2 天可见快照净增约 +1,951。当前 3,610 Star、224 Fork，新上榜第二。
- **贡献与讨论**：近 7 天提交 **≥100**、54 个新 Issue；近期加入 JavaScript discipline、SCSS/Less、Lit、Glimmer 扫描和 legacy-scan 加速。
- **爆发原因（推断）**：编码模型容易从训练数据复现旧式 Web 模式；Chrome、Edge、Firefox、MDN 团队共同维护的现代平台知识正好补足这一缺口。
- **亮点**：250 项现代 Web 特性、面向 Token 效率的检索、遗留扫描和公开评测，既可作 Skill 也能作为规则数据源。
- **潜在风险**：当前 5,000 文件上限可能让大型仓库被静默漏扫；Issue 还要求暴露解析失败、截断和跳过文件诊断。浏览器兼容性与 fallback 指导会随平台快速变化，不能当作永久正确的静态规范。
- **适合人群与关注程度**：前端平台、编码 Agent、Web 性能、可访问性与代码评审团队；**★★★★★**。

### 3. we-promise/sure

- **主要用途**：自托管个人财务与资产管理应用，统一账户、交易、预算、净值和投资持仓。
- **技术栈**：Ruby on Rails、Hotwire/Stimulus、PostgreSQL、Sidekiq、Docker；AGPL-3.0。
- **近期增长及口径**：约 **+967 Star/24h**，3 天可见快照净增约 +2,359。当前 14,175 Star、1,066 Fork，Fork +92，由第五升至第三。
- **贡献与讨论**：近 7 天约 93 次提交、45 个新 Issue；近期增加德语翻译并修复密码挑战。问题包括睡眠主机错过定时任务、同 `transaction_id` 导入覆盖、IBKR 税费遗漏。
- **爆发原因（推断）**：用户对可自托管、可迁移的个人财务数据需求增强；完整仪表盘和多源导入兼具演示效果与实际用途。
- **亮点**：覆盖现金流、预算、投资和净值，AGPL 推动服务端改动回馈社区；增长、提交和真实工单同时活跃。
- **潜在风险**：金融数据极敏感；导入幂等性、交易去重、汇率、税费和成本基础错误会导致错误决策。升级前应备份并在副本验证，外部同步凭据必须最小化。
- **适合人群与关注程度**：自托管用户、个人财务工程、FinOps 和数据导入团队；**★★★★★**。

### 4. openai/codex-security

- **主要用途**：通过 CLI、TypeScript SDK、Codex 工作流和 GitHub Action 查找、验证、修复漏洞，并导出 SARIF/JSON/CSV。
- **技术栈**：TypeScript/Node.js CLI 与 SDK、Python 3.10+ 辅助环境、Docker、GitHub Actions、第三方扫描器导入；Apache-2.0。
- **近期增长及口径**：约 **+643 Star/24h**；2 天可见快照净增约 +1,022。当前 12,655 Star、988 Fork，新上榜第四。
- **贡献与讨论**：近 7 天提交 **≥100**、11 个新 Issue；近期强化 Deep Scan 沙箱说明、合成安全评测与 CrowdStrike IaC 导入。问题涉及 Windows helper 返回旧退出码、长文件名保存失败、manifest validator 忽略 `else` 分支和大写 HTTP URL 被当命令。
- **爆发原因（推断）**：安全扫描正在从“只报候选问题”转向验证、补丁、复测和工单闭环；CLI、SDK、CI 与多扫描器导入让项目更容易进入企业流程。
- **亮点**：支持范围化扫描、差异扫描、Deep Scan、威胁模型、发现去重、修复验证和多格式导出，覆盖从调查到交付的完整链路。
- **潜在风险**：扫描会接触源码、Git 历史、API Key 和高敏感发现；模型判断仍可能误报漏报，深度扫描还有时间与费用不确定性。CI 使用应固定审阅过的分发提交，并隔离凭据与结果存储。
- **适合人群与关注程度**：AppSec、DevSecOps、代码评审平台、CI 与安全 Agent 团队；**★★★★★**。

### 5. milind-soni/OpenMausBot

- **主要用途**：自托管多 Bot 聊天应用，让 Agent 在隔离虚拟机中使用浏览器、终端和文件工具。
- **技术栈**：TypeScript、Electron、Expo、Node.js、Docker/虚拟机、计算机操作 Agent；Apache-2.0。
- **近期增长及口径**：周榜约 **+9,104 Star/7d**，相邻快照约 +173/24h。当前 21,851 Star、3,035 Fork，Fork +48，由第二降至第五。
- **贡献与讨论**：近 7 天提交与新 Issue 均 **≥100**。近期问题包括预算耗尽交接选择旧请求并遗漏新指令、跨 Bot 审批证明和持续扩展模型支持。
- **爆发原因（推断）**：多 Agent 对话、桌面/移动端与真实执行 VM 被整合成完整产品，比单一提示词或工具演示更容易保持周热度。
- **亮点**：具备任务接力、执行环境、多端入口和连接器，适合研究长期任务编排。
- **潜在风险**：提交与工单双触顶意味着稳定性压力大；终端、浏览器、文件、网络和第三方凭据必须在 VM 层隔离，跨 Bot 审批需要防重放与可验证来源。
- **适合人群与关注程度**：自托管 Agent、桌面 AI、虚拟化和多 Agent 产品团队；**★★★★☆**。

### 6. vercel-labs/agent-desktop

- **主要用途**：让 Agent 通过操作系统无障碍树查看并操作 macOS、Windows 和 Linux 桌面应用。
- **技术栈**：Rust 原生 CLI、系统 Accessibility API、Node/npm 包装、MCP、跨平台输入与会话层；Apache-2.0。
- **近期增长及口径**：周榜约 **+6,414 Star/7d**，相邻快照约 +238/24h。当前 22,894 Star、1,696 Fork，Fork +39，由第四降至第六。
- **贡献与讨论**：近 7 天 12 次提交、27 个新 Issue；发布 v1.3.1，并将 macOS 沙箱访问从 SSH 改为 guest agent。问题包括 Windows snapshot 权限错误、Electron 菜单点击静默失效、`list-apps` 超时和 2048 节点预算。
- **爆发原因（推断）**：电脑操作从截图坐标转向结构化无障碍树，跨平台 CLI 让 Agent 更容易进入真实桌面工作流。
- **亮点**：结构化控件语义比像素坐标稳定、上下文更紧凑，也更便于操作审计；guest agent 方向有利于强化沙箱边界。
- **潜在风险**：无障碍权限能读取敏感界面并执行高影响操作；平台差异、不可访问控件、焦点漂移和 guest/host 会话隔离都可能导致误操作。
- **适合人群与关注程度**：电脑操作 Agent、桌面自动化、可访问性工具和沙箱平台团队；**★★★★★**。

### 7. NVIDIA/auto-ontology

- **主要用途**：从企业元数据生成语义本体与关系图，为 Agent 提供指标定义、SQL 校验、血缘与来源证据。
- **技术栈**：Python、FastAPI、Postgres、Next.js/React、MCP/CLI/API、数据库连接器与 NVIDIA NIM；Apache-2.0。
- **近期增长及口径**：周榜约 **+5,802 Star/7d**，相邻快照约 +146/24h。当前 12,340 Star、1,015 Fork，Fork +32，由第三降至第七。
- **贡献与讨论**：近 7 天 2 次提交、33 个新 Issue；需求包括 Oracle/Athena 连接器、密码特殊字符处理和多条 Join 路径排序。
- **爆发原因（推断）**：企业 Agent 的瓶颈从“能否查询”转向“语义是否一致、结果能否追溯”，本体、血缘与审批因此成为数据控制面。
- **亮点**：把语义、关系、连接器、查询与答案证据链置于同一层，并通过 MCP 暴露给 Agent。
- **潜在风险**：33 个 Issue 对 2 次提交显示需求快于修复；错误本体或连接器结果会被放大为可信上下文。生产使用必须验证只读权限、RLS/CLS、人工审批与审计日志。
- **适合人群与关注程度**：企业数据平台、语义层、Text-to-SQL、RAG 和 Agent 治理团队；**★★★★☆**。
