4. **当前 Star/Fork**：采用 2026-10-05 08:00 前后的 GitHub 页面/API 快照；分钟级变化会带来少量差异。
5. **Fork 变化**：仅对连续上榜且上一期有同口径快照的项目计算相邻快照差；新上榜或重新上榜项目标为“缺失”。

9. **爆发原因**：依据 README、近期提交、Issue 与榜单表现作分析推断，不代表维护者官方结论。

## 项目分析

### 1. DietrichGebert/ponytail

- **主要用途**：以“先删复杂度、少写代码”为核心，为编码 Agent 提供规则、Skills 与 Hooks。
- **技术栈**：JavaScript、Markdown Skills、Claude/Cursor/OpenCode/Codex/Muse 集成；MIT。
- **近期增长及口径**：约 **+1,894 Star/24h**，相对日增约 **1.24%**；7 天直接值缺失。当前 154,851 Star、8,322 Fork，Fork 较上期 +97；由第二升至第一。
- **贡献与讨论**：近 7 天 44 次提交、24 个作者身份、18 个新 Issue；最新增加 Muse Code 1.4.2 的 `AGENTS.md` 与 Skill 适配。
- **爆发原因**：项目用极短规则直指 Agent 过度设计，并持续增加宿主适配，降低了团队试用成本。
- **亮点**：作者分布健康；把质疑需求、优先删除和最小变更固化成可安装检查清单。
- **潜在风险**：规则无法替代权限、安全和测试设计；宿主增多后，Hook 与指令优先级的兼容性回归成本上升。
- **适合人群与关注程度**：希望抑制编码 Agent 复杂度、统一 `AGENTS.md` 规范的团队；**★★★★☆**。

- **主要用途**：为编码 Agent 提供前端设计语言、设计命令、浏览器迭代流程和确定性“AI 味”检测规则。
- **技术栈**：JavaScript、Node.js CLI、浏览器扩展、Markdown Skill 与静态规则；Apache-2.0。
- **近期增长及口径**：约 **+1,171 Star/24h、+4,242 Star/7d**，相对日增约 **1.56%**。当前 76,269 Star、4,549 Fork，Fork 较上期 +33；由第五升至第二。
- **贡献与讨论**：近 7 天 56 次提交、4 个作者身份、17 个新 Issue；最新仍集中在同步各 Provider 的生成输出。
- **爆发原因**：前端团队需要减少模板化 AI 界面，并把产品事实、视觉方向和浏览器审计固化进生成流程。

### 7. tester-army/e2e

- **主要用途**：用自然语言描述目标，让 Agent 驱动 Web 或移动应用，再用 Locator 与 Assertion 验证结果；成功路径可重放而无需再次调用模型。
- **技术栈**：TypeScript、Playwright、iOS/Android 模拟器、Agent Decision Model、CLI 与 GitHub Reporter；Apache-2.0。
- **近期增长及口径**：约 **+345 Star/24h**，相对日增约 **12.6%**；7 天直接值缺失。当前 3,081 Star、116 Fork；首次进入近期前十。
- **贡献与讨论**：近 7 天提交 **≥100**、约 19 个作者身份、34 个新 Issue；最新更新项目级 `AGENTS.md`。
- **爆发原因**：纯自然语言测试缺乏可复现性，而传统 E2E 又脆弱；“Agent 探索、确定性断言、成功路径重放”的组合切中两者之间的空档。
- **亮点**：模型调用被限制在语义动作与断言，后续可零模型重放；Web 与移动端采用统一测试思路，并支持自带模型或订阅。
- **潜在风险**：仍在走向 1.0，次版本可能改变 API；CLI 默认匿名遥测需按企业要求关闭，模型驱动步骤仍要防止不确定性和越权操作。
- **适合人群与关注程度**：前端/移动测试、CI、低代码流程与 Agent QA 团队；**★★★★★**。

1. **Agent 控制面开始替代单一 IDE 插件。** `t3code` 统一多个本机 Agent，`pstack-claude` 迁移工作流，`ponytail` 与 `agent-skills` 迁移规则；竞争点从“调用哪个模型”转向宿主、路由、权限和审查。

## 最值得深入研究的 3 个项目

### 1. tester-army/e2e

它把“Agent 理解目标”与“确定性 Locator/Assertion 验证”拆开，并将成功动作录制后重放，正好对应企业 E2E 测试中智能性与稳定性的冲突。对 Vue 前端、Java 微服务和低代码流程页面，它尤其适合验证跨页面业务链路。研究重点应放在重放失效检测、模型步骤权限、移动端一致性与关闭遥测后的完整行为。

### 2. t3code

t3code 把 Codex、Claude Code、Cursor、OpenCode 等工具统一到本地服务、桌面/Web 和手机控制面，代表编码 Agent 从单工具走向多宿主管理。100+ 提交和 23 个作者说明生态正在快速形成，但 100+ 新 Issue 也显示仍处早期。建议重点研究 Provider 适配层、远程连接、权限批准和会话隔离，不宜直接暴露到公网。

### 3. claude-mem

claude-mem 以 100+ 周提交和约 40 个作者身份显示出很强的工程生命力。它与企业 Open Code Review、旧 Skill 迁移和长期知识库都有直接关联：可将审查结果、架构事实和历史决策跨会话复用。深入研究时应优先验证数据生命周期、敏感信息过滤、召回可解释性、记忆冲突与投毒防护。
