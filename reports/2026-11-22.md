## 统计口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 2026-11-21 日榜及同一采集时点语言榜的 `stars today`，读取于 2026-11-21 06:58 UTC；它是滚动窗口，不等于北京时间自然日。
2. **7 天新增 Star**：优先采用同一时点周榜直接值；未进入周榜时仅列站点保存的可见区间净增，并明确标注起点。无法构造可靠 7 天窗口时标“缺失”，不以累计 Star 代替。
3. **当前 Star/Fork**：采用 Trending 快照与 2026-11-21/22 附近 GitHub API 读取值。部分仓库只能取得四舍五入值，统一加 `≈`；不同页面分钟级读取差异会造成少量偏差。
4. **Fork 较上期**：仅对上一期主榜中的持续项目计算；重新上榜项目没有上一期主榜基线，标“缺失”。
5. **工程活跃度**：统计 2026-11-15 00:00 UTC 起约 7 天默认分支提交；每仓库最多读取 100 条，达到上限记为 `≥100`。
6. **贡献者身份**：接口未稳定返回作者登录名或邮箱，本期统一标“缺失”；提交量只表示活动频率，不等于独立贡献者数。
7. **讨论热度**：统计同一窗口新建的 Issue/PR 线程，最多 100 条；接口无法稳定分离两类对象，统一称“新议题”。机器人、模板、重复工单和自动发布可能放大数量。
8. **综合排序**：综合 24h/7d Star、相对增速、Fork、提交、讨论质量、许可证与部署风险，不是 GitHub Trending 原始顺序。
9. **严格开源筛选**：主榜要求存在可核验的标准开源许可证。`app-store-compliance` 使用自定义 OpenRoots Agent License 2.3，`cursor/plugins` 没有可识别的根许可证，故未纳入主榜。`LoopForge` 的 GitHub API 未识别 SPDX，但根 `LICENSE` 明确为 MIT，故纳入。

## 项目分析

### 1. elementalsouls/Claude-BugHunter

- **主要用途**：为 Claude Code 提供漏洞挖掘与外部红队 Skill 包，覆盖 24 类漏洞、企业身份和基础设施攻击矩阵。
- **技术栈**：Python、Shell/PowerShell、Claude Code Skills、漏洞模式库、命令行引擎与报告模板；MIT。
- **近期增长及口径**：约 **+1,622 Star/24h**，11 月 14 日以来快照净增约 +8,871；采集时 14,702 Star、Fork 约 1,700，由第二升至第一。
- **贡献与讨论**：近七日约 80 次提交、11 个新议题；最新修复包括报告泄露本机登录名、Windows PowerShell 编码崩溃和 HackerOne 查询边界。
- **爆发原因（推断）**：将大量已披露漏洞模式包装为 Agent 可调用技能，能够快速形成侦察、验证、报告和平台对接流程。
- **亮点**：覆盖面广，漏洞类别、命令、矩阵和报告模板结构化程度高；近期仍有大量实质修复。
- **潜在风险**：具备攻击性能力，只能在明确授权范围内使用；规则数量不等于准确率，误报、漏报、敏感信息落盘和平台封禁都需要控制。
- **适合人群与关注程度**：经授权的渗透测试、Bug Bounty、AppSec 与红队研究人员；**★★★★☆**。

### 2. firecrawl/firecrawl

- **主要用途**：为 Agent 提供搜索、抓取、结构化抽取、浏览器交互及 550 多个数据源的统一知识入口。
- **技术栈**：TypeScript/Node.js、爬虫与浏览器、队列、PDF/HTML 转 Markdown、REST API、SDK 与自托管组件；AGPL-3.0。
- **近期增长及口径**：约 **+1,241 Star/24h**，11 月 19 日以来快照净增约 +2,017；当前 206,066 Star、10,774 Fork，Fork +55，由第六升至第二。
- **贡献与讨论**：近七日约 82 次提交、16 个新议题；新增托管 MCP 代理密钥与联系人过滤，问题涉及 robots.txt 延时单位、Markdown 内容协商、PDF 和私网目标。
- **爆发原因（推断）**：Agent 的瓶颈正从模型本身转向新鲜、可解析、可引用且合规的数据摄取；统一搜索、抓取和 Provider 接口具有平台价值。
- **亮点**：覆盖网页、PDF、浏览器与结构化抽取，同时提供托管服务和开源自托管路径；高涨星与持续提交同步。
- **潜在风险**：AGPL 对网络服务部署有源码义务；抓取受 robots、版权、站点条款和隐私约束，SSRF、队列成本与数据保留策略必须审计。
- **适合人群与关注程度**：RAG、Agent 知识摄取、搜索、数据管道和自托管平台团队；**★★★★★**。

### 3. Tencent/LoopForge

- **主要用途**：把 Codex、Claude Code、CodeBuddy 等编码 Agent 编排为可自托管的交付工作流，提供 SOP、脚本、审批门禁和代码托管集成。
- **技术栈**：Go 控制面、TypeScript/Web 前端、工作流编排、沙箱/执行器、GitHub/GitLab 集成与模型 Provider；根许可证 MIT。
- **近期增长及口径**：约 **+1,216 Star/24h**，相对昨日基础增长约 30%；当前约 5,300 Star、734 Fork。11 月 20 日主榜快照以来净增约 +1,389，重新上榜第三。
- **贡献与讨论**：近七日约 71 次提交、67 个新议题；焦点包括 CodeBuddy 可选化、SOP 角色绑定、多上游网关、GitHub OAuth 信任边界和运行状态/Token/产物可观测性。
- **爆发原因（推断）**：团队开始需要的不只是“能写代码”的 Agent，而是可恢复、可审计、可审批并能纳入 PR/MR 的交付控制面。
- **亮点**：覆盖执行器、SOP、人工门禁和托管平台衔接；增长、提交和真实需求讨论三类信号同时强。
- **潜在风险**：项目仍快速演进，凭据、执行器隔离、失败恢复、模型路由和审批语义尚在收敛；高权限部署前必须做租户隔离和密钥审计。
- **适合人群与关注程度**：企业 AI 工程平台、DevOps、内部开发者平台和多 Agent 编排团队；**★★★★★**。

### 4. obra/superpowers

- **主要用途**：用可组合 Skills 为编码 Agent 建立从头脑风暴、规划、实现、测试到评审的软件开发方法论。
- **技术栈**：Shell、Markdown/Agent Skills、插件命令、测试脚本及多客户端适配；MIT。
- **近期增长及口径**：约 **+890 Star/24h**，11 月 17 日以来快照净增约 +4,336；当前 323,562 Star、28,704 Fork，Fork +60，由第一降至第四。

- **爆发原因（推断）**：技能化开发纪律能跨多个编码 Agent 复用，传播门槛低，在 Agent 用户扩张期容易持续吸引关注。

- **潜在风险**：涨星与零提交继续背离，短期动量主要由传播驱动；文档与实现漂移、客户端提示注入差异会影响可重复性。

### 5. jingyaogong/minimind

- **主要用途**：用小规模代码和数据演示从零预训练、微调、蒸馏与部署一个约 64M 参数语言模型。
- **技术栈**：Python、PyTorch、Tokenizer、预训练/SFT/DPO、ModelScope/Hugging Face 数据与推理脚本；Apache-2.0。
- **近期增长及口径**：约 **+847 Star/24h**，11 月 17 日以来快照净增约 +2,208；当前 68,086 Star、8,902 Fork，Fork +84，由第十升至第五。
- **贡献与讨论**：近七日约 23 次提交、3 个新议题；更新覆盖生僻字符和 CJK 重复惩罚，问题集中在 Apple Silicon 与 PyArrow/NumPy 依赖冲突。
- **爆发原因（推断）**：“两小时从零训练小模型”降低了理解预训练全流程的门槛，适合教学与个人硬件实验。
- **亮点**：模型小、链路完整，便于观察数据、Tokenizer、训练、对齐和推理之间的真实关系。
- **潜在风险**：教学模型效果不能外推到大模型生产系统；数据许可、复现实验、依赖版本和硬件差异需要单独核验。
- **适合人群与关注程度**：LLM 初学者、课程、训练流程研究与低成本实验团队；**★★★★☆**。

### 6. HKUDS/CLI-Anything

- **主要用途**：为桌面软件和专业工具生成统一 CLI，使 Agent 能以命令方式调用原本只有 GUI 的能力。
- **技术栈**：Python、Click/CLI、软件适配器、测试与文档生成、Hub 包管理；Apache-2.0。
- **近期增长及口径**：约 **+773 Star/24h**，11 月 18 日以来快照净增约 +2,361；当前 61,988 Star、5,616 Fork，Fork +102，由第五降至第六。
- **贡献与讨论**：近七日默认分支 0 次提交、11 个新议题；问题涉及 Windows 进程检测、3D/办公软件适配和新工具贡献。
- **爆发原因（推断）**：Agent 操作 GUI 易受布局和视觉误差影响，把软件能力转成确定性 CLI 可以提高可重复性和自动化密度。
- **亮点**：适配器可把设计、文档、3D 等工具纳入 Agent 工作流，并便于测试和审计。
- **潜在风险**：七日零提交与强涨星背离；自动生成 CLI 很难完整覆盖 GUI 语义，文件覆盖、平台兼容和数值边界需沙箱验证。
- **适合人群与关注程度**：Agent Tool、桌面自动化、CLI 设计和专业软件集成团队；**★★★☆☆**。

### 7. alibaba/open-code-review

- **主要用途**：以确定性规则管线和 LLM Agent 混合方式做仓库级代码审查，并输出行级缺陷与安全评论。
- **技术栈**：Go CLI、规则引擎、仓库级上下文、OpenAI/Anthropic 兼容接口、GitHub/GitLab CI；Apache-2.0。
- **近期增长及口径**：24 小时直接值缺失；约 **+4,457 Star/7d**。当前 55,055 Star、4,558 Fork，Fork +47，连续第七。
- **贡献与讨论**：近七日约 41 次提交、22 个新议题；新增 Token 用量展示，讨论覆盖无行号发现、换行规范化、原生 Review 的影响分析与失败语义。
- **爆发原因（推断）**：企业需要把生成式审查接入 CI，同时保留确定性规则、失败语义和可审计评论，混合架构比纯聊天式 Review 更易治理。
- **亮点**：覆盖多类静态规则、仓库上下文、会话比较和多 Provider，适合渐进接入现有流水线。
- **潜在风险**：错误退出码、无限重试和“假通过”会削弱门禁可信度；代码与提示可能外发，必须限制权限、脱敏并保留人工审批。
- **适合人群与关注程度**：企业代码审查、DevSecOps、CI 平台和 LLM 治理团队；**★★★★★**。

### 8. kajisho5/ffmpeg-skill

- **主要用途**：为 Claude Code、Cursor、Codex 等 Agent 提供本地视频剪辑、字幕、画幅、响度和平台导出能力。
- **技术栈**：Python、FFmpeg/FFprobe、Whisper、MCP Server、机器可读工具契约与 npm 安装入口；MIT。
- **近期增长及口径**：24 小时直接值缺失；约 **+3,268 Star/7d**。当前约 9,000 Star、819 Fork，Fork +32，由第九升至第八。
- **贡献与讨论**：近七日提交 **≥100**、74 个新议题；发布节奏密集，问题涉及裁剪语义、时间轴/章节偏移、NVENC、测量状态和自动化守卫。
- **爆发原因（推断）**：视频 Agent 的真实门槛是把复杂 FFmpeg 参数封装为可发现、可组合、可验证的本地工具契约。
- **亮点**：无需云 API Key，覆盖从探测到交付，可用 FFprobe 验证输出，适合隐私视频和批处理。

- **适合人群与关注程度**：短视频自动化、媒体流水线、字幕音频处理与 MCP/Agent Tool 开发者；**★★★★★**。

## 当天技术趋势

1. **Agent 基础设施从“能力包”走向“控制面”**：`LoopForge` 的执行器、SOP、审批和托管平台集成说明团队重点已转向可恢复、可观测和可审计的交付过程。
2. **数据摄取仍是模型之外的关键瓶颈**：`Firecrawl` 的涨星与提交同步增强，真实问题已深入 robots、内容协商、PDF 和私网边界，说明市场从 Demo 进入生产可靠性阶段。

4. **企业落地围绕质量与失败语义**：`Open Code Review` 的持续周增与工程活动表明，代码审查、Token 可见性、退出码和可审计评论比“生成更多代码”更接近稳定价值。
