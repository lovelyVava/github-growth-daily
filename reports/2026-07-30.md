## 三、项目逐项分析

### 1. virgiliojr94/book-to-skill

- **主要用途**：把技术书 PDF 转换为可供 Claude Code/Codex 等编码 Agent 检索和调用的 Skill，兼顾学习、查阅与工作流复用。
- **技术栈**：Python、PDF 文本提取、Markdown/Skill 目录结构；MIT 许可证仅覆盖转换工具本身。
- **近期增长**：约 **+1,428 Star/24h**，当前 12,526 Star、1,406 Fork；日增较昨日 +366 提高约 **290%**。当前开放 3 个 Issue、13 个 PR；提交总数页面抓取异常，最新可靠快照为昨日 89 次，故不据此判断今日提交增量。
- **爆发原因**：把“读一本书”直接转化为 Agent 可复用能力，击中了 Skill 生态与个人知识库结合的需求；产物直观、演示传播成本低。
- **亮点**：从长文档到结构化技能的一站式流程；适合作为内部文档、SDK 手册和技术规范的 Agent 化模板。
- **潜在风险**：转换结果可能丢失上下文或生成错误摘要；书籍版权通常不因转换工具的 MIT 许可证而改变，上传、共享和二次分发需单独确认授权。
- **适合人群**：Agent 工程师、技术培训团队、需要把内部文档变成 Codex/Claude Skills 的开发者。
- **值得关注程度**：**★★★★★**。增长强、用途清晰，但应优先处理自有或获授权内容。

### 2. pascalorg/editor（Pascal Editor）

- **主要用途**：浏览器中的 3D 建筑/空间编辑器，也可作为结构化场景编辑、关卡编辑和可扩展节点系统的架构参考。
- **技术栈**：React 19、Next.js 16、Three.js WebGPU、React Three Fiber、Zustand、Zod、Zundo、Turborepo、Bun；MIT。
- **近期增长**：约 **+1,026 Star/24h**，当前 19,454 Star、2,585 Fork；较昨日 Fork +66，日增速提高约 **147%**。当前约 1,237 次提交、15 个 Issue、18 个 PR，较昨日约 +1 次提交、+2 个 PR。
- **爆发原因**：完整可运行的 WebGPU 3D 编辑器稀缺；节点模型、插件系统、脏节点增量更新、撤销/重做等设计对游戏与数字孪生开发者都很有吸引力。
- **亮点**：编辑器与 Viewer 分包；场景状态、渲染注册表和工具层职责清晰；插件使用与内置节点相同的 manifest。
- **潜在风险**：WebGPU 兼容性与大型场景性能仍需实测；建筑语义不能直接等价为游戏关卡语义；快速演进可能带来 API 变动。
- **适合人群**：Web 3D、数字孪生、室内设计、关卡/地图编辑器开发者。
- **值得关注程度**：**★★★★★**。尤其值得借鉴数据模型和编辑器分层。

- **技术栈**：以 Markdown/Python 生态资源为主；仓库未识别到明确开源许可证。
- **近期增长**：约 **+950 Star/24h**，当前 10,292 Star、1,342 Fork；较昨日 Fork +55，日增速提高约 **136%**。约 129 次提交、9 个 Issue、37 个 PR，提交总数未变、PR 约 +1。

- **亮点**：覆盖研究到实盘链路，包含中文入口，适合快速建立领域地图。

- **值得关注程度**：**★★★★☆**。适合学习导航，不应据此直接交易。

### 4. affaan-m/ECC

### 5. huggingface/speech-to-speech

- **主要用途**：用开源模型搭建本地实时语音 Agent，将 VAD、STT、LLM、TTS 组合成可替换流水线。
- **技术栈**：Python、PyTorch/Transformers、Silero VAD、Whisper 等语音模型、Docker；Apache-2.0。
- **近期增长**：约 **+837 Star/24h**，当前 7,774 Star、993 Fork；较昨日 Fork +51，日增从 +177 提高约 **373%**。约 634 次提交、82 个 Issue、33 个 PR；较昨日约 +4 次提交、PR +3，保持活跃。
- **爆发原因**：实时语音交互已成为 AI 伴侣、游戏 NPC、客服与桌面助手的共同入口；本地化降低隐私和 API 依赖。
- **亮点**：组件可替换、支持 Docker 与 ARM64，便于比较不同模型的延迟与效果。
- **潜在风险**：低延迟需要合适 GPU/CPU 与量化策略；多模型许可证、音色授权、录音隐私和内容安全需逐项核对；不同语言的识别与合成质量差异大。
- **适合人群**：语音 Agent、AI NPC、客服机器人和边缘端推理开发者。
- **值得关注程度**：**★★★★★**。增长加速且应用路径直接。

- **技术栈**：Shell、Markdown、插件 manifest、测试/评测脚本；MIT。

1. **知识正被包装成 Agent 可执行资产**  
   `book-to-skill` 把书籍转成 Skills，`ECC` 与 `superpowers` 把工程经验变成自动触发流程。热点已从“提示词集合”转向可安装、可验证、可复用的能力包。

2. **Agent 竞争进入 harness 和工程治理阶段**  
   `jcode` 竞争资源效率，`open-code-review` 竞争审查稳定性，`ECC`/`superpowers` 竞争开发方法论。模型能力趋同后，流程、上下文、工具调度、安全与成本开始决定体验。

3. **实时、多模态交互持续升温**  
   `speech-to-speech` 与 `AIRI` 分别代表底层实时语音管线和上层 AI 角色容器。对游戏开发而言，语音、记忆、Avatar 和环境行动正在形成可组合栈。

4. **复杂创作工具继续向浏览器迁移**  
   `Pascal Editor` 的 WebGPU 3D 编辑与 `GeoLibre` 的 WASM GIS 分析，都显示浏览器正承担更多传统桌面工具工作负载。

5. **高增长不等于高成熟度**  
   `GeoLibre`、`jcode` 的相对增速很高，但 Issue 也快速累积；`awesome-systematic-trading` 许可证不明。采用前应同时检查维护活跃、许可证、数据安全和可复现实测。

## 六、最值得深入研究的 3 个项目

### 1. book-to-skill

**理由**：日增第一且加速最明显；更重要的是，它提供了一条可直接迁移到 Codex 的知识工程路线。可用自有 Unity 文档、技术方案或团队规范试做 Skill，验证“文档 → 可调用能力”的质量、引用和更新机制。

### 2. Pascal Editor

**理由**：不仅是成品编辑器，更是完整的结构化场景架构样本。节点 Schema、场景注册表、脏节点更新、插件 manifest、撤销/重做和编辑器/Viewer 分层，对地图编辑器与游戏工具链极具借鉴价值。

### 3. speech-to-speech

**理由**：日增速提高约 373%，项目又具备较完整的模块化语音流水线。它适合直接验证 AI NPC 的端到端延迟、打断处理、中文效果、本地硬件成本和多模型替换，而这些指标比单纯演示更接近产品决策。

> 次优先：`open-code-review` 适合研究 CI 审查工程化；`ECC` 与 `superpowers` 适合拆解 Agent 开发规范；`AIRI` 适合长期观察 AI 角色平台架构。

## 七、数据可靠性与限制

- **较可靠**：抓取时的累计 Star/Fork、Trending 页面显示的日/周新增 Star、当前开放 Issue/PR、仓库页面显示的提交总数。
- **估算**：相对日增按当前累计 Star 计算；24h Fork 增量为相邻两期快照差，不是 GitHub 官方 24h 指标。
- **缺失**：未进入周榜项目的精确 7 日新增 Star；GitHub 未公开任意仓库统一口径的 24h 新增贡献者、Issue 评论和 Discussions 热度。
- **活跃度代理**：本报告用提交总数变化、开放 Issue/PR 变化和周榜出现情况辅助判断；开放数量下降可能表示合并/关闭，并不等同于活跃度降低。
- **排序方法**：以日增 Star 为主排序，再结合周榜出现、Fork 快照差、提交与 Issue/PR 活跃度解释；不按累计 Star 排名。
