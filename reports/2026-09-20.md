## 项目分析

### 1. cloudflare/security-audit-skill

- **主要用途**：把编码 Agent 编排为多阶段安全审计器，覆盖侦察、覆盖账本、漏洞猎取、候选验证、结构化结论和独立复核。
- **技术栈**：Agent Skill/Markdown、JavaScript 零依赖验证器、JSON Schema、隔离子 Agent、机器可读 findings 与 coverage ledger；MIT。
- **近期增长及口径**：日榜约 **+3,162 Star**；周榜直接值缺失；相对日增约 **24.1%**。当前 16,286 Star、891 Fork，较上期 Fork约 **+163**，排名保持第一。
- **贡献与讨论**：近 7 天仅 1 次默认分支提交、10 个新 Issue；作者身份缺失。提交仍是澄清指导模式与完整审计模式。
- **爆发原因**：Cloudflare 的“覆盖可量化、结论可机读、发现者与验证者分离”方法论继续扩散，传播速度远高于代码更新速度。
- **亮点**：confirmed、needs_validation、rejected 三态清晰；覆盖账本避免把未检查区域默认为安全；多轮运行可复用证据并针对缺口继续审计。
- **潜在风险**：增长高度集中于传播；公开 Issue 涉及覆盖验证器与产物真实性边界。实际效果依赖模型、预算、目标可构建性、权限和沙箱，绝不能把榜首当安全认证。
- **适合人群**：获授权代码审计、AppSec、Agent 安全评估和希望建立可机读证据链的研发安全团队。
- **值得关注程度**：**★★★★☆**。方法论价值高，但必须用已知漏洞基准与人工复核验证。

### 2. trycua/cua

- **主要用途**：为 AI Agent 提供跨 macOS、Linux、Windows 的电脑操作能力，统一桌面、浏览器、沙箱、远程环境、模型训练与评测入口。
- **技术栈**：Python/TypeScript/Rust、CLI/MCP/SDK、macOS 虚拟化、Linux/Windows 沙箱、远程桌面、CUA-S1 研究组件；仓库标示 MIT，各模型/数据制品需单独核验。
- **近期增长及口径**：日榜约 **+1,124 Star**；周榜直接值缺失；相对日增约 **4.8%**。当前 24,383 Star、1,678 Fork；新上榜第二。
- **贡献与讨论**：近 7 天约 39 次默认分支提交、90 个新 Issue；作者身份缺失。近期引入 CUA-S1、表单模型制品、可选感知扩展 RFC、舰队分组和服务 WebSocket 目标。
- **爆发原因**：CUA-S1 发布叠加“真实桌面 + 浏览器 + 云沙箱 + Benchmark”一体化叙事，正面回应电脑操作 Agent 的可复现训练和部署需求。
- **亮点**：同一套 Driver 可跨操作系统；支持 CLI、MCP 和 SDK；加入 fail-closed 集成、凭据遮蔽、服务头防伪和确定性合成训练等工程约束。
- **潜在风险**：90 个新 Issue 显示扩张与兼容性压力，最新报告还涉及数据集一次性载入内存导致约 26GB 占用。真实登录态、桌面权限、远程服务和 Fleet 计费/回收策略都需要最小权限与强制销毁。
- **适合人群**：电脑操作 Agent、桌面自动化、浏览器任务、Agent Benchmark、沙箱和人机接管研究者。
- **值得关注程度**：**★★★★★**。研究面与产品面兼具，适合在测试账户和隔离 VM 中验证，不宜直接接入日常主机。

- **亮点**：覆盖多个岗位和 SaaS；结构文件化，适合审查、Fork 和企业定制；许可证清晰。
- **潜在风险**：每个连接器都引入新的凭据、数据流和供应链；高敏领域需要最小化数据、审批、审计和人工终审。合作伙伴插件不能因处于同一仓库就默认同等可信。
- **适合人群**：希望建立知识工作插件目录、岗位模板和 MCP 权限清单的企业 Agent 团队。
- **值得关注程度**：**★★★★☆**。适合作为目录与结构参考，部署应逐插件审计。

### 9. cactus-compute/needle

- **主要用途**：在本地设备上运行极小型、低内存的工具调用和结构化提取模型，强调隐私、离线与毫秒级交互。
- **技术栈**：Rust 单文件运行时、Python/JAX 训练工具、约 121M 参数 2-bit 模型、Laddered Simple Attention、字节级 Grammar、LoRA 与 Hugging Face 制品；Apache-2.0。
- **近期增长及口径**：日榜约 **+207 Star**；周榜直接值缺失；相对日增约 **1.8%**。当前 11,594 Star、741 Fork；新上榜第九。
- **贡献与讨论**：近 7 天约 18 次提交、4 个新 Issue；作者身份缺失。近期更新默认模型、修复 Playground rewind，并有 LoRA 导出行为不一致报告。
- **爆发原因**：8–29MB 单文件、工具调用、结构化抽取和离线运行，将“端侧 Agent 不必依赖大模型 API”变成容易演示的产品主张。
- **亮点**：模型极小、内存占用低、支持 Grammar 约束和置信度；本地数据不必出设备，适合固定领域工具路由。
- **潜在风险**：121M 2-bit 模型的通用性、鲁棒性和越界输入表现需要严谨基准；LoRA 导出已出现一致性 Issue。代码许可证不自动覆盖权重、数据集和外部引擎。
- **适合人群**：移动端/边缘推理、隐私助手、固定 Schema 抽取、工具调用路由和小模型研究者。
- **值得关注程度**：**★★★★★**。最适合做可控小实验：固定任务集、端侧延迟、内存和准确率都能量化。

### 10. docling-project/docling

- **主要用途**：把 PDF、DOCX、PPTX、XLSX、HTML、EPUB、邮件、音频和视频等内容解析为结构化文档与 Markdown，服务 RAG、搜索和 Agent 证据摄取。
- **技术栈**：Python、PDF 布局/表格/公式解析、OCR、VLM、CLI/API/MCP，以及 LangChain、LlamaIndex、Haystack 等集成；MIT。
- **近期增长及口径**：日榜约 **+94 Star**；周榜直接值缺失；相对日增约 **0.1%**。当前 67,026 Star、4,833 Fork；新上榜第十。
- **贡献与讨论**：近 7 天约 29 次提交、14 个新 Issue；作者身份缺失。近期发布 2.129.0，改进 Chandra OCR 解析并重构图表抽取引擎选项。
- **爆发原因**：文档 Agent 和 RAG 开始重视版面、表格、公式、图表和来源追溯，Docling 的本地/气隙运行与广泛格式支持持续受益。
- **亮点**：解析范围广、可本地运行、输出结构化；OCR/VLM 可按场景选择；生态集成成熟，适合作为证据链入口。
- **潜在风险**：复杂 PDF、扫描件、跨页表格和混合语言仍需数据集验证；依赖模型可能带来下载、显存、速度和许可证差异。Markdown 输出不能自动保留所有视觉语义。
- **适合人群**：OCR、RAG、企业文档搜索、论文/报告解析、Agent 知识摄取与气隙部署团队。
- **值得关注程度**：**★★★★★**。增长不算最高，但与真实文档工作流高度相关，工程活动和生态信号扎实。
