## 项目分析

### 1. GoogleChrome/modern-web-guidance-src

- **主要用途**：把现代 Web API、性能、可访问性和兼容性实践以可检索 Skill 注入编码 Agent，并扫描遗留模式。
- **技术栈**：TypeScript、Node.js/npm CLI、静态分析器、评测 Harness、文档与 Dashboard；Apache-2.0。
- **近期增长及口径**：约 **+1,219 Star/24h**，相对日增约 **19.5%**；完整七日值缺失，11 月 11 日以来可见净增约 +5,819。当前 7,478 Star、645 Fork，Fork +174，连续第一。
- **贡献与讨论**：近七日约 91 次提交、47 个新议题；最新工作覆盖 Eval 向量、部分测试集评分和 JavaScript 指南检索。新议题包括已发布包缺少 CLI 文件、`legacy-scan` 对 dialog 规则的漏检和包管理器兼容问题。
- **爆发原因（推断）**：模型容易复现训练数据中的旧式 Web 模式；由 Chrome 生态维护、可检索、可扫描且带 Eval 的规则层直接补上编码 Agent 的知识时效缺口。
- **亮点**：专家知识、Token 友好检索、静态检查和公开评测形成闭环，不只是提示词集合。
- **潜在风险**：当前仍存在发布包入口、规则冲突与扫描漏检；浏览器能力快速变化，规则必须持续更新，不能当作永久正确的静态规范。
- **适合人群与关注程度**：前端平台、编码 Agent、Web 性能、可访问性与代码评审团队；**★★★★★**。

### 2. backnotprop/plannotator

- **主要用途**：在多 Agent 工作与人类之间提供本地审阅界面，集中展示问题、计划、原型、文档与代码 Diff，让人工批注直接回到原 Agent 会话。
- **技术栈**：TypeScript、Bun、浏览器本地界面、MCP、Agent 插件/Hooks、Git/GitLab/GitHub/Jujutsu/Perforce 集成；Apache-2.0。
- **近期增长及口径**：约 **+866 Star/24h、+1,719 Star/7d**，相对日增约 **7.7%**。当前 12,050 Star、1,121 Fork，Fork +148，由第五升至第二。
- **贡献与讨论**：近七日提交 **≥100**、59 个新议题；最新工作集中在 Inbox 计划页、线程视图和多 Agent 路由。工单包括 Pi 会话回复丢失、MCP 会话收不到规则与子模块 Diff 聚合。
- **爆发原因（推断）**：多 Agent 并行后，瓶颈从“生成更多代码”转向“人如何看到关键决策并异步反馈”；Inbox 提供了跨 Agent 的人工控制面。
- **亮点**：默认本地保存计划、Diff 与批注；支持本地代码、GitHub PR、GitLab MR 和多种 Agent，反馈可回到发起会话。
- **潜在风险**：Ask AI、远程 PR/MR、URL 抓取和分享会让选定内容离开本机；企业部署应关闭非必要联网与分享，并审查模型提供方的数据边界。
- **适合人群与关注程度**：多 Agent 编排、企业代码评审、产品/架构审批与 GitLab 工作流团队；**★★★★★**。

### 3. dream-num/univer

- **主要用途**：在产品中嵌入表格、文档、计算、协作与文件处理能力，并让 Agent 通过统一 API 操作 Office 内容。
- **技术栈**：TypeScript、Canvas 渲染、公式引擎、插件/依赖注入、Facade API、Web/Server/AI SDK、pnpm Monorepo；开源核心 Apache-2.0。
- **近期增长及口径**：约 **+988 Star/24h**，相对日增约 **3.9%**；完整七日值缺失，11 月 11 日以来可见净增约 +3,432。当前 26,604 Star、2,419 Fork，Fork +123，由第十升至第三。
- **贡献与讨论**：近七日约 50 次提交、15 个新议题；近期修复数字校验、条件格式并共享超链接编辑组件。问题涉及会计负数、排序语义与专业包误报恶意软件告警。
- **爆发原因（推断）**：Agent 从生成文本转向编辑真实业务文档，需要可嵌入、可计算、可撤销并能接入应用权限的 Office 执行层。
- **亮点**：开源核心包含内容模型、命令、公式、渲染与 Facade API，可用于结构化、可撤销的业务操作。
- **潜在风险**：开源 Web SDK 核心与商业插件、Server SDK、AI SDK 扩展存在功能边界；公式兼容、协作冲突、文档保真和供应链告警需用真实样本验证。
- **适合人群与关注程度**：企业办公平台、低代码、文档 Agent、表格自动化与嵌入式编辑器团队；**★★★★★**。

### 4. Tencent/LoopForge

- **主要用途**：自托管编码 Agent 交付工作台，用聊天或标准化 SOP 串联规划、实现、测试、独立评审、人类审批和 PR/MR。
- **技术栈**：Go 平台、Docker/Compose 沙箱、MySQL、Web 控制台、Node.js 本地 CLI、GitHub/GitLab 与多种 Agent CLI；MIT（第三方组件保留各自许可）。
- **近期增长及口径**：约 **+423 Star/24h**，相对日增约 **29.7%**；完整七日值缺失，11 月 11 日以来可见净增约 +1,536。当前 1,846 Star、306 Fork，新上榜第四。
- **贡献与讨论**：近七日提交 **≥100**、56 个新议题；最新提交新增 MR 节点与主机侧验证、按保存者凭据执行计划任务、需求直达对话和回收工作区恢复。工单集中在 OpenCode/Cursor 等执行器兼容与本地插件注入。
- **爆发原因（推断）**：团队开始要求 Agent 交付具备固定阶段、确定性脚本、人类门禁、可恢复运行和 MR 证据，而不只是一次性聊天产出。
- **亮点**：Agent、脚本、人类门禁和子 SOP 可组合；每步保留日志、产物与状态，并支持重试、回退和接管。
- **潜在风险**：默认 Docker 沙箱通过宿主 Docker socket 启动，文档明确这不适合不可信多租户；实例默认监听所有接口且团队成员可读实例内项目数据。上线前必须收紧注册、网络、凭据、仓库权限和宿主隔离。
- **适合人群与关注程度**：研发效能、Agent 平台、内网交付、GitOps 与需要人工审批的团队；**★★★★★**。

### 5. alibaba/open-code-review

- **主要用途**：混合确定性流水线与 LLM Agent 的代码评审 CLI，提供精确行级评论、全文件扫描和多语言规则。
- **技术栈**：Go CLI、Git、npm 分发、模板化规则、并发子 Agent、OpenAI/Anthropic 兼容模型接口；Apache-2.0。
- **近期增长及口径**：约 **+691 Star/24h**，相对日增约 **1.3%**；完整七日值缺失，11 月 11 日以来可见净增约 +2,567。当前 52,404 Star、4,184 Fork，Fork +204，由第三降至第五。
- **贡献与讨论**：近七日约 32 次提交、16 个新议题；近期修复不同路径写法的会话比较、Unicode 文件名截断和带点 MCP 服务名配置。工单涉及 OAuth 回调关闭、生成文件识别和 Windows 取消逻辑。
- **爆发原因（推断）**：文件选择、规则匹配与评论定位由确定性工程约束，动态上下文交给 Agent；这种混合架构比纯提示词评审更适合企业流程。
- **亮点**：公开基准覆盖多仓库、真实 PR 与多语言，并强调高精度、较低 Token 成本和大变更集覆盖。
- **潜在风险**：以精度换取一定召回率，不能把“少误报”误解为“无漏报”；模型端点、源码、Diff 与 API Key 的隔离、保留和成本仍需企业自行治理。
- **适合人群与关注程度**：企业代码评审、研发效能、AppSec、GitHub/GitLab 流水线团队；**★★★★★**。

### 8. ag-ui-protocol/ag-ui

- **主要用途**：定义 Agent 与用户界面之间的轻量事件协议，使运行状态、工具调用、上下文和人机协作可以跨框架流式传输。
- **技术栈**：TypeScript 核心与协议 Schema、多语言 SDK、事件流、前端客户端、中间件及多种 Agent 框架集成；MIT。
- **近期增长及口径**：约 **+355 Star/24h**，相对日增约 **2.0%**；完整七日值缺失，11 月 14 日以来可见净增约 +848。当前 18,157 Star、1,868 Fork，新上榜第八。
- **贡献与讨论**：近七日约 60 次提交、14 个新议题；近期加强事件联合类型校验和代码审查配置。工单包括 LangGraph 每请求工厂、事件流 v3、AWS Strands 系统提示结构和 malformed outcome 校验。
- **爆发原因（推断）**：Agent 后端和前端框架快速分化，团队需要一个比自定义 WebSocket 消息更稳定、比单一 SDK 更中立的交互层。
- **亮点**：事件模型适合流式状态、工具调用和人工介入，并通过多语言 SDK 与框架适配降低前后端耦合。
