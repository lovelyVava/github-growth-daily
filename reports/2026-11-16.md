## 项目分析

### 1. GoogleChrome/modern-web-guidance-src

- **主要用途**：把现代 Web API、性能、可访问性和兼容性实践以可检索 Skill 注入编码 Agent，并扫描遗留模式。
- **技术栈**：TypeScript、Node.js/npm CLI、静态分析器、评测 Harness、文档与 Dashboard；Apache-2.0。
- **近期增长及口径**：约 **+1,231 Star/24h**，相对日增约 **24.3%**；完整七日值缺失，11 月 11 日以来可见净增约 +4,644。当前 6,303 Star、471 Fork，Fork +192，连续第一。
- **贡献与讨论**：近七日提交 **≥100**、54 个新议题。近期工作覆盖 JavaScript discipline、SCSS/Less、Lit、Glimmer 扫描和 legacy-scan 性能；问题包括 IME 安全 Enter 检测与更多 Agent 适配。
- **爆发原因（推断）**：模型容易复现训练数据中的旧式 Web 模式；由 Chrome 生态维护、可检索、可扫描且带 Eval 的规则层直接补上了编码 Agent 的知识时效缺口。
- **亮点**：专家知识、Token 友好检索、静态检查和公开评测形成闭环，不只是提示词集合。
- **潜在风险**：大型仓库文件上限、解析失败与跳过诊断仍需验证；浏览器能力快速变化，规则必须持续更新，不能当作永久正确的静态规范。
- **适合人群与关注程度**：前端平台、编码 Agent、Web 性能、可访问性与代码评审团队；**★★★★★**。

### 2. meta/astryx

- **技术栈**：React 19、TypeScript、StyleX、CSS 自定义属性、Storybook、pnpm Monorepo；MIT，当前仍处 Beta 阶段。
- **近期增长及口径**：周榜约 **+13,660 Star/7d**，相邻快照约 +250/24h。当前 28,307 Star、2,201 Fork；昨日未进入主榜，本期重新上榜第二。

- **爆发原因（推断）**：Meta 品牌、150+ 组件以及“人和 Agent 共用可预测 API/文档”的定位持续形成传播飞轮；周榜仍强，但日增已明显回落。
- **亮点**：组件、主题、模板、CLI、文档和可访问性测试形成完整交付链；预编译 CSS 降低消费者接入门槛。
- **潜在风险**：Beta API、React 19 依赖和极高变更频率会增加迁移成本；88 个新议题意味着生产采用前仍需自行做可访问性与回归验证。
- **适合人群与关注程度**：设计系统、前端平台、React、可访问性和 Agent UI 生成团队；**★★★★★**。

### 3. alibaba/open-code-review

- **主要用途**：混合确定性流水线与 LLM Agent 的代码评审 CLI，提供精确行级评论、全文件扫描和多语言规则。
- **技术栈**：Go CLI、Git、npm 分发、模板化规则、并发子 Agent、OpenAI/Anthropic 兼容模型接口；Apache-2.0。
- **近期增长及口径**：约 **+893 Star/24h**，相对日增约 **1.8%**；完整七日值缺失，11 月 11 日以来可见净增约 +1,733。当前 51,570 Star、3,980 Fork，Fork +194，由第五升至第三。

- **爆发原因（推断）**：文件选择、规则匹配与评论定位由确定性工程约束，动态上下文交给 Agent；这种混合架构比纯提示词评审更适合企业流程。
- **亮点**：公开基准覆盖 50 个仓库、200 个真实 PR、10 种语言，并强调高精度、较低 Token 成本和大变更集覆盖。
- **潜在风险**：项目承认以精度换取一定召回率，不能把“少误报”误解为“无漏报”；模型端点、源码、Diff 与 API Key 的隔离、保留和成本仍需企业自行治理。
- **适合人群与关注程度**：企业代码评审、研发效能、AppSec、GitHub/GitLab 流水线团队；**★★★★★**。

### 4. google/elephant-goldfish-model

- **主要用途**：以“带上下文的设计者 + 无前序对话的新鲜审阅者”工作流产出设计文档、复核盲点，并检查文档与代码漂移。
- **技术栈**：Agent Skills/插件、Markdown/YAML、Python 辅助工具、Astro 文档站，支持 Codex、Claude Code、Antigravity 等宿主；Apache-2.0。
- **近期增长及口径**：周榜约 **+5,539 Star/7d**，相邻快照约 +204/24h。当前 19,307 Star、1,431 Fork，Fork +32，维持第四。
- **贡献与讨论**：近七日约 42 次提交、26 个新议题；近期修复通过游离反引号绕过 mention-neutralization 的问题，并继续完善 Windsurf/Devin Desktop 适配与实现—设计一致性检查。
- **爆发原因（推断）**：它刻意让审阅者忘记前序对话，以暴露确认偏差和未说明假设，回应了 Agent 长上下文带来的“共同误判”问题。
- **亮点**：Brainstorm、Draft、Resolve、Review 与 Drift Report 分工明确；要求新子 Agent 上下文，能主动引入独立视角。
- **潜在风险**：审阅依赖宿主能创建新子 Agent；多 Agent 评审增加 Token、延迟与供应链面，也不能替代测试或人工架构决策。项目不是 Google 官方支持产品。
- **适合人群与关注程度**：架构设计、规范驱动开发、Agent 工作流与技术文档治理团队；**★★★★★**。

### 5. backnotprop/plannotator

- **主要用途**：在多 Agent 工作与人类之间提供本地审阅界面，集中展示问题、计划、原型、文档与代码 Diff，让人工批注直接回到原 Agent 会话。
- **技术栈**：TypeScript、Bun、浏览器本地界面、MCP、Agent 插件/Hooks、Git/GitLab/GitHub/Jujutsu/Perforce 集成；Apache-2.0。
- **近期增长及口径**：约 **+408 Star/24h、+818 Star/7d**，相对日增约 **3.7%**。当前 11,360 Star、973 Fork，首次进入本日报主榜第五。
- **贡献与讨论**：近七日提交 **≥100**、52 个新议题；最新迭代集中在 Inbox、多 Agent 稳定排序、测试与回复交互。工单包括启动独立工作不清晰、无法关闭自动 reload、移动端选择器被裁切。
- **爆发原因（推断）**：多 Agent 并行后，瓶颈从“生成更多代码”转向“人如何看到关键决策并异步反馈”；Inbox 正好提供了跨 Agent 的人工控制面。
- **亮点**：默认本地保存计划、Diff 与批注；支持本地代码、GitHub PR、GitLab MR 和多种 Agent，且回复能回到发起会话，不必长期占用 Agent。
- **潜在风险**：Ask AI、远程 PR/MR、URL 抓取和分享会让选定内容离开本机；默认会访问 GitHub 检查版本，托管 Workspaces 也不适用本地存储假设。企业部署应关闭非必要联网与分享，并审查模型提供方的数据边界。
- **适合人群与关注程度**：多 Agent 编排、企业代码评审、产品/架构审批与 GitLab 工作流团队；**★★★★★**。

- **爆发原因（推断）**：浏览器操作从重型 SDK 转向 Agent 友好的短命令、文本快照与可恢复会话，跨平台二进制降低部署门槛。

### 10. dream-num/univer

## 当天技术趋势

1. **多 Agent 的新瓶颈是人类审阅带宽。** `Plannotator` 的 Inbox 把决策、问题、原型和 Diff 汇入一个异步界面，说明竞争点正从“并行跑更多 Agent”转向“让人只看关键节点并可靠回传”。
2. **专业知识与运行时证据开始合流。** `Modern Web Guidance` 提供规则、扫描与 Eval，`Chrome DevTools MCP` 提供网络、控制台、性能和页面运行证据；二者组合比纯代码生成更接近可验证的前端 Agent。
3. **代码评审正在形成确定性控制面。** `Open Code Review` 用工程逻辑约束覆盖、分组、规则和定位，`Elephant–Goldfish Model` 用独立上下文约束确认偏差；两条路线都在减少模型自由度带来的漂移。
4. **Agent 执行面继续扩展到真实业务文档。** `Univer` 把表格、文档、公式、撤销和权限接入 Agent 工作流，意味着“办公 Agent”开始从聊天回答转向结构化、可回滚操作。
5. **周热度和当日动能明显分化。** `Meta Astryx` 周增仍超过 1.3 万，但相邻日增已降至约 250；报告因此同时保留日榜和周榜，不把峰值传播误当持续加速。
