## 统计口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 2026-11-19 日榜及同一采集时点语言榜的 `stars today`，读取于 2026-11-19 06:59 UTC；这是滚动窗口，不等于北京时间自然日。
2. **7 天新增 Star**：优先采用同一时点周榜直接值；未进入周榜的项目采用站点保存的相邻日期总 Star 净增，并明确注明“可见区间”，不能与周榜直接值完全等同。
3. **当前 Star/Fork**：采用同一快照附近的 GitHub API/Trending 数值；分钟级读取差异与四舍五入可能造成少量偏差。
4. **Fork 较上期**：仅对上一期主榜中持续上榜项目按相邻快照计算；新上榜项目没有同口径基线，记为“缺失”。
5. **工程活跃度**：统计 2026-11-13 00:00 UTC 起约 7 天默认分支提交；每仓库最多读取 100 条，达到上限记为 `≥100`。
6. **贡献者身份**：接口没有稳定返回作者登录名或邮箱，因此人数统一标“缺失”，不从提交文本猜测；提交量仅代表活动频率，不等同于独立贡献者数量。
7. **讨论热度**：统计同一窗口新建的 Issue/PR 线程，最多读取 100 条；接口不能稳定分离两类对象，统一称“新议题”。模板、机器人和重复工单可能放大数量。
8. **综合排序**：综合 24h/7d Star、相对增速、Fork、提交、讨论质量、许可证与部署风险；不是 GitHub Trending 原始顺序，也不按累计 Star 排名。
9. **开源范围**：主榜要求存在可核验的标准开源许可。`LoopForge` 的 GitHub API 未识别 SPDX，但根 `LICENSE` 明确声明 MIT，并保留第三方组件原许可，故纳入主榜。

## 项目分析

### 1. google-research/paper-orchestra

- **主要用途**：把研究想法、实验日志与素材交给多 Agent 流程，生成文献综述、图表和可投稿的 LaTeX 论文草稿。
- **技术栈**：Python、多 Agent 编排、LaTeX、Semantic Scholar/文献检索、LLM Provider API、绘图与论文模板；Apache-2.0。
- **近期增长及口径**：约 **+1,524 Star/24h**，11 月 16 日以来快照净增约 +3,187；当前 4,557 Star、565 Fork，Fork 较上期 +124，由第六升至第一。
- **贡献与讨论**：近七日仅 6 次默认分支提交、16 个新议题；问题集中在数据集缺失、图片 MIME 错误、无绘图模式丢图和 API Key 输出到日志。
- **爆发原因（推断）**：完整展示了“素材—检索—结构—图表—LaTeX”的科研 Agent 流水线，演示效果强且 Google Research 背书明显。
- **亮点**：把研究写作拆成可审计角色与产物，能够从非结构化实验材料生成论文工程，而不只是单轮润色。
- **潜在风险**：提交量低于传播热度；引用真实性、密钥保护、图片保真、作者责任、数据授权和学术不端风险必须人工把关。
- **适合人群与关注程度**：科研写作工具、多 Agent 编排、实验记录与 LaTeX 自动化团队；**★★★★☆**。

### 2. affaan-m/ECC

- **主要用途**：为 Claude Code、Codex、OpenCode、Cursor 等编码 Agent 提供 Skills、Instincts、Memory、安全规则和研究优先开发工作流。
- **技术栈**：JavaScript/Node.js、Shell、跨 Agent 配置与插件、MCP、技能/记忆文件、自动化测试；MIT。
- **近期增长及口径**：约 **+1,108 Star/24h**；11 月 13 日以来快照净增约 +4,339。当前 306,752 Star、45,158 Fork，新上榜第二。
- **贡献与讨论**：近七日提交 **≥100**、21 个新议题；近期合并 Antigravity/UI Canvas 集成与大量社区修复。问题包括技能快照过期、安装缺文件、OpenCode Agent 未安装和 CRLF 校验缺口。
- **爆发原因（推断）**：多编码 Agent 并存后，团队需要可迁移的 Harness 优化层，而不是为每个客户端重写提示、记忆、安全和评测规则。
- **亮点**：覆盖安装、上下文、技能、记忆、安全与研究流程，且跨多种 Agent；工程活动与讨论都很强。
- **潜在风险**：仓库规模和功能面极大，配置叠加可能产生冲突；安装器与生成脚本拥有高权限，必须审查来源、锁定版本并在隔离仓库验证。
- **适合人群与关注程度**：Agent 平台、开发者效率、编码规范、安全与多客户端治理团队；**★★★★★**。

### 3. mvanhorn/last30days-skill

- **主要用途**：让 Agent 聚合 Reddit、X、YouTube、Hacker News、Polymarket 与 Web 的近 30 天信息，并按互动与市场信号综合成带来源的研究摘要。
- **技术栈**：Python、浏览器/站点搜索、社交平台 API、转录与抓取、Agent Skill、Node 安装入口；MIT。
- **近期增长及口径**：约 **+1,059 Star/24h、+2,423 Star/7d**；当前 70,265 Star、6,257 Fork，新上榜第三。
- **贡献与讨论**：近七日约 88 次提交、11 个新议题；反馈集中在安装安全扫描、来源规划器越权添加来源、Doctor 误报以及 Firefox/X Cookie 读取失败。
- **爆发原因（推断）**：通用搜索对近期社区信号覆盖不足，用户希望 Agent 能基于互动量、真实讨论和时间窗口做“最近发生了什么”的快速研究。
- **亮点**：跨平台、时间范围明确，并把来源质量与互动信号带入综合；适合热点追踪和产品调研。
- **潜在风险**：依赖站点政策、登录 Cookie、API 配额与反爬机制；社交信号易被操纵，隐私、授权和自动化访问条款需逐平台核验。
- **适合人群与关注程度**：市场研究、内容策略、开发者关系、产品调研与 OSINT 工具团队；**★★★★☆**。

### 4. Tencent/LoopForge

- **主要用途**：自托管编码 Agent 交付工作台，以标准化 SOP 串联规划、实现、测试、独立评审、人类审批和 PR/MR。
- **技术栈**：Go、Docker/Compose 沙箱、MySQL、Web 控制台、Node.js CLI、GitHub/GitLab 与多种 Agent CLI；根许可证为 MIT，第三方组件沿用原许可。
- **近期增长及口径**：Go 日榜约 **+821 Star/24h**；11 月 13 日以来快照净增约 +3,245。当前 3,911 Star、561 Fork，Fork +82，由第七升至第四。
- **贡献与讨论**：近七日提交 **≥100**、69 个新议题；问题涉及非 CodeBuddy 运行时评测、运行时/模型选择、Secret 管理、私有漏洞报告和 CI 静默跳过扫描。
- **爆发原因（推断）**：编码 Agent 从个人聊天工具转向团队交付系统，企业开始需要固定阶段、脚本门禁、人类审批、凭据控制和可恢复运行。
- **亮点**：把 SOP、沙箱、代码托管与审批链路放在同一控制面，适合验证“Agent 产出如何进入生产流程”。
- **潜在风险**：高活跃也伴随大量兼容与凭据问题；执行器可运行代码并接触仓库、PAT 和 Secret，必须隔离网络、最小权限并启用独立审计。
- **适合人群与关注程度**：研发平台、DevSecOps、代码 Agent 编排、企业交付治理团队；**★★★★★**。

### 5. obra/superpowers

- **主要用途**：用可组合 Skills 为编码 Agent 建立从头脑风暴、计划、实现、测试到评审的软件开发方法论。
- **技术栈**：Shell、Markdown/Agent Skills、插件命令、测试脚本与多客户端适配；MIT。
- **近期增长及口径**：约 **+822 Star/24h**；7 天直接值缺失，11 月 17 日以来快照净增约 +2,263。当前 321,489 Star、28,577 Fork，新上榜第五。
- **贡献与讨论**：近七日默认分支 **0 次提交**、17 个新议题；讨论涉及子 Agent 修复循环、提示缓存、OpenCode 隐藏运行和长计划压缩。
- **爆发原因（推断）**：技能化开发流程适配多种编码 Agent，传播门槛低；成熟方法论在 Agent 用户增长时容易反复进入热榜。
- **亮点**：把开发纪律显式化为可复用步骤，强调计划、测试、审查和任务边界，而不是只追求代码生成速度。
- **潜在风险**：涨星与默认分支零提交明显背离，短期热度可能主要由传播驱动；不同 Agent 的提示注入与上下文机制可能导致行为漂移。
- **适合人群与关注程度**：个人开发者、团队规范、提示/Skill 设计和编码 Agent 研究者；**★★★☆☆**。

### 6. sveltejs/svelte

- **主要用途**：把声明式组件编译为高效 JavaScript 和精确 DOM 更新，用于构建 Web 应用。
- **技术栈**：JavaScript/TypeScript、编译器、响应式 Runes、DOM/SSR/Hydration、Vite 生态；MIT。
- **近期增长及口径**：约 **+692 Star/24h**；11 月 13 日以来快照净增约 +938。当前 89,692 Star、6,217 Fork，新上榜第六。
- **贡献与讨论**：近七日约 14 次提交、15 个新议题；问题聚焦异步 Hydration、自定义 Renderer、HMR、内存泄漏和 each block 回归。
- **爆发原因（推断）**：成熟前端框架在新异步能力、自定义渲染方向和生态发布节点重新获得关注，而非单纯由累计 Star 带动。
- **亮点**：编译期优化和简洁组件模型成熟，问题讨论质量高，适合观察下一代异步渲染与非 DOM Renderer 设计。

- **适合人群与关注程度**：前端框架、编译器、SSR、设计系统与性能工程团队；**★★★★☆**。

- **主要用途**：为 Docker、Compose 和镜像管理提供现代化、自托管的 Web 控制台。

### 8. NVIDIA/SkillEvaluator

- **主要用途**：用分层流水线验证 Agent Skill 的格式、质量、安全、语义重叠、Harness 兼容性及对真实任务结果的增益。
- **技术栈**：Python、CLI/CI、静态扫描、Gitleaks、可选 Semgrep、Embedding/LLM、Docker/Harbor 沙箱；Apache-2.0。
- **近期增长及口径**：约 **+312 Star/24h**；11 月 13 日以来快照净增约 +2,906。当前 3,880 Star、530 Fork，Fork +56，由第五降至第八。
- **贡献与讨论**：近七日提交 **≥100**、28 个新议题；问题涉及 YAML 无界加载、Tier 1 `INCOMPLETE`、运行预算、Provider 与 OpenCode EPIPE。
- **爆发原因（推断）**：Skills 数量暴增后，团队需要证明它们“安全、无重复、兼容，而且真的改善任务表现”，评估开始成为独立基础设施。
- **亮点**：从无模型的确定性检查升级到嵌入去重和沙箱对照实验，可直接接入 CI 门禁。
- **潜在风险**：安全规则仍会误报/漏报；外部扫描器、模型或沙箱配置不完整会产生 `INCOMPLETE`，小样本也不足以证明真实收益。
- **适合人群与关注程度**：Agent Skill 平台、评测、安全、CI 和企业技能目录团队；**★★★★★**。

- **技术栈**：Go CLI、规则引擎、仓库级上下文、OpenAI/Anthropic 兼容接口、GitHub/GitLab CI；Apache-2.0。

- **贡献与讨论**：近七日约 35 次提交、22 个新议题；问题包括无限重试、批量参数静默忽略、审查全失败仍返回成功，以及 GitLab 失败时错误发布通过评论。
- **爆发原因（推断）**：企业希望把生成式审查接入现有 CI，同时保留确定性规则、失败语义和可审计评论，混合架构比纯聊天式 Review 更易落地。
- **亮点**：覆盖 NPE、线程安全、XSS、SQL 注入等规则，并提供仓库上下文、会话比较和多 Provider 支持。
- **潜在风险**：当前失败语义和重试边界仍可能制造“假通过”；自动评论可能暴露代码与提示，必须限制权限、配置脱敏并保留人工门禁。
- **适合人群与关注程度**：企业代码审查、DevSecOps、CI 平台、Go 工具链与 LLM 治理团队；**★★★★★**。

## 当天技术趋势

1. **Agent 生态开始补齐“质量基础设施”**：`SkillEvaluator` 负责 Skill 评估，`ECC` 负责 Harness/记忆/安全优化，`Open Code Review` 负责代码质量门禁。关注点从“会不会调用工具”转向“是否安全、有效、可复现”。
2. **编码 Agent 进入交付控制面阶段**：`LoopForge` 的 SOP、沙箱、审批与代码托管集成说明企业需求已从个人助手走向可恢复、可审计的团队流水线。
3. **专业工作流被 Skill 化**：科研写作、近期情报、设计到代码分别由 `PaperOrchestra`、`last30days-skill`、`stitch-skills` 承载，但平台条款、数据授权和输出真实性成为主要风险。
4. **传统工程项目仍能因关键方向重新爆发**：`Svelte` 的异步渲染、自定义 Renderer 与 `Arcane` 的容器/GitOps 管理说明榜单并非只剩 Agent 项目；成熟工程栈仍有独立增长动能。
5. **Star 与工程活动必须分开看**：`Superpowers` 24 小时 +822，但近七日零提交；`Arcane` 仅 +547，却有 ≥100 次提交。短期传播强度不等于工程成熟度。

## 最值得深入研究的 3 个项目

1. **[NVIDIA SkillEvaluator](https://github.com/NVIDIA/SkillEvaluator)**：它直接解决 Skill 生态最欠缺的可验证性问题，把静态安全、语义重叠、兼容性和真实 Agent 对照实验串成 CI。适合研究“如何证明一个 Skill 有价值”。
2. **[Tencent/LoopForge](https://github.com/Tencent/LoopForge)**：它把编码 Agent 放入脚本门禁、沙箱、人类审批和 PR/MR 流程，是研究 Agent 从个人生产力工具走向企业交付系统的具体样本。
3. **[affaan-m/ECC](https://github.com/affaan-m/ECC)**：它尝试为多种编码 Agent 建立可移植的 Harness、记忆、安全与技能层，且工程活动极强。适合研究多客户端治理，但应优先审计安装器和权限边界。
