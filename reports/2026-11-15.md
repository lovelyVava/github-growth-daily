## 项目分析

### 1. GoogleChrome/modern-web-guidance-src

- **主要用途**：把现代 Web API、性能、可访问性与兼容性实践以可检索 Skill 注入编码 Agent，并扫描遗留模式。
- **技术栈**：TypeScript、Node.js/npm CLI、静态分析器、评测 Harness、文档与可视化 Dashboard；Apache-2.0。
- **近期增长及口径**：约 **+1,925 Star/24h**，相对日增约 **60.9%**；完整七日值缺失，11 月 11 日以来可见净增约 +3,426。当前 5,085 Star、279 Fork，Fork +55，由第二升至第一。
- **贡献与讨论**：近 7 天提交 **≥100**、54 个新议题。近期加入 JavaScript discipline、SCSS/Less、Lit 与 Glimmer 扫描，并把 legacy-scan 提速约 4.5 倍。
- **爆发原因（推断）**：编码模型容易从训练数据复现旧式 Web 模式；由浏览器生态维护、可直接供 Agent 检索且带扫描与 Eval 的规则层击中了真实痛点。
- **亮点**：专家知识、Token 友好检索、遗留扫描和公开评测形成闭环，不只是提示词集合。
- **潜在风险**：大型仓库文件上限、解析失败与跳过诊断仍需验证；浏览器能力快速变化，规则也必须持续更新，不能当作永久正确的静态规范。
- **适合人群与关注程度**：前端平台、编码 Agent、Web 性能、可访问性与代码评审团队；**★★★★★**。

### 2. we-promise/sure

- **主要用途**：自托管个人财务与资产管理，统一账户、交易、预算、净值和投资持仓。
- **技术栈**：Ruby on Rails、Hotwire/Stimulus、PostgreSQL、Sidekiq、Docker；AGPL-3.0。
- **近期增长及口径**：约 **+925 Star/24h**，相对日增约 **6.6%**；完整七日值缺失，11 月 10 日以来可见净增约 +3,069。当前 14,885 Star、1,132 Fork，Fork +66，由第三升至第二。

- **爆发原因（推断）**：用户对可自托管、可迁移的个人财务数据需求增强；完整仪表盘与多源导入兼具演示效果和实际用途。
- **亮点**：现金流、预算、投资、净值与导入链路完整，增长、提交和真实工单同步活跃。
- **潜在风险**：金融数据极敏感；交易去重、汇率、税费、精度和成本基础错误会影响决策。升级前应备份并在副本验证，外部同步凭据必须最小化。
- **适合人群与关注程度**：自托管用户、个人财务工程、FinOps 与数据导入团队；**★★★★★**。

### 4. google/elephant-goldfish-model

- **主要用途**：为编码 Agent 提供“带上下文的设计者 + 无前序对话的新鲜审阅者”工作流，产出设计文档、复核盲点并检查文档与代码漂移。
- **技术栈**：Agent Skills/插件、Markdown/YAML、Python 辅助工具、Astro 文档站，支持 Codex、Claude Code、Antigravity 等宿主；Apache-2.0。
- **近期增长及口径**：周榜约 **+5,560 Star/7d**，相邻快照约 +171/24h。当前 18,731 Star、1,399 Fork，新上榜第四。
- **贡献与讨论**：近 7 天约 41 次提交、31 个新议题；近期加入 Windsurf/Devin Desktop 适配并修正文档站。讨论涉及代码围栏匹配、适配器兼容性与审阅隔离边界。
- **爆发原因（推断）**：它把“先带着上下文设计，再让失忆审阅者质疑假设”包装成清晰、可迁移的工程流程，正好回应 Agent 长上下文带来的确认偏差。
- **亮点**：Brainstorm、Draft、Resolve、Review、Drift Report 分工明确；要求新子 Agent 上下文，能主动暴露未说明假设和设计漂移。
- **潜在风险**：README 明确说明审阅依赖宿主能创建新子 Agent，能力不足时会停止；多 Agent 评审增加 Token、延迟与供应链面，且不能替代测试或人工架构决策。项目也声明不是 Google 官方支持产品。
- **适合人群与关注程度**：架构设计、规范驱动开发、Agent 工作流、技术文档治理团队；**★★★★★**。

### 5. alibaba/open-code-review

- **主要用途**：混合确定性流水线与 LLM Agent 的代码评审 CLI，提供精确行级评论、全文件扫描与多语言规则。
- **技术栈**：Go CLI、Git、npm 分发、模板化规则、并发子 Agent、OpenAI/Anthropic 兼容模型接口；Apache-2.0。
- **近期增长及口径**：约 **+215 Star/24h**；完整七日值缺失，11 月 11 日以来可见净增约 +1,010。当前 50,847 Star、3,786 Fork，重新上榜第五。
- **贡献与讨论**：近 7 天约 27 次提交、14 个新议题；近期增加 Markdown 摘要、workspace `--resume` 和比较侧代码访问。
- **爆发原因（推断）**：项目把文件选择、规则匹配、评论定位等必须稳定的步骤交给确定性工程，把动态上下文检索交给 Agent；这比单纯提示词评审更接近企业可控流程。
- **亮点**：公开基准覆盖 50 个仓库、200 个真实 PR、10 种语言，并强调高精度、较低 Token 成本与大变更集覆盖。
- **潜在风险**：项目承认以精度换取一定召回率，不能把“少误报”误解为“无漏报”；模型端点、源码、Diff 与 API Key 的隔离、数据保留和成本上限仍需企业自行治理。
- **适合人群与关注程度**：企业代码评审、研发效能、AppSec、GitHub/GitLab 流水线团队；**★★★★★**。

## 当天技术趋势

1. **Agent 知识层从“提示词”升级为规则、扫描与 Eval。** `Modern Web Guidance` 用专业规则、静态扫描和公开评测把领域知识变成可验证工程资产，而不是只堆叠 Markdown。
2. **安全与代码评审的竞争点转向确定性控制面。** `Codex Security` 强调扫描—验证—修复—复测闭环，`Open Code Review` 则把文件选择、规则匹配与评论定位交给确定性流水线；共同目标是降低不可控的语言模型漂移。
3. **“新鲜上下文”成为 Agent 评审的新设计原语。** `Elephant–Goldfish Model` 刻意让审阅者忘记前序对话，以暴露确认偏差和未说明假设；这比无限扩展上下文更重视独立证据与反方检查。
4. **电脑操作 Agent 正形成浏览器、桌面、VM 三层栈。** `agent-browser`、`agent-desktop`、`OpenMausBot` 分别覆盖 Web、OS 与隔离执行环境；下一阶段差异会集中在权限边界、凭据载体、会话恢复和审计。
5. **Star 与工程活动的分化仍需警惕。** Sherlock 与多个 Skill 仓库周增很高，但主榜更看重提交、工单质量、许可证和真实部署风险；增长速度不是成熟度代理变量。

## 最值得深入研究的 3 个项目

### 1. GoogleChrome/modern-web-guidance-src

约 +1,925 Star/24h、相对日增 60.9%，近七日提交触顶。它把前端专家知识、静态扫描与 Eval 放在同一条链路，特别适合研究如何为编码 Agent 构建可验证、可更新的领域知识层。建议重点测试大型仓库文件上限、解析失败诊断、框架覆盖、浏览器兼容性和规则误报率。

### 2. openai/codex-security

约 +751 Star/24h，近七日提交触顶。它覆盖从代码扫描到验证、补丁、复测、SARIF 和 CI 的完整安全交付路径，对企业代码评审与 GitHub/GitLab 流水线具有直接参考价值。建议重点评估权限与凭据隔离、成本上限、发现去重、固定版本策略、Windows 兼容与人工复核边界。
