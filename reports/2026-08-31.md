## 统计口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 日榜的 `stars today`，这是滚动窗口指标，不等于自然日增量。
2. **7 天新增 Star**：采用周榜的 `stars this week`。本期前十仅 `archify`、`scientific-agent-skills`、`OpenMAIC`、`freellmapi` 有公开周榜值；其余标记“缺失”，不从累计 Star 反推。
3. **Fork 变化**：只对上一期已有快照且本期继续上榜的项目计算相邻快照差；新上榜项目的 24 小时 Fork 变化不估算。
4. **工程活跃度**：统计 2026-08-24 00:00 UTC 起约 7 天的最近提交，单仓最多读取 100 条；本期没有仓库触及 100 条上限。
5. **贡献者活跃度**：GitHub 提交搜索结果未返回稳定作者身份，因此独立贡献者数统一标记为缺失；以提交数作为替代工程信号，但不能等同于贡献者人数。
6. **讨论热度**：统计同窗口的 GitHub Issue 搜索结果；PR 与 Discussions 的独立增量未能可靠取得，均标记缺失，避免把 Issue 数冒充完整社区活跃度。
7. **爆发原因**：依据 README、近期版本、活动变化和榜单表现作分析推断，不代表维护者官方结论。

## 项目分析

### 1. tt-a1i/archify

- **主要用途**：让 Agent 把代码库或系统描述转成可交互、可验证的架构图、工作流图、时序图、数据流图和生命周期图。
- **技术栈**：JavaScript、Node.js CLI、typed JSON IR、自包含 HTML/SVG、Agent Skill；MIT License。
- **近期增长**：日榜约 **+3,730 Star**，周榜约 **+14,875 Star**；相对日增约 **12.4%**。当前 33,927 Star、2,162 Fork；较上一期 Fork 约 **+262**。
- **贡献与讨论**：近 7 天约 51 次提交、38 个新 Issue；独立贡献者、PR 与 Discussions 增量缺失。v2.16.0 于 8 月 30 日发布，增长与版本迭代同步。
- **爆发原因**：typed IR、确定性校验、源码证据和 Before/Delta/After 对比持续击中 Agent 图表“好看但不可审查”的痛点。
- **亮点**：事实层与展示层分离；生成物可校验、可修复、可导出；新增的多语言、更新清单和架构差异能力增强了工程可用性。
- **潜在风险**：模型化结果不等于真实运行拓扑；动态调用与配置依赖可能漏检；验证收敛成本在复杂图上仍可能较高；内部架构分享前必须脱敏。
- **适合人群**：架构师、研发效能和代码审查团队、复杂代码库学习者。
- **值得关注程度**：**★★★★★**。连续四天第一，Star、Fork、提交和讨论同时增长。

- **适合人群**：大型代码库维护、编码 Agent、代码审查、重构、Graph RAG 和静态分析团队。
- **值得关注程度**：**★★★★★**。工程活跃且架构借鉴价值高，但许可风险必须放在技术评估之前。

## 今日技术趋势

1. **Agent 从通用助手转向专用工作台**：`OpenMAIC` 把课程生成、材料、修改、持久化与多媒体组合成工作台；`open-seo` 则把 SEO 数据和标准工作流暴露给 Agent。
2. **Skills 正在承担“可更新知识和流程”的角色**：`scientific-agent-skills` 与 `last30days-skill` 分别解决领域数据库和近期社会信号，说明模型外能力包比单纯提示词库更有生命力。
3. **代码上下文开始图结构化、证据化**：`GitNexus` 预计算调用链与影响半径，`archify` 将架构交付物类型化和校验化，两者共同指向可审查 Agent。
4. **成熟基础工具仍能被 Agent 时代重新激活**：`crawl4ai` 是网页获取层，`ghidra` 是二进制分析层；它们的价值在于可编程、可自动化，而不是“带聊天框”。
5. **虚拟设备成为 Agent E2E 的新执行面**：`vphone-cli` 的截图、触控和控制 socket 展示了移动端 Agent 测试潜力，但安全与平台限制远高于普通应用自动化。
6. **热度质量需要拆开看**：`GitNexus` 日增不高但 7 天有约 50 次提交；`open-seo` 日增较高但只检索到 1 次提交。Star 传播与工程成熟度不是同一个指标。
