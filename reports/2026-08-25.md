## 数据口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 日榜观察时刻显示的 `stars today`，属于滚动窗口近似值。页面展示顺序不完全等于该数值大小，本报告按日增 Star 重新排序。
2. **7 天新增 Star**：采用周榜显示的 `stars this week`。未进入周榜可见范围时标记“缺失”，不使用累计 Star 倒推。本期可可靠取得 `OpenLogi`、`omarchy` 的周榜值；`claude-plugins-community` 日榜和周榜由不同时间快照抓取，出现 24h 值高于周榜值，已标记为“窗口差异”。
3. **Fork**：累计 Fork 来自本期仓库 API 快照；连续上榜项目以本期减上一期快照得到约 24h Fork 增量，统一标为“快照估算”；新上榜项目的 Fork 增量缺失。
4. **贡献活跃度**：近 7 天提交数来自最近 100 条提交按 `created_at >= 2026-08-18` 过滤；达到 100 时记为“≥100（截断）”。新建 Issue/PR 来自同日起的 GitHub Search 计数，包含已关闭项、机器人和自动同步，不能等同于独立贡献者人数。统一的独立贡献者数本期无法可靠取得，明确标记为缺失。
5. **讨论热度**：使用近 7 天新建 Issue/PR 和 Discussions 是否启用作为代理；未取得统一口径的 Discussion 新增帖/评论数。
6. **相对日增**：按 `24h 新增 Star ÷（当前累计 Star - 24h 新增 Star）` 估算，用于识别小体量项目爆发强度。
7. **许可证**：采用仓库 API 的 SPDX 识别结果；缺失不代表可任意商用，需继续核对仓库文件、数据来源和第三方资产条款。

## 最值得深入研究的 3 个项目

### 1. [anthropics/claude-plugins-community](https://github.com/anthropics/claude-plugins-community)

重点研究只读镜像、内部审核管线、自动安全扫描、夜间同步和插件命名空间。它对建设企业内部插件/Skill 注册表很有参考价值：公共市场只作为候选源，内部还应增加来源固定、权限声明、版本签名、人工审批、撤回和审计记录。

### 2. [VoltAgent/awesome-agent-skills](https://github.com/VoltAgent/awesome-agent-skills)

它覆盖大量官方与社区 Skills，适合做生态地图和规则分类样本。建议抽取“触发条件—所需证据—工具权限—输出契约—验证步骤”字段，建立内部白名单与静态扫描，而不是批量安装；还要为每个条目单独保留来源和许可证。

### 3. [openai/codex](https://github.com/openai/codex)

继续研究沙箱、批准机制、工具调用协议、补丁生成、仓库指令加载与非交互执行。把它与插件市场和 Skills 目录放在同一架构图中，可以更清楚地划分执行器、扩展包、团队规则与模型服务各自的权限边界。
