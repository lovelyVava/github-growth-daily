## 统计口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 日榜的 `stars today`，属于滚动窗口，不等于自然日或相邻累计快照差；页面顺序不严格按该值排序，本报告按数值重新排序。
2. **7 天新增 Star**：采用周榜的 `stars this week`。只有周榜直接展示的项目才记录；未进入周榜标为“缺失”，不从累计 Star 反推。
3. **开源范围**：主榜要求仓库存在可识别的标准开源许可证。公开源码但采用自定义限制性条款、没有明确授权，或主体为新闻/文章/资料汇编的仓库不计入软件主榜。
4. **当前 Star/Fork**：采用 2026-09-22 07:58–08:27 的公开页面/API 快照，不同接口抓取时间存在分钟级差异。
5. **比较基线**：仓库中没有 2026-09-21 报告，本期与最新可用的 2026-09-20 报告比较。因此连续项目的 Fork 差是约 48 小时的快照差，不是 24 小时新增；新上榜项目不估算 Fork 增量。
6. **工程活跃度**：统计 2026-09-15 00:00 UTC 起约 7 天的默认分支提交，单仓最多读取 100 条；触及上限写作“≥100”。作者字段未可靠返回，统一标为“缺失”。
7. **讨论热度**：统计同一窗口新建 Issue，排除 PR。机器人健康检查、模板工单、维护者拆分和垃圾 Issue 会放大数字，因此同时审阅内容性质。
8. `agent-native` 的默认分支提交搜索为 0，但仓库在 9 月 21 日发布了一批新版本；这里分别记录，不把 Release 错算为默认分支提交。
9. **爆发原因**：根据 README、近期提交、Release、Issue 与榜单表现作分析推断，不代表维护者官方结论。

### 1. Open-Dev-Society/OpenStock

- **主要用途**：开源股票研究和市场信息工作台，整合行情、图表、新闻、关注列表与用户账户。
- **技术栈**：Next.js 15、React 19、TypeScript、Tailwind CSS 4、shadcn/Radix、Better Auth、MongoDB、Inngest、TradingView、Finnhub；AGPL-3.0。
- **近期增长及口径**：日榜约 **+843 Star**；周榜直接值缺失；相对日增约 **5.0%**。当前 17,697 Star、2,189 Fork；较 9 月 20 日 Fork 约 **+105/约48h**，排名由第四升至第一。
- **贡献与讨论**：近 7 天约 5 次默认分支提交、0 个新 Issue；作者身份缺失。近期主要补充唯一标识、周报 Cron 与说明文档。
- **爆发原因**：完整可演示的金融仪表盘、现代 Next.js 技术栈和自托管定位仍然容易传播，且每日增量从 9 月 20 日的约 477 上升到 843。
- **亮点**：前后端一体，认证、异步任务、邮件、行情与图表接入路径清晰，适合作为金融 Web 应用样板。
- **潜在风险**：近期工程提交弱于传播；行情源可能延迟、限流或改变条款；AGPL 对网络部署有源码义务。README 顶部存在与产品无关的代币地址推广，形成治理与信誉风险。
- **适合人群与关注程度**：金融数据可视化、Next.js 全栈、自托管研究仪表盘开发者；**★★★☆☆**，适合原型和架构参考，不应直接用于交易决策。

### 2. trycua/cua

- **主要用途**：为 AI Agent 提供跨 macOS、Linux、Windows 的电脑操作能力，统一桌面、浏览器、沙箱、远程环境、模型训练与评测入口。
- **技术栈**：Python、TypeScript、Rust、CLI/MCP/SDK、虚拟化与远程桌面、CUA-S1 研究组件；MIT。
- **近期增长及口径**：日榜约 **+609 Star**；周榜直接值缺失；相对日增约 **2.4%**。当前 25,683 Star、1,767 Fork；较 9 月 20 日 Fork 约 **+89/约48h**，排名保持第二。
- **贡献与讨论**：近 7 天约 24 次提交、60 个新 Issue；作者身份缺失。近期推进 CUA-S1 文档、感知 RFC、能力拒绝路径、模型路由和动作结果词汇。
- **爆发原因**：真实桌面、浏览器、云沙箱、Fleet 和 Benchmark 被组合为统一电脑操作控制面，承接了从 Demo 向可复现部署转移的需求。
- **亮点**：跨系统 Driver、CLI/MCP/SDK 多入口、模型研究和运行环境相互衔接，适合系统化评估电脑操作 Agent。
- **潜在风险**：Issue 显示模型保存/加载不一致和数据集一次性加载导致约 26GB 内存占用；真实登录态、桌面权限、远程服务、网络和实例回收都是高权限边界。
- **适合人群与关注程度**：电脑操作 Agent、桌面自动化、沙箱与 Benchmark 研究者；**★★★★★**，仅建议在隔离 VM 和测试账户中验证。

### 3. BuilderIO/agent-native

- **主要用途**：用统一动作和状态模型构建“界面与 Agent 共用能力”的应用，同一动作可暴露给 UI、HTTP、MCP、A2A 和 CLI。
- **技术栈**：TypeScript、Nitro、PostgreSQL/PGlite、共享 Actions、Skills/Memory、认证与权限、自动化和多 Agent 团队；`package.json` 声明 ISC。
- **近期增长及口径**：日榜约 **+607 Star**；周榜直接值缺失；相对日增约 **11.5%**，为主榜最高。当前 5,877 Star、534 Fork；相对 9 月 20 日为新上榜。
- **贡献与讨论**：默认分支提交搜索为 0，但 9 月 21 日发布了 `core 0.183.0`、`toolkit 0.20.5`、`dispatch 0.38.3` 等一批版本；新 Issue 搜索达到 **≥100** 条，其中大量是自动生产健康与站点可用性检查，不能视为同量级人工讨论。
- **爆发原因**：“一份业务动作契约同时服务人类 UI 与 Agent”直击 Agent 应用重复实现、权限漂移和多协议适配问题，且批量 Release 放大了近期曝光。
- **亮点**：数据、动作、权限与多种调用协议同源；对需要 Web UI、Agent、API 和 MCP 一致行为的产品很有架构参考价值。
- **潜在风险**：统一动作层也会集中权限和爆炸半径；自动健康检查反映部署面尚不稳定。仓库根目录没有独立 LICENSE 文件，需核对 monorepo 子包与发布制品是否都与 ISC 声明一致。
- **适合人群与关注程度**：Agent 产品框架、全栈平台、需要统一 UI/API/MCP 权限契约的团队；**★★★★★**，建议先审计动作授权和失败隔离。

- **技术栈**：Go、TypeScript/React、Terraform、Kubernetes/Docker/VM、WireGuard、OIDC/OAuth；核心 AGPL-3.0，另含商业 Enterprise 许可证。

## 当天技术趋势

1. **Agent 应用开始围绕统一动作契约组织**：`agent-native` 把 UI、Agent、HTTP、MCP、A2A 和 CLI 放在同一动作/权限模型上，重点从“加一个聊天框”转向一致的业务能力和授权边界。
2. **电脑操作 Agent 仍是高权限增长核心**：`cua` 保持第二，并有 24 次提交、60 个 Issue。能力从单机自动化扩展到模型、数据、Fleet 和远程环境后，资源、登录态和销毁策略成为系统问题。
3. **垂直行业 Agent 更重视角色、证据和人工签核**：`financial-services` 的价值不在某个提示词，而在角色分工、连接器、结构化产物和人工终审的组合，这种模式可迁移到法务、客服和企业文档流程。
4. **长期记忆正在从黑盒数据库转向人可读、Git 可审计的知识层**：`ai-memory` 用 Markdown Wiki 作为权威来源，回应跨工具迁移与团队交接；与此同时，Hooks 和 Embedding 端点带来新的隐私边界。
5. **本地与离线基础设施不等于低风险**：`project-nomad`、`AutoClip`、`Codex-X` 都强调本地能力，但 root 安装、容器、模型下载、视频版权、密钥存储和自动更新仍需要供应链审计。
6. **基础协议库提供与流量无关的长期信号**：`quiche` 日增不高，却有明确周增和 24 次近期提交；与爆发型 Agent 仓库相比，它代表更稳定的基础设施研究价值。
7. **严格开源筛选仍然必要**：`mvt` 的限制性自定义许可证和 `ruanyf/weekly` 的内容属性都说明，Trending 上的高增长不能直接等同“可复用开源软件”。

## 最值得深入研究的 3 个项目

### 1. akitaonrails/ai-memory

**理由**：日榜约 +217 Star，近 7 天提交达到 100 条读取上限并有 27 个新 Issue，热度背后有真实的高速工程活动。它把记忆落到 Git 支持的 Markdown、可重建索引、审计与交接语义，对多 Agent 团队比单一宿主私有数据库更有研究价值。建议用脱敏仓库验证：记忆召回准确率、跨 Agent 交接、冲突合并、删除是否彻底、提示注入传播，以及外部 Embedding 地址是否会造成未预期数据外发。

### 2. BuilderIO/agent-native

**理由**：约 +607 Star/24h、相对日增约 11.5%，而核心价值是把同一业务动作同时提供给人类界面和多种 Agent 协议。对企业 OCR 或代码审查扩展，这种设计可以避免 UI、API、MCP 各自复制权限和校验逻辑。建议用一个小型审批流验证 Actions 的幂等性、授权继承、重放防护、失败补偿和审计日志；同时核对各子包许可证，过滤自动健康检查造成的讨论热度噪声。

### 3. anthropics/financial-services

**理由**：约 +425 Star/24h，虽然近 7 天只有 3 次提交，但它提供了“行业角色＋Skills＋连接器＋结构化产物＋人工签核”的完整样板。其金融领域的监管强度，反而使数据边界和审批节点更清晰，适合借鉴到企业文档/OCR、研究和代码审查工作流。建议重点审阅凭据传递、连接器失败时的降级、文件路径验证、每一步证据引用和人工终审是否真的不可绕过。
