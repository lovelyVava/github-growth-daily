6. **讨论热度**：Discussions 只记录是否启用；未取得同口径的 7 天讨论新增数。Issue/PR 数可能包含机器人、模板化或迅速关闭的内容，不能等同于独立贡献者人数。
7. **对比基线**：仓库中最近一期为 2026-08-17；8 月 18–20 日缺少报告和连续快照，因此只做跨期榜单对比，不计算严格的逐日排名变化。

- **值得关注程度**：★★★★★。规模不大但方向关键，尤其适合拆解其 Manifest、权限和审查插件设计。

### 10. [modular](https://github.com/modular/modular)｜新上榜

## 当天技术趋势

1. **Agent Skills 正在变成通用分发单元**：`skills`、`superpowers`、`cursor/plugins` 同时上榜，说明开发者关注点已从单个 Prompt 转向可安装、可组合、带 Manifest 与生命周期的能力包。

## 最值得深入研究的 3 个项目

### 1. [OpenViking](https://github.com/volcengine/OpenViking)

最适合用于企业代码审查与团队 Agent 记忆。建议重点拆解 `viking://` 资源模型、L0/L1/L2 分层加载、检索轨迹和会话记忆提炼，评估如何映射到代码仓库、规则、审查证据和历史结论；同时先解决 AGPL 合规与敏感记忆隔离。

### 2. [cursor/plugins](https://github.com/cursor/plugins)

它提供官方插件规范和多个与代码审查直接相关的样例。建议重点分析 Manifest、权限边界、`thermos` 深度审查、`continual-learning` 团队记忆以及 `pr-review-canvas` 证据呈现，再将可用部分转译为 Open Code Review 的扩展文件，而不是照搬 Cursor 专有目录。

### 3. [munder-difflin](https://github.com/chaitanyagiri/munder-difflin)

它对多 Agent 循环、后台任务、共享记忆和桌面可视化的处理，与“提交前扫描—全量上线审查—结果归档”这类长流程高度相关。建议优先验证任务锁、重复执行防护、状态恢复、人工验收点和权限隔离，再考虑引入并行 Agent。
