8. **开源范围**：主榜要求仓库根目录存在可验证的标准开源许可。模型权重、数据、插件、托管服务与付费功能可能有独立条款，仍需逐项核验。
9. **爆发原因**：依据 README、许可证、近期提交、Issue 与榜单表现作分析推断，不代表维护者官方结论。

## 项目分析

### 1. MadsLorentzen/ai-job-search

- **主要用途**：把职位发现、匹配评分、定制简历与求职信、申请跟踪和面试准备组织为可本地运行的 Agent 求职工作流。
- **技术栈**：Python 3.10+、Claude Code/Agent Skills、Bun、LaTeX 与 PDF 可解析性检查；MIT。
- **近期增长及口径**：约 **+3,860 Star/24h、+5,742 Star/7d**，相对日增约 **7.2%**。当前 57,152 Star、18,168 Fork，Fork 较上期约 +816；连续第一。
- **贡献与讨论**：近 7 天约 84 次提交、作者身份缺失、12 个新 Issue；最新修复网页抓取与 robots 检查的 UTF-8 输出。
- **爆发原因**：从“AI 写简历”扩展到职位源、匹配、材料、跟踪与面试的端到端流程，且快速处理真实网站和编码边角问题，推动传播转化为 Fork 与工程贡献。
- **亮点**：drafter-reviewer 双阶段写作、LaTeX/PDF 输出、职位门户 Skill、薪资基准与申请追踪形成闭环。
- **潜在风险**：设置流程可能把姓名、联系方式、履历和薪资预期写入 Git 历史；职位站点条款、模型幻觉和招聘公平性也需评估。必须使用私有工作区并人工核验全部材料。
- **适合人群与关注程度**：希望结构化个人求职流程、研究垂直 Agent 或构建职业服务工具的团队；**★★★★★**。

- **主要用途**：多 Agent 桌面工作区，让 Claude Code、Codex、OpenCode、Pi 等 CLI Agent 并行运行在独立 Git worktree 中，并统一管理终端、差异审查、远程主机和移动端跟进。
- **技术栈**：TypeScript、Electron、React、Vite、Node/Bun、node-pty、Playwright、Git worktree 与原生移动组件；MIT。
- **近期增长及口径**：约 **+1,591 Star/24h**，相对日增约 **1.6%**；7 天直接值缺失。当前 98,230 Star、6,265 Fork，Fork 较上期约 +91；由第五升至第二。
- **贡献与讨论**：近 7 天提交与新 Issue 均 **≥100**、作者身份缺失；最新修复多个主机上同名卡片导致 Pin 操作对象错误的问题。

- **亮点**：并行 worktree、终端分屏、AI diff、移动伴侣、SSH worktree 和脚本化 CLI，形成多 Agent IDE 的完整雏形。
- **潜在风险**：工作区会接触源代码、终端、Agent 凭据和远程主机，必须按高权限开发工具审查；Issue 达上限也意味着快速迭代与回归风险并存。

- **贡献与讨论**：近 7 天提交 **≥100**、作者身份缺失、54 个新 Issue；最新修复 OpenCode 调用 Haiku 5.5 时的 Messages 路由。
- **爆发原因**：多 Agent 宿主切换使失败路径、架构决策和未完成问题的迁移成为刚需；普通 Markdown 与 Git 后端又降低了锁定焦虑。
- **亮点**：记忆源数据保持为可编辑 Markdown，数据库仅作可重建索引；支持 typed handoff、团队共享、个人隔离、多机同步和审计日志。
- **潜在风险**：长期记忆会集中代码上下文、个人偏好和团队知识，需严格设置访问控制、保留期、敏感信息清理与备份；跨 Agent hooks 也是高权限注入点。

- **亮点**：按 JSON、代码与文本路由压缩，原文可回取；覆盖 Codex、Claude Code、OpenCode 等多种 Agent，并公开可复现实验脚本和准确率基准。
- **潜在风险**：压缩可能删除低频但关键的信息，官方基准不能替代目标任务评测；代理与跨 Agent 记忆会接触高敏感提示、文件和凭据，必须审查网络转发、缓存权限和恢复边界。
