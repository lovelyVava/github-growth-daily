## 项目分析

### 1. dream-num/univer

- **主要用途**：在产品中嵌入表格、文档、计算、协作与文件处理能力，并让 Agent 通过统一 API 操作 Office 内容。
- **技术栈**：TypeScript、Canvas 渲染、公式引擎、插件/依赖注入、Facade API、Web/Server/AI SDK、pnpm Monorepo；开源核心 Apache-2.0。
- **近期增长及口径**：约 **+1,828 Star/24h**；完整七日值缺失，11 月 11 日以来可见净增约 +5,055。当前 28,227 Star、2,559 Fork，Fork +140，由第三升至第一。
- **贡献与讨论**：近七日约 46 次提交、17 个新议题；近期工作涉及 `XLOOKUP` 字面量、混合排序与 `focus-visible`。问题集中在负数文本格式、`EDATE/EOMONTH` 和函数兼容。
- **爆发原因（推断）**：Agent 从生成文本转向编辑真实业务文档，需要可嵌入、可计算、可撤销并能接入应用权限的 Office 执行层。
- **亮点**：开源核心包含内容模型、命令、公式、渲染与 Facade API，可用于结构化、可撤销的业务操作。
- **潜在风险**：开源核心与商业插件、Server SDK、AI SDK 存在功能边界；公式兼容、协作冲突、文档保真和第三方依赖需用真实样本验证。
- **适合人群与关注程度**：企业办公平台、低代码、文档 Agent、表格自动化与嵌入式编辑器团队；**★★★★★**。

### 2. GoogleChrome/modern-web-guidance-src

- **主要用途**：把现代 Web API、性能、可访问性和兼容性实践以可检索 Skill 注入编码 Agent，并扫描遗留模式。
- **技术栈**：TypeScript、Node.js/npm CLI、静态分析器、评测 Harness、文档与 Dashboard；Apache-2.0。
- **近期增长及口径**：约 **+1,200 Star/24h、+6,542 Star/7d**，当前 8,132 Star、704 Fork，Fork +59，由第一降至第二但仍是周榜第一。
- **贡献与讨论**：近七日约 57 次提交、36 个新议题；近期更新依赖、发布通道与指南命名。问题包括数组方法误建议、虚拟列表可访问性指南和发布包缺少 CLI 文件。
- **爆发原因（推断）**：模型容易复现训练数据中的旧式 Web 模式；由 Chrome 生态维护、可检索、可扫描且带 Eval 的规则层直接补上知识时效缺口。
- **亮点**：专家知识、Token 友好检索、静态检查和公开评测形成闭环，不只是提示词集合。
- **潜在风险**：仍存在发布包入口、规则冲突和扫描漏检；浏览器能力快速变化，规则不能被当作永久正确的静态规范。
- **适合人群与关注程度**：前端平台、编码 Agent、Web 性能、可访问性与代码评审团队；**★★★★★**。

### 3. Tencent/LoopForge

- **主要用途**：自托管编码 Agent 交付工作台，用聊天或标准化 SOP 串联规划、实现、测试、独立评审、人类审批和 PR/MR。
- **技术栈**：Go 平台、Docker/Compose 沙箱、MySQL、Web 控制台、Node.js 本地 CLI、GitHub/GitLab 与多种 Agent CLI；根 `LICENSE` 为 MIT，第三方组件保留原许可。
- **近期增长及口径**：约 **+1,020 Star/24h**、相对日增约 **69%**；完整七日值缺失，11 月 11 日以来可见净增约 +2,190。总量约 2,500 Star、378 Fork，Fork +72，由第四升至第三。
- **贡献与讨论**：近七日提交 **≥100**、59 个新议题；近期发布 v0.4.0、增强端到端流程和聊天入口。问题集中在 API 文档、模型选择校验和 CLI 安装诊断。
- **爆发原因（推断）**：团队开始要求 Agent 交付具备固定阶段、确定性脚本、人类门禁、可恢复运行和 MR 证据，而不只是一次性聊天产出。
- **亮点**：Agent、脚本、人类门禁和子 SOP 可组合；每步保留日志、产物与状态，并支持重试、回退和接管。
- **潜在风险**：默认 Docker 沙箱通过宿主 Docker socket 启动，不适合不可信多租户；上线前必须收紧注册、网络、凭据、仓库权限和宿主隔离。
- **适合人群与关注程度**：研发效能、Agent 平台、内网交付、GitOps 与需要人工审批的团队；**★★★★★**。

### 4. NVIDIA/SkillEvaluator

- **主要用途**：用三层流水线验证 Agent Skill：静态质量/安全检查、语义去重、以及有无 Skill 的真实 Agent 对照评测。
- **技术栈**：Python 3.12–3.14、CLI/CI、SkillSpector、Gitleaks、可选 Semgrep、Embedding/LLM、Docker/Harbor 沙箱；Apache-2.0。
- **近期增长及口径**：约 **+873 Star/24h**、相对日增约 **41%**；完整七日值缺失，11 月 12 日以来可见净增约 +2,157。当前 2,981 Star、416 Fork，Fork +145，由第九升至第四。
- **贡献与讨论**：近七日提交 **≥100**、25 个新议题；近期发布 v1.0.1、加强 URL 安全和 Tier 3 辅助流程。工单包括自定义请求头、OpenCode `EPIPE`、标点 Token 和负向计算样例。
- **爆发原因（推断）**：Skill 数量快速增加后，团队需要回答“格式正确、安全、无重复，而且是否真的提升任务结果”，评估层开始成为独立基础设施。
- **亮点**：可从无模型的确定性检查升级到嵌入去重和沙箱对照实验；结果能接入 CLI、JSON 与 CI 门禁。
- **潜在风险**：项目仍处早期，外部扫描器、模型或沙箱配置不完整会产生 `INCOMPLETE`；小样本也不足以证明真实收益或安全性。
- **适合人群与关注程度**：Agent Skill 平台、评测、安全、CI 和企业技能目录团队；**★★★★★**。

### 5. alibaba/open-code-review

- **主要用途**：混合确定性流水线与 LLM Agent 的代码评审 CLI，提供精确行级评论、全文件扫描和多语言规则。
- **技术栈**：Go CLI、Git、npm 分发、模板化规则、并发子 Agent、OpenAI/Anthropic 兼容模型接口；Apache-2.0。
- **近期增长及口径**：约 **+951 Star/24h、+3,056 Star/7d**。总量约 53,200 Star、4,400 Fork，Fork 约 +216，排名维持第五。
- **贡献与讨论**：近七日约 31 次提交、18 个新议题；近期新增会话身份字段、遥测初始化并修复取消后的 Git 等待。问题涉及 Windows CI 退出、多文件分组键泄漏和 Provider 文档。
- **爆发原因（推断）**：文件选择、规则匹配与评论定位由确定性工程约束，动态上下文交给 Agent；混合架构比纯提示词评审更适合企业流程。
- **亮点**：公开基准覆盖多仓库、真实 PR 与多语言，并强调高精度、较低 Token 成本和大变更集覆盖。
- **潜在风险**：以精度换取一定召回率，不能把“少误报”误解为“无漏报”；模型端点、源码、Diff 与 API Key 的隔离、保留和成本仍需自行治理。
- **适合人群与关注程度**：企业代码评审、研发效能、AppSec、GitHub/GitLab 流水线团队；**★★★★★**。

### 6. backnotprop/plannotator

- **主要用途**：在多 Agent 工作与人类之间提供本地审阅界面，集中展示问题、计划、原型、文档与代码 Diff，让人工批注回到原 Agent 会话。
- **技术栈**：TypeScript、Bun、浏览器本地界面、MCP、Agent 插件/Hooks、Git/GitLab/GitHub/Jujutsu/Perforce 集成；Apache-2.0。
- **近期增长及口径**：约 **+696 Star/24h、+2,325 Star/7d**，当前 12,766 Star、1,262 Fork，Fork +141，由第二降至第六。
- **贡献与讨论**：近七日提交 **≥100**、64 个新议题；近期为 0.29.0 做 QA 并继续完善 Inbox。工单包括本地视频、规格签署、跨源嵌入与 Cloudflare 会话。
- **爆发原因（推断）**：多 Agent 并行后，瓶颈从“生成更多代码”转向“人如何看到关键决策并异步反馈”；Inbox 提供跨 Agent 的人工控制面。
- **亮点**：默认本地保存计划、Diff 与批注；支持本地代码、GitHub PR、GitLab MR 和多种 Agent，反馈可回到发起会话。
- **潜在风险**：Ask AI、远程 PR/MR、URL 抓取和分享会让选定内容离开本机；企业部署应关闭非必要联网与分享并审查模型方数据边界。
- **适合人群与关注程度**：多 Agent 编排、企业代码评审、产品/架构审批与 GitLab 工作流团队；**★★★★★**。

- **爆发原因（推断）**：安全技能可即插即用，公开漏洞报告的模式化整理又具备很强传播性，正好命中 Agent 安全与 Bug Bounty 两个热点。

### 8. ag-ui-protocol/ag-ui

- **主要用途**：定义 Agent 与用户界面之间的轻量事件协议，使运行状态、工具调用、上下文和人机协作可以跨框架流式传输。
- **技术栈**：TypeScript 核心与协议 Schema、多语言 SDK、事件流、前端客户端、中间件及多种 Agent 框架集成；MIT。
- **近期增长及口径**：约 **+791 Star/24h**；完整七日值缺失，11 月 14 日以来可见净增约 +2,138。当前 19,447 Star、2,005 Fork，Fork +137，排名维持第八。
- **贡献与讨论**：近七日约 71 次提交、9 个新议题；近期发布 Cloudflare Agents 集成并更新变更日志。问题涉及 LangGraph Hooks、事件流 v3 和畸形结果校验。
- **爆发原因（推断）**：Agent 后端和前端框架快速分化，团队需要一个比自定义 WebSocket 消息更稳定、比单一 SDK 更中立的交互层。
- **亮点**：事件模型适合流式状态、工具调用和人工介入，并通过多语言 SDK 与框架适配降低前后端耦合。
- **潜在风险**：协议与各语言 SDK 可能版本漂移；事件流可能携带提示、工具参数或用户数据，必须设计认证、租户隔离、脱敏、重放保护和断线恢复。
- **适合人群与关注程度**：Agent UI、实时协作、协议设计、跨框架平台与前端基础设施团队；**★★★★★**。

1. **Agent 基础设施从“能运行”转向“可验证”。** `SkillEvaluator` 验证 Skill 本身，`Open Code Review` 验证代码变更，`LoopForge` 验证交付阶段与审批证据，质量门禁正在形成分层体系。
