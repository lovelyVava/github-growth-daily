## 统计口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 日榜的 `stars today`，这是滚动窗口，不等于自然日或相邻累计快照差；页面顺序不严格按该值排序，本报告按数值重新排序。
2. **7 天新增 Star**：采用周榜的 `stars this week`。只有公开周榜直接展示的数值才写入；未进入周榜的项目标为“缺失”，不从累计 Star 反推。
3. **当前 Star/Fork**：采用 2026-09-18 08:02–08:16 的 GitHub 页面/API 快照；不同接口抓取时间存在分钟级差异。
4. **Fork 变化**：对连续进入前十的项目比较 9 月 17 日与 9 月 18 日相邻快照；新上榜项目不估算 24 小时 Fork 变化。
5. **工程活跃度**：统计 2026-09-11 00:00 UTC 起约 7 天的默认分支提交，单仓最多读取 100 条；触及上限写作“≥100”。
6. **贡献者活跃度**：按提交记录中的 GitHub 账号或作者邮箱去重估算，可能拆分同一人的多个身份或包含机器人，不等同累计 Contributors。
7. **讨论热度**：统计同一窗口新建 Issue，排除 PR。Issue 可能由机器人、模板、集中投稿或维护者拆分产生，数量不等于有效人工讨论。
8. **安全问题状态**：按观察时点的公开 Issue 与默认分支状态判断；后续可能修复，部署前必须再次核验版本与提交。
9. **许可证识别**：按 GitHub API、README 与根许可证文件交叉判断；模型、插件、数据和下载内容仍可能保留独立条款。
10. **爆发原因**：根据 README、近期提交、Issue 内容与榜单表现作分析推断，不代表维护者官方结论。

## 项目分析

### 1. cloudflare/security-audit-skill

- **主要用途**：把编码 Agent 编排为多阶段安全审计器，覆盖侦察、覆盖账本、漏洞猎取、候选验证、结构化结论和独立复核。
- **技术栈**：Agent Skill/Markdown、JavaScript 零依赖验证器、JSON Schema、隔离子 Agent、机器可读 `findings.json` 与 `coverage-ledger.json`；MIT。
- **近期增长**：日榜约 **+3,607 Star**；周榜直接值缺失；相对日增约 **51.8%**。当前 10,569 Star、564 Fork；较上期 Fork约 **+144**，从第八升至第一。
- **贡献与讨论**：近 7 天仅 1 次提交、1 个作者身份、8 个新 Issue；唯一提交主要澄清指导模式与完整审计模式。
- **爆发原因**：Cloudflare 公开漏洞发现 Harness 方法后，“覆盖可量化、结论可机读、发现者与验证者分离”的审计思路集中传播。
- **亮点**：`confirmed`、`needs_validation`、`rejected` 三态清晰；严重性必须有实际影响；覆盖账本避免把未验证区域默认为安全。
- **潜在风险**：涨星明显快于维护和作者扩张；效果高度依赖模型、预算、目标可构建性与沙箱；单轮审计仍可能漏报，输出不能替代人工 AppSec 复核。
- **适合人群**：获授权代码审计、AppSec、Agent 安全评估和希望建立可机读证据链的研发安全团队。
- **值得关注程度**：**★★★★☆**。方法论价值高，但应先用已知漏洞基准评测，不应因登顶就直接投入生产。

### 2. alibaba/open-code-review

- **主要用途**：对工作区、分支、提交或完整目录进行 AI 代码审查，以确定性管线控制文件覆盖、规则匹配和评论位置，以 Agent 完成语义判断。
- **技术栈**：Go、Git、文件分组、隔离子任务、位置校正、OpenAI/Anthropic 兼容模型、MCP、CLI、Agent Skills 与 CI/CD；Apache-2.0。
- **近期增长**：日榜约 **+3,286 Star**、周榜约 **+11,489 Star**；相对日增约 **10.5%**。当前 34,667 Star、2,466 Fork；较上期 Fork约 **+209**，排名下降 1 位。
- **贡献与讨论**：近 7 天约 52 次提交、31 个作者身份、64 个新 Issue，协作广度为本期最高。最新修复运行中分组的 Token 预算门禁、重叠增量评论去重，并加入过期 Review Thread 的可报告/可选清理模式。
- **爆发原因**：企业规则、全量 Scan、可恢复 Session、GitLab/GitHub 集成和本地模型兼容持续回应“Agent 审查必须可控、可追踪”的需求。
- **亮点**：预算在每轮 LLM 调用前生效；过期线程清理由 GitHub 的 `isOutdated` 和多重 veto 决定，不让模型自主删除；路径和评论位置由确定性逻辑约束。
- **潜在风险**：高 Precision 不代表高 Recall；忽略、路径或 `backgroundFile` 配置错误会形成系统性盲区；自动解决线程和增量去重必须在镜像仓库回归测试。
- **适合人群**：内网 GitLab、提交前扫描、MR 自动评论、本地 `/v1` 模型和需要 `background.md`/规则路由的研发团队。
- **值得关注程度**：**★★★★★**。与现有 OCR 改造最直接相关，新增预算与线程治理值得优先验证。

### 3. Tencent/BrowserSkill

- **主要用途**：让 Codex、Claude Code、Cursor 等 Shell 型 Agent 借用真实、已登录的 Chrome/Edge 标签页，在独立可见窗口中执行浏览器任务并支持人工接管。
- **技术栈**：TypeScript 浏览器扩展、Rust `bsk` CLI/本地守护进程、WebSocket、Chrome DevTools Protocol、Agent Skill 与 DeepSeek Harness 插件；MIT。
- **近期增长**：日榜约 **+1,302 Star**；周榜直接值缺失；相对日增约 **46.5%**。当前 4,100 Star、291 Fork；首次进入近期前十。
- **贡献与讨论**：近 7 天约 77 次提交、5 个作者身份、22 个新 Issue；近期发布 0.3.0，强化标签借用确认、人机协作、远程守护进程和长截图。
- **爆发原因**：复用真实登录态、跨 Agent Harness、独立 Agent 窗口和人机接管解决了无头浏览器难处理登录与验证码的问题。
- **亮点**：借用标签需要显式归还；确认与人工帮助由扩展设置控制；支持 Windows、Linux、macOS 和 Chrome/Edge；对沙箱 Agent 有持久守护进程方案。
- **潜在风险**：公开 Issue [#273](https://github.com/Tencent/BrowserSkill/issues/273) 在观察时仍为 Open：默认本地 WebSocket 只校验扩展来源格式，未锁定官方扩展 ID，其他扩展可能借守护进程控制已登录浏览器。另有 Windows 未签名二进制被 Smart App Control 阻止、`doctor` 无扩展时可能挂起等问题。
- **适合人群**：浏览器 Agent 架构、安全边界、人机接管和跨 Harness 工具研究者；当前不适合含公司 GitLab、邮箱、网银等敏感登录态的日常浏览器。
- **值得关注程度**：**★★★☆☆（研究价值高，部署降权）**。如需试验，应使用独立浏览器配置文件、无敏感账户、最少扩展，并等待鉴权修复后重新审计。

## 当天技术趋势

1. **安全审计成为最大增量主题**：`security-audit-skill` 与 `open-code-review` 合计约 +6,893 Star，占前十约 47.1%。前者提供审计方法论，后者提供生产管线与工程边界，两者更适合组合而不是互相替代。
2. **浏览器 Agent 的核心矛盾是登录态价值与权限风险同时放大**：`BrowserSkill` 复用真实会话带来极高实用性，但本地守护进程鉴权缺陷也能直接升级为会话接管。浏览器控制必须把扩展身份、配对密钥、确认策略和独立 Profile 视为一等安全边界。
3. **代码审查控制面继续确定性化**：`open-code-review` 把 Token 上限前移到每轮调用、用服务器 `isOutdated` 加 veto 管理线程、对增量评论去重，说明生产 Agent 的重点正在从“模型会不会审查”转向“审查何时停止、如何回滚、哪些副作用允许发生”。
4. **RAG 平台正在变成 MCP 权限代理**：`WeKnora` 的工作区端点、令牌、KB/工具白名单、写权限授予和所有者租户上下文，比单纯向量检索更接近企业 Agent 控制面。
5. **研究型 Agent 更重视 Windows 与跨平台可复现**：`OpenResearch` 对 Windows Cursor/Codex 安装的修复，使其更适合桌面环境中的长期实验；证据链价值不只来自 Git，也来自执行环境可复现。
6. **本地推理热度降速但没有失去工程支撑**：`colibri` 从第二降至第八，但仍有约 83 次提交；排名回落更多是新增安全主题分流，而不是项目停滞。

## 最值得深入研究的 3 个项目

### 1. alibaba/open-code-review

**理由**：约 +3,286 Star/24h、+11,489 Star/7d，且近 7 天有约 31 个作者身份。对现有内网 OCR 改造，最值得立即验证的是三项：`--max-tokens-budget` 是否能在运行中分组准确停止；重叠增量评论是否能避免重复噪声；`resolve_outdated=report` 是否能先只报告、完全不修改 MR 线程。建议在镜像 GitLab/GitHub 仓库用固定缺陷集、`background.md`、`rules.json` 和本地 `/v1` 模型做回归。

### 2. Tencent/BrowserSkill

**理由**：约 +1,302 Star/24h、相对日增约 46.5%，并有 77 次提交，代表真实浏览器 Agent 的主流形态。但研究重点应是安全边界而非安装使用：分析 WebSocket 配对、扩展 ID 白名单、标签借用确认、人工接管、下载归属和守护进程生命周期。公开 Issue #273 修复并通过复测前，不应连接含公司 GitLab、邮箱、网银或其他敏感登录态的浏览器；实验只能放在独立 Profile 与测试账户中。

### 3. Tencent/WeKnora

**理由**：约 +1,125 Star/24h、+3,982 Star/7d，近 7 天约 81 次提交、20 个作者身份。它最新的原生 MCP Server 正好覆盖 Agent/RAG 学习中的关键问题：谁能访问哪个知识库、哪些工具可调用、写操作如何授权、共享 KB 应在哪个租户上下文执行。建议重点抽取其端点令牌、KB allowlist、工具 allowlist、速率限制、Owner Tenant 切换和审计链路，用于团队记忆与内网知识平台设计。
