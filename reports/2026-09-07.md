1. **24 小时新增 Star**：采用 GitHub Trending 日榜的 `stars today`；这是滚动窗口，不等于自然日增量。GitHub 页面展示顺序不严格按该值排序，本报告按数值重新排序。

3. **Fork 变化**：对连续上榜项目使用 9 月 6 日与 9 月 7 日相邻快照差；新上榜项目不估算 24 小时 Fork 变化。
4. **工程活跃度**：统计 2026-08-31 00:00 UTC 起约 7 天的默认分支提交，单仓最多读取 100 条。`hermes-agent` 触及上限，写作“≥100”。
5. **贡献者活跃度**：按提交记录中的去重作者邮箱估算，可能把同一人的多个邮箱拆开，也可能包含机器人；`hermes-agent` 因提交截断写作“≥18”。该值是活跃作者替代信号，不等同仓库累计 Contributors。
6. **讨论热度**：统计同窗口新建 GitHub Issue，单仓最多读取 100 条；`hermes-agent`、`opencode` 与 `FckSignups` 触及上限，写作“≥100”。PR 与 Discussions 独立增量未可靠取得。
7. **爆发原因**：根据 README、近期活动和榜单表现作分析推断，不代表维护者官方结论。

## 项目分析

### 1. mattpocock/skills

- **主要用途**：提供可组合 Agent Skills，覆盖需求澄清、领域语言、ADR、TDD、故障诊断、代码审查、重构和项目工作流。
- **技术栈**：`SKILL.md`、Markdown、Shell/Node 辅助、Claude Code Plugin 与 skills.sh 分发；MIT License。
- **近期增长**：日榜约 **+2,207 Star**；周榜值缺失；相对日增约 **0.87%**。当前 254,493 Star、21,464 Fork；较上一期 Fork 约 **+146**，排名上升 1 位。
- **贡献与讨论**：近 7 天约 2 次提交、约 2 个作者身份、32 个新 Issue；PR 与 Discussions 增量缺失。
- **爆发原因**：把传统工程方法拆成可修改、可组合的 Skills，直接针对需求偏差、测试不足和架构腐化等 Agent 开发失败模式。
- **亮点**：不绑定模型；区分用户编排 Skill 与模型自动调用的纪律 Skill；支持只读订阅版与可编辑复制版。
- **潜在风险**：多 Skill 叠加会产生指令冲突和上下文膨胀；自动更新扩大供应链信任范围；代码活动低于传播热度。
- **适合人群**：软件工程师、技术负责人、编码 Agent 用户及希望逐步引入 AI 工程规范的团队。
- **值得关注程度**：**★★★★☆**。方法体系成熟，但应通过团队缺陷率和交付周期验证实际收益。

- **近期增长**：日榜约 **+436 Star**；周榜值缺失；相对日增约 **15.21%**。当前 3,303 Star、209 Fork；首次进入近期前十，24 小时 Fork 变化缺失。
- **贡献与讨论**：近 7 天约 5 次提交、约 1 个作者身份，新 Issue **≥100**。大量 Issue 是网站表单自动创建的工具投稿，代表参与度与审核队列，不是同等数量的缺陷报告。
- **爆发原因**：“开箱即用、无账号、无追踪”的反注册墙定位清晰，200+ 工具的目录形式易分享；用户可通过表单直接投稿，放大社区热度。
- **亮点**：工具准入条件透明；无 Cookie、无分析；明确区分目录 GPL-3.0 与第三方项目许可证；分类和数据 Schema 简单。
- **潜在风险**：目录链接、隐私承诺与开源状态会随第三方变化；投稿量远高于维护者人数，审核、死链与恶意站点风险上升；项目名称与品牌名不一致可能造成发现和信任摩擦。
- **适合人群**：隐私敏感用户、浏览器工具使用者、开源目录维护者与研究社区审核流水线的开发者。
- **值得关注程度**：**★★★★☆**。增长快且社区输入强，但长期价值取决于审核质量而非收录数量。

5. **“免注册、可直接使用”形成反平台化需求**：`NoSignups` 新上榜，反映用户对账号墙、追踪和云端绑定的反感；但目录型项目的核心壁垒是持续审核，而不是代码复杂度。
