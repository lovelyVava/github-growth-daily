## 统计口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 日榜的 `stars today`，这是滚动窗口，不等于自然日或相邻累计快照差；页面顺序不严格按该值排序，本报告按数值重新排序。
2. **7 天新增 Star**：采用周榜的 `stars this week`。只有公开周榜直接展示的数值才写入；未进入周榜的项目标为“缺失”，不从累计 Star 反推。
3. **当前 Star/Fork**：采用 2026-09-17 08:00–08:13 的 GitHub 页面/API 快照；不同接口抓取时间存在分钟级差异。
4. **Fork 变化**：仅对连续进入前十的项目比较 9 月 16 日与 9 月 17 日相邻快照；新上榜或重新上榜项目不估算 24 小时 Fork 变化。
5. **工程活跃度**：统计 2026-09-10 00:00 UTC 起约 7 天的默认分支提交，单仓最多读取 100 条；触及上限写作“≥100”。
6. **贡献者活跃度**：按提交记录中的 GitHub 账号或作者邮箱去重估算，可能拆分同一人的多个身份或包含机器人；截断仓库写作下限，不等同累计 Contributors。
7. **讨论热度**：统计同一窗口新建 Issue，排除 PR。Issue 可能由机器人、模板、集中投稿或维护者快速拆分产生，数量不等于有效人工讨论。
8. **许可证识别**：按 GitHub API、README 与根许可证文件交叉判断；模型、插件、数据和下载内容仍可能保留独立条款。
9. **爆发原因**：根据 README、近期提交、Issue 内容与榜单表现作分析推断，不代表维护者官方结论。

## 项目分析

### 1. alibaba/open-code-review

- **主要用途**：对工作区、分支、提交或完整目录进行 AI 代码审查，以确定性管线控制文件覆盖、规则匹配和评论位置，以 Agent 完成语义判断。
- **技术栈**：Go、Git、文件筛选与分组、隔离子任务、位置校正、OpenAI/Anthropic 兼容模型、MCP、CLI、Agent Skills 与 CI/CD；Apache-2.0。
- **近期增长**：日榜约 **+3,231 Star**、周榜约 **+8,594 Star**；相对日增约 **11.3%**。当前 31,748 Star、2,257 Fork；较上期 Fork 约 **+214**，排名保持第一。
- **贡献与讨论**：近 7 天约 39 次提交、26 个作者身份、53 个新 Issue。最新提交修复 CRLF diff、超大未跟踪文件读取和二进制文件识别，并改善 Suggested Change 缩进。
- **爆发原因**：企业规则、全量 Scan、可恢复 Session、GitLab CI 和本地模型兼容持续回应“Agent 审查必须可控、可追踪”的需求；近期安全与性能修复增强了可信度。
- **亮点**：确定性管线保证文件覆盖和行级定位；背景文件、路径规则、JSON 输出与可恢复会话适合内网落地。
- **潜在风险**：高 Precision 不代表高 Recall，仍会漏报；路径/忽略配置错误会形成系统性盲区；外部模型可能接触源码；Issue 增长也意味着边界条件仍在暴露。
- **适合人群**：内网 GitLab、提交前扫描、MR 自动评论、本地 `/v1` 模型和需要项目背景规则的研发团队。
- **值得关注程度**：**★★★★★**。增长、协作广度与实际修复三项都强，但应以回归集验证召回率。

### 2. JustVugg/colibri

- **主要用途**：把 VRAM、RAM 与 NVMe 作为统一层级，按路由流式加载 MoE 专家，使消费级或异构硬件运行超大模型。
- **技术栈**：纯 C、异步 I/O、专家 LRU/热缓存、CPU/CUDA/Metal/Vulkan、MLA KV 压缩、MTP/语法推测解码；Apache-2.0。
- **近期增长**：日榜约 **+1,546 Star**；周榜直接值缺失；相对日增约 **4.6%**。当前 35,015 Star、3,677 Fork；较上期 Fork约 **+136**，排名上升 1 位。
- **贡献与讨论**：近 7 天提交 **≥100**、作者身份 **≥12**、45 个新 Issue；近期明确 Apache-2.0 版权主体并补上 NOTICE。
- **爆发原因**：超大 MoE 的本地运行想象、纯 C 零依赖与 AMD RDNA4 Vulkan 路径继续传播。
- **亮点**：不静默改变精度和路由语义；按专家热度做内存放置；公开端到端基准与负结果。
- **潜在风险**：低内存能启动不等于可交互；Kimi K3 仍需约 1.6 TB 存储，SSD 随机读和内存带宽会成为瓶颈；RX 9070 XT 吞吐需本机复现。
- **适合人群**：MoE、I/O 调度、本地推理、AMD GPU/Vulkan 和大模型系统研究者。
- **值得关注程度**：**★★★★★**。工程活动极强，但先用小型 MoE 建立硬件基线更务实。

### 4. abue-ammar/tinycast

- **主要用途**：macOS 原生启动器，整合应用/文件搜索、剪贴板、快捷键、窗口管理、笔记、AI Chat，并原生运行 Raycast 扩展。
- **技术栈**：Swift、SwiftUI、macOS Accessibility/Spotlight/Shortcuts、原生扩展兼容层；AGPL-3.0-or-later（GitHub API未识别，已以根 LICENSE 核验）。
- **近期增长**：日榜约 **+1,179 Star**；周榜直接值缺失；相对日增约 **26.8%**。当前 5,572 Star、266 Fork；首次进入近期前十。
- **贡献与讨论**：近 7 天约 99 次提交、15 个作者身份、172 个新 Issue。最新修复企业受管 MCP 配置冲突、扩展 Buffer 兼容性，并加入自定义窗口尺寸。
- **爆发原因**：原生 SwiftUI、无 Electron、无遥测、免费开源以及 Raycast 扩展兼容形成清晰替代叙事。
- **亮点**：功能整合度高；AI 默认关闭并可自带 Key；文件搜索复用 Spotlight，不建立私有索引；权限用途写得较清楚。
- **潜在风险**：目前要求 macOS 26，macOS 15 路径已停止维护；自签名安装需要清除 quarantine；Accessibility、剪贴板、Shell Command 与扩展共同扩大权限和供应链面；Issue 爆发带来维护压力。
- **适合人群**：macOS 26+、希望替代 Raycast/Alfred、重视本地原生与无遥测的用户和 SwiftUI 开发者。
- **值得关注程度**：**★★★★☆**。产品热度与工程活动强，但平台限制和高权限需要谨慎评估。

## 当天技术趋势

1. **Agent 安全从清单走向可验证控制回路**：`security-audit-skill` 的覆盖账本、独立验证者和三态结论，与 `open-code-review` 的确定性文件覆盖、位置校正形成互补。前者关心“有没有证据”，后者关心“有没有遗漏文件与评论错位”。
2. **企业知识平台开始吸收 Agent Runtime**：`WeKnora` 不再只是 RAG UI，而是加入 Skill 沙箱、长期记忆、MCP、Wiki 版本历史、任务队列和工作区 RBAC，知识库正在变成 Agent 的控制面。
3. **研究 Agent 强调可复现而非只会聊天**：`OpenResearch` 用 worktree、实验树、提交快照和终端把假设—代码—实验—结果串成证据链，降低“回答看似合理但无法重现”的风险。
4. **本地原生应用重新获得增长**：`tinycast` 的原生 SwiftUI、无 Electron、无遥测叙事和 `colibri` 的纯 C/零依赖共同表明，用户愿意为更低资源占用和更透明的本地执行迁移。
5. **高活跃不等于低风险**：`tinycast` 的 172 个 Issue、`WeKnora` 的 659 个开放 Issue、`open-code-review` 的 53 个新 Issue都提示，爆发期会迅速暴露兼容、权限和规模边界。
6. **许可证元数据不能只信 API**：WeKnora 与 tinycast 的 GitHub API 均未给出标准 SPDX，但根文件分别明确 MIT 与 AGPL-3.0-or-later；自动化尽调必须回读根许可证。

## 最值得深入研究的 3 个项目

### 1. cloudflare/security-audit-skill

**理由**：约 +927 Star/24h，核心价值不是排名，而是把安全审计拆成覆盖账本、猎取、独立反证和机器可读结果。建议先用带已知 CVE/测试漏洞的小型仓库跑多轮基准，记录召回率、误报率、Token 成本、覆盖缺口与 `needs_validation` 比例，再决定是否接入正式审查；任何目标代码执行都应在禁网、环境白名单、资源限制、scratch-only 写入的 OS 级沙箱中完成。

### 3. Tencent/WeKnora

**理由**：约 +1,197 Star/24h、+3,034 Star/7d，且有 19 个作者身份参与；它把 RAG、Wiki、长期记忆、Skill 沙箱、MCP、RBAC 与可观测性连接成完整平台。建议重点研究其文档版本/回滚、租户网络策略、主体验证、跨工作区隔离和 Langfuse 证据链，并用混合语言大文档测试检索、TPM 限流与失败恢复。
