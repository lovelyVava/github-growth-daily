## 数据口径与限制

1. **24 小时新增 Star**：采用 GitHub Trending 日榜观察时刻显示的 `stars today`，属于滚动窗口近似值。GitHub 页面展示顺序不完全等于该数值大小，本报告按日增 Star 重新排序。
2. **7 天新增 Star**：采用周榜显示的 `stars this week`。未进入周榜可见范围时标记“缺失”，不使用累计 Star 倒推。本期前十仅 `OpenLogi` 与 `omarchy` 能可靠取得周榜值。
3. **Fork**：累计 Fork 来自本期仓库 API 快照；连续上榜项目以本期减上一期快照得到约 24h Fork 增量，统一标为“快照估算”；新上榜项目的 Fork 增量缺失。
4. **贡献活跃度**：近 7 天提交数来自最近 100 条提交按 `created_at >= 2026-08-17` 过滤；达到 100 时记为“≥100（截断）”。新建 Issue/PR 来自同日起的 GitHub Search 计数，包含已关闭项、机器人和自动同步，不能等同于独立贡献者人数。统一的独立贡献者数本期无法可靠取得，明确标记为缺失。
5. **讨论热度**：使用近 7 天新建 Issue/PR 和 Discussions 是否启用作为代理；未取得统一口径的 Discussion 新增帖/评论数。
6. **相对日增**：按 `24h 新增 Star ÷（当前累计 Star - 24h 新增 Star）` 估算，用于识别小体量项目爆发强度。
7. **许可证**：采用仓库 API 的 SPDX 识别结果；缺失不代表可任意商用，需继续核对仓库文件、数据来源和第三方资产条款。

- **爆发原因**：编码 Agent 正从编辑器助手扩展到终端、CI、自动化和多 Agent 协作；高频发布与真实工作负载不断扩大关注。
- **亮点**：权限、沙箱、工具调用、会话、补丁和非交互执行链路完整，是企业 Agent 工程的重要参考实现。

## 当天技术趋势

1. **编码 Agent 生态开始分层**：`codex` 提供执行器，`free-claude-code` 负责模型路由，`skills`/`ECC` 负责工程规则，`hermes-agent` 延伸到记忆、计划与多渠道交付。
2. **“可执行知识”成为新资产形态**：`skills`、`ECC`、`book-to-skill` 都在把经验、书籍或流程转成 Agent 可调用单元，版本、来源、权限与冲突管理会成为下一阶段关键问题。
3. **本地优先从应用扩展到系统级环境**：`OpenLogi` 解决外设控制，`omarchy` 直接整合桌面和开发栈；两者都用隐私、可控与默认体验换取增长。
4. **热度与工程信号仍需分开看**：`awesome-gpt-image-2` 传播强但近 7 日代码与协作量较低；`codex`、`OpenLogi`、`omarchy` 则同时具备高涨星和高协作活跃度。
5. **长时 Agent 的安全成本快速上升**：当记忆、自我改进、Cron、消息渠道和终端执行叠加，必须把最小权限、身份验证、审计、记忆投毒防护和回滚放在功能之前。

## 最值得深入研究的 3 个项目

### 1. [openai/codex](https://github.com/openai/codex)

重点研究沙箱与批准机制、工具调用协议、补丁生成、仓库指令加载、会话恢复和非交互执行。它最适合作为“IDE 日常辅助—提交前扫描—服务器上线前审查”分层权限模型的参考底座；同时应分析其高 Issue 密度背后的兼容性与支持成本。

### 2. [Alishahryar1/free-claude-code](https://github.com/Alishahryar1/free-claude-code)

重点研究如何在不破坏原生 Agent 会话、工具与流式输出的前提下统一模型目录、故障切换和多端入口。对企业内网模型适配与成本路由很有参考价值，但试验时应优先审查安装器、代理鉴权、密钥存储、日志脱敏和各提供商条款。

### 3. [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent)

它把长期记忆、自生成 Skills、计划任务、消息网关、子 Agent 和多种执行后端放到同一架构中，是研究长时自主 Agent 的高密度样本。建议先做威胁建模和最小权限部署，再评估其记忆治理、技能版本、任务恢复和审计链路；不要直接在含生产凭据的环境运行。
