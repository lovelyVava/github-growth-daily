## 项目分析

### 1. GoogleChrome/modern-web-guidance-src

- **主要用途**：把现代 Web API、性能、可访问性和兼容性实践以可检索 Skill 注入编码 Agent，并扫描遗留模式。
- **技术栈**：TypeScript、Node.js/npm CLI、静态分析器、评测 Harness、文档与 Dashboard；Apache-2.0。
- **近期增长及口径**：约 **+7,015 Star/7d**，周榜第一；24 小时直接值缺失，相邻快照净增约 +165。当前 8,554 Star、731 Fork，Fork +27，由第二升至第一。
- **贡献与讨论**：近七日约 54 次提交、29 个新议题；近期增加 dialog 与视觉效果可访问性规则，并让空评测集上传直接失败。问题包括 Passkey 网络错误处理、支付表单扫描漏检和外部 PR 路由。
- **爆发原因（推断）**：模型容易复现训练数据中的旧式 Web 模式；由 Chrome 生态维护、可检索、可扫描且带 Eval 的规则层直接补上知识时效缺口。
- **亮点**：专家知识、Token 友好检索、静态检查和公开评测形成闭环，不只是提示词集合。
- **潜在风险**：日增直接值已缺失，短期峰值可能降温；发布包入口、规则冲突、扫描误报与漏报仍需在真实仓库复测。
- **适合人群与关注程度**：前端平台、编码 Agent、Web 性能、可访问性与代码评审团队；**★★★★★**。

### 2. dream-num/univer

- **主要用途**：在产品中嵌入表格、文档、计算、协作与文件处理能力，并让 Agent 通过统一 API 操作 Office 内容。
- **技术栈**：TypeScript、Canvas 渲染、公式引擎、插件/依赖注入、Facade API、Web/Server/AI SDK、pnpm Monorepo；开源核心 Apache-2.0。
- **近期增长及口径**：约 **+1,774 Star/24h**；11 月 11 日以来可见净增约 +6,245。当前 29,417 Star、2,635 Fork，Fork +76，由第一降至第二但日增仍居本榜第一。
- **贡献与讨论**：近七日约 49 次提交、14 个新议题；近期强化批注写入权限、Word 制表位和表格边框兼容。问题仍集中在负数文本格式、日期函数和 Excel 函数缺口。
- **爆发原因（推断）**：Agent 从生成文本转向编辑真实业务文档，需要可嵌入、可计算、可撤销并能接入应用权限的 Office 执行层。
- **亮点**：开源核心包含内容模型、命令、公式、渲染与 Facade API，可用于结构化、可撤销的业务操作。
- **潜在风险**：开源核心与商业插件、Server SDK、AI SDK 存在功能边界；公式兼容、协作冲突、文档保真与权限语义需用真实样本验证。
- **适合人群与关注程度**：企业办公平台、低代码、文档 Agent、表格自动化与嵌入式编辑器团队；**★★★★★**。

### 3. ag-ui-protocol/ag-ui

- **主要用途**：定义 Agent 与用户界面之间的轻量事件协议，使运行状态、工具调用、上下文和人机协作可以跨框架流式传输。
- **技术栈**：TypeScript 核心与协议 Schema、多语言 SDK、事件流、前端客户端、中间件及多种 Agent 框架集成；MIT。
- **近期增长及口径**：约 **+1,445 Star/24h**、相对日增约 **7.7%**；11 月 14 日以来可见净增约 +2,847。当前 20,156 Star、2,078 Fork，Fork +73，由第八升至第三。
- **贡献与讨论**：近七日约 49 次提交、6 个新议题；近期发布 Cloudflare Agents 集成。问题涉及 LangGraph 每请求工厂、事件流 v3、畸形 outcome 校验与 AG2 快速入门。
- **爆发原因（推断）**：Agent 后端和前端框架快速分化，团队需要一个比自定义 WebSocket 消息更稳定、比单一 SDK 更中立的交互层。
- **亮点**：事件模型适合流式状态、工具调用和人工介入，多语言 SDK 与框架适配可降低前后端耦合。
- **潜在风险**：协议与各语言 SDK 可能版本漂移；事件流可能携带提示、工具参数或用户数据，必须设计认证、租户隔离、脱敏、重放保护和断线恢复。
- **适合人群与关注程度**：Agent UI、实时协作、协议设计、跨框架平台与前端基础设施团队；**★★★★★**。

### 4. kajisho5/ffmpeg-skill

- **主要用途**：为 Claude Code、Cursor、Codex 等编码 Agent 提供本地视频剪辑能力，覆盖裁切、字幕、重构画幅、响度与平台导出。
- **技术栈**：Python、FFmpeg/FFprobe、Whisper、MCP Server、机器可读工具契约、npm 安装入口；MIT。
- **近期增长及口径**：约 **+1,292 Star/24h**、相对日增约 **20%**；11 月 13 日以来可见净增约 +2,415。当前 7,838 Star、730 Fork，新上榜第四。
- **贡献与讨论**：近七日提交 **≥100**、87 个新议题；近期发布 3.13.2、补充 Reels 全流程示例并在 doctor 中检查 Whisper 启动。反馈集中在音画漂移、导出探测、响度和批量裁剪。
- **爆发原因（推断）**：视频 Agent 的最大门槛不是生成提示词，而是把 FFmpeg 复杂参数封装为可发现、可验证、可组合的本地工具契约。
- **亮点**：本地处理、无需云 API Key，工具覆盖从检查到交付，且输出可以用 FFprobe 复核；对隐私视频与批处理尤其有吸引力。
- **潜在风险**：87 个新议题说明格式、编解码器、时长与平台交付边界仍在快速收敛；Agent 对本地文件和 FFmpeg 命令的权限必须隔离，批量操作前应使用副本。
- **适合人群与关注程度**：短视频自动化、媒体流水线、字幕与音频处理、Agent Tool/MCP 开发者；**★★★★★**。

### 5. NVIDIA/SkillEvaluator

- **主要用途**：用三层流水线验证 Agent Skill：静态质量/安全检查、语义去重，以及有无 Skill 的真实 Agent 对照评测。
- **技术栈**：Python、CLI/CI、SkillSpector、Gitleaks、可选 Semgrep、Embedding/LLM、Docker/Harbor 沙箱；Apache-2.0。
- **近期增长及口径**：约 **+869 Star/24h**、相对日增约 **34%**；11 月 12 日以来可见净增约 +2,584。当前 3,408 Star、474 Fork，Fork +58，由第四降至第五。
- **贡献与讨论**：近七日提交 **≥100**、28 个新议题；近期加强解释器代码、HTTP 上传和破坏性命令检测并补充无密钥校验文档。问题包括 Tier 1 `INCOMPLETE`、新 Provider 与自定义请求头。
- **爆发原因（推断）**：Skill 数量快速增加后，团队需要回答“格式正确、安全、无重复，而且是否真的提升任务结果”，评估层开始成为独立基础设施。
- **亮点**：可从无模型的确定性检查升级到嵌入去重和沙箱对照实验；结果能接入 CLI、JSON 与 CI 门禁。
- **潜在风险**：安全规则仍会出现误报与漏报，外部扫描器、模型或沙箱配置不完整会产生 `INCOMPLETE`；小样本不足以证明真实收益。
- **适合人群与关注程度**：Agent Skill 平台、评测、安全、CI 和企业技能目录团队；**★★★★★**。

### 6. google-research/paper-orchestra

- **主要用途**：把研究想法、实验日志和素材交给多 Agent 流程，生成文献综述、图表和可投稿的 LaTeX 论文草稿。
- **技术栈**：Python、多 Agent 编排、LaTeX、Semantic Scholar/文献检索、LLM Provider API、绘图与论文模板；Apache-2.0。
- **近期增长及口径**：约 **+1,072 Star/24h**、相对日增约 **46%**；11 月 16 日以来可见净增约 +2,014。当前 3,384 Star、441 Fork，新上榜第六。
- **贡献与讨论**：近七日仅 6 次提交、11 个新议题；近期修复 LaTeX 转义、缺失依赖和可选 Provider 密钥。问题包括无绘图模式丢失用户图片、API Key 输出到日志和会议模板缺口。
- **爆发原因（推断）**：科研 Agent 从单轮润色走向“材料—检索—结构—图表—LaTeX”流水线，完整演示极易获得传播，但真实论文质量仍需同行评审验证。
- **亮点**：能把非结构化实验材料组织成完整论文工程，并把检索、写作、图表和模板拆给不同角色。
- **潜在风险**：提交活动较低，已有密钥泄露和图像遗漏问题；引用真实性、作者责任、数据授权、幻觉和学术不端风险不能交给 Agent 自动兜底。
- **适合人群与关注程度**：科研写作工具、实验记录整理、多 Agent 编排与 LaTeX 自动化研究者；**★★★★☆**。

### 7. Tencent/LoopForge

- **主要用途**：自托管编码 Agent 交付工作台，用聊天或标准化 SOP 串联规划、实现、测试、独立评审、人类审批和 PR/MR。
- **技术栈**：Go、Docker/Compose 沙箱、MySQL、Web 控制台、Node.js 本地 CLI、GitHub/GitLab 与多种 Agent CLI；MIT，第三方组件保留原许可。
- **近期增长及口径**：约 **+591 Star/24h**、相对日增约 **20%**；11 月 11 日以来可见净增约 +3,206。当前 3,516 Star、479 Fork，Fork +101，由第三降至第七。
- **贡献与讨论**：近七日提交 **≥100**、62 个新议题；近期将 Local 标为 legacy、加入个人会话工作区和每模型 reasoning effort。问题涉及统计归属、版本兼容契约与 CI 静默跳过扫描。
- **爆发原因（推断）**：团队开始要求 Agent 交付具备固定阶段、确定性脚本、人类门禁、可恢复运行和 MR 证据，而不只是一次性聊天产出。
- **亮点**：Agent、脚本、人类门禁和子 SOP 可组合；每步保留日志、产物与状态，并支持重试、回退和接管。
- **潜在风险**：默认 Docker socket 不适合不可信多租户；最新 CI 议题还暴露了缺少 `ripgrep` 时扫描静默跳过的问题，上线前必须验证门禁真实执行。
- **适合人群与关注程度**：研发效能、Agent 平台、内网交付、GitOps 与需要人工审批的团队；**★★★★★**。

### 8. alibaba/open-code-review

- **主要用途**：混合确定性流水线与 LLM Agent 的代码评审 CLI，提供精确行级评论、全文件扫描和多语言规则。
- **技术栈**：Go CLI、Git、npm 分发、模板化规则、并发子 Agent、OpenAI/Anthropic 兼容模型接口；Apache-2.0。
- **近期增长及口径**：约 **+763 Star/24h、+3,675 Star/7d**。当前 53,942 Star、4,448 Fork；上期 Fork 只有近似值，变化缺失。排名由第五降至第八。
- **贡献与讨论**：近七日约 32 次提交、20 个新议题；近期修复 OAuth 回调、链接评测榜并优化多语言文档加载。问题包括所有子任务失败仍退出 0、GitLab 失败评审发布“Looks good”和 Windows CI 退出异常。
- **爆发原因（推断）**：文件选择、规则匹配与评论定位由确定性工程约束，动态上下文交给 Agent；混合架构比纯提示词评审更适合企业流程。
- **亮点**：公开基准覆盖多仓库、真实 PR 与多语言，并强调高精度、较低 Token 成本和大变更集覆盖。
- **潜在风险**：当前“评审全失败仍返回成功”的工单会影响 CI 门禁可信度；修复前应对输出状态做二次校验，并继续治理源码、Diff 与密钥边界。
- **适合人群与关注程度**：企业代码评审、研发效能、AppSec、GitHub/GitLab 流水线团队；**★★★★★**。
