## 项目分析

### 1. google/ax

- **主要用途**：用声明式任务、工作区、网关与模型配置运行大规模 Agent，并支持隔离、挂起、恢复和远程观察。
- **技术栈**：Go、gRPC、Redis Streams、Kubernetes、YAML 清单、Agent Substrate；Apache-2.0。
- **近期增长及口径**：约 **+1,543 Star/24h**；周榜直接值缺失；相对日增约 **17.1%**。当前 9,022 Star、432 Fork，Fork 较上期约 +79；连续第一。
- **贡献与讨论**：近 7 天 3 次提交、1 个作者身份、38 个新 Issue；提交包括外部路线图、工作流权限收紧和架构重组。Issue 含少量垃圾项，但控制器串行吞吐、状态回写与真实状态一致性问题有效且关键。
- **爆发原因**：Google 品牌、类 Kubernetes 声明式体验，以及任务、工作区、模型与出网控制的统一抽象，正好命中企业 Agent 控制面的缺口。
- **亮点**：原语边界清晰；工作区可预置 Git、MCP 和 Skills；可暂停、恢复与 SSH 观察任务，并把高密度沙箱委托给 Agent Substrate。
- **潜在风险**：项目仍在快速变化；任务状态、密钥、网络白名单和工作区就绪信号都是高权限边界。日增很高但 7 天只有 3 次默认分支提交，传播速度明显快于核心提交速度。
- **适合人群与关注程度**：Agent 平台、Kubernetes、沙箱和企业控制面团队；**★★★★★**。适合隔离验证，不宜直接承载生产密钥。

### 2. dream-num/univer

- **主要用途**：在浏览器或 Node.js 中嵌入电子表格、文档、演示、数据表、画布与 PDF，让 Agent 生成、编辑、渲染并交由人类审阅 Office 内容。
- **技术栈**：TypeScript、Canvas、公式引擎、插件系统、React/Vue/Web Components、统一 Facade API；开源核心 Apache-2.0。
- **近期增长及口径**：约 **+1,142 Star/24h**；周榜值缺失；相对日增约 **7.0%**。当前 16,314 Star、1,433 Fork，Fork 较上期约 +65；由第三升至第二。
- **贡献与讨论**：近 7 天 37 次提交、4 个作者身份、2 个新 Issue；最新发布 `v1.0.0`，并持续修复工作表菜单、通知、格式刷和切片器。
- **爆发原因**：Agent 不只需要输出文件，还需要可编辑、可渲染、可比较差异、可人工审阅的工作表面；`v1.0.0` 也强化了“从组件到平台”的成熟度信号。
- **亮点**：表格、文档、幻灯片与公式引擎共用插件化架构；浏览器 UI 与无头处理并存，适合 OCR 结果复核和企业文档 Agent。
- **潜在风险**：开源核心、Pro 与协作能力边界需逐项核验；实时画布与导出一致性仍有缺口，例如页眉页脚图片可导出却不渲染。复杂格式必须做视觉回归与文件级 round-trip 测试。
- **适合人群与关注程度**：Office 产品、OCR 后处理、企业文档生成与人工审阅团队；**★★★★★**。

### 5. agent-substrate/substrate

- **主要用途**：高密度运行有状态 Agent 沙箱，让大量 Actor 复用较少 Worker，并支持挂起、恢复、迁移、快照和零信任网络隔离。
- **技术栈**：Go、Kubernetes、gVisor、microVM/cloud-hypervisor、Envoy、gRPC、WorkerPool/ActorTemplate；Apache-2.0。
- **近期增长及口径**：约 **+558 Star/24h**；周榜值缺失；相对日增约 **16.0%**。当前 3,483 Star、411 Fork，Fork 较上期约 +26；从第四降至第五但绝对增速翻倍以上。
- **贡献与讨论**：近 7 天 56 次提交、24 个作者身份、62 个新 Issue，是本期贡献者广度最强项目。近期增加删除前置条件、状态页与恢复文档，并清理失败原因分类。
- **爆发原因**：长期 Agent 需要保存内存、文件系统与网络状态，而“一任务一 Pod”密度和冷启动成本太高；它又是 `google/ax` 的执行层，获得联动关注。
- **亮点**：框架无关，支持 gVisor 与 microVM；状态快照、挂起/恢复、高密度复用、网络与凭据注入边界清晰。
- **潜在风险**：README 明确未准备好生产使用。Issue 报告节点重启后 Actor 仍显示 RUNNING 但不可达，以及状态页输出原始 Postgres 连接串；多租户残留、真实状态校验和 Secret 脱敏必须先解决。
- **适合人群与关注程度**：Agent Runtime、云开发环境、Kubernetes 沙箱和多租户平台工程师；**★★★★★**。

### 10. DeusData/codebase-memory-mcp

- **主要用途**：把代码库索引为持久知识图谱，为编码 Agent 提供函数、类、调用链、HTTP 路由、跨服务关系、影响分析与架构查询。

- **适合人群与关注程度**：大型代码库、MCP、代码理解、影响分析和本地优先 Agent 团队；**★★★★★**。

## 当天技术趋势

1. **Agent 控制面与运行时开始分层**：`google/ax` 负责声明式编排，`Agent Substrate` 负责沙箱与状态生命周期。真正难点已从“启动容器”转向真实状态校验、快照、凭据注入、网络边界与资源回收。
2. **Office 正成为 Agent 的可验证交付界面**：`Univer v1.0.0` 把表格、文档、演示和公式引擎放在统一 Runtime 中。对 OCR 与知识工作流来说，可编辑、可渲染、可 diff、可人工确认比直接生成 Markdown 更接近生产需要。
3. **本地代码知识图谱重新升温**：`codebase-memory-mcp` 把 tree-sitter、LSP 与 MCP 结合，目标是减少大仓库逐文件扫描和 Token 浪费。下一步竞争会落在图谱准确性、增量更新、跨语言调用与供应链可信度。
4. **Skills 生态从内容包走向行为门禁**：`superpowers`、`claude-code-templates`、`Impeccable` 分别覆盖研发流程、组件分发和前端设计；审批是否真的被执行、Hooks 是否跨平台一致、第三方组件是否可信，比 Skill 数量更重要。
5. **传播热度与交付强度差异明显**：`video-use` 约 +746 Star 却 7 天零提交、有效 Issue 近乎为零；`codebase-memory-mcp` 仅约 +190 Star，却有 74 次提交与 9 个作者身份。采用评估不能只看 Star。
6. **金融 Agent 分成“流程模板”和“终端替代”两条线**：`financial-services` 强调角色、连接器与人工签核；`OpenStock` 强调自托管行情看板。两者都需要清晰的数据时效、合规责任和失败降级路径。
7. **许可证筛选仍会重排榜单**：`mvt` 与 `treg` 的日增很高，但附加使用或商业服务限制。源码可见不等于标准开源，部署与二次分发前必须读具体条款。
