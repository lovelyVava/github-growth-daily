## 统计口径与限制

1. **24 小时新增 Star**：直接采用 GitHub Trending 日榜页面的 “stars today”，它是 GitHub 的滚动窗口指标，抓取时间差会使其与仓库当前累计 Star 不完全对齐。
2. **7 天新增 Star**：优先采用 GitHub Trending 周榜的 “stars this week”。未进入周榜的项目明确标为“缺失”，不使用累计 Star 反推。
3. **Fork 变化**：只有本日报在上一期留有同项目 API 快照时，才计算约 24 小时变化；新上榜项目只给当前 Fork 总量，避免伪造日增。
4. **贡献活跃度**：统计 2026-08-19 00:00 UTC 起约 7 天内 GitHub 可检索的提交、创建的 Issue 和 PR。提交查询最多返回 100 条，因此“≥100”代表截断下限。
5. **讨论热度**：GitHub 没有跨仓库统一的“讨论增量”接口，本报告以新建 Issue/PR、Trending 连续出现和社区入口作为代理；无法可靠量化时标为缺失。
6. **爆发原因**：根据 README、近期活动和榜单位置作出的分析性判断，不代表项目维护者官方结论。

## 项目分析

### 1. freestylefly/awesome-gpt-image-2

- **主要用途**：将 GPT Image 2 的提示词组织成可复用的“Prompt as Code”模板、案例和 Skills，面向工业级图像生成工作流。
- **技术栈**：JavaScript、Markdown/提示词模板；MIT License。
- **近期增长**：日榜约 **+1,698 Star**，周榜约 **+4,341 Star**；相对日增约 **10.9%**。API 当前 17,624 Star、1,822 Fork；较上期快照 Fork 约 **+183**。
- **活跃度与口径**：近 7 天约 10 次提交、0 个新 Issue、3 个新 PR。讨论量不高，增长更像内容传播驱动。
- **爆发原因**：GPT Image 2 热点与“高质量可复制提示词”需求叠加，案例可直接预览和复用，传播门槛低。
- **亮点**：530+ 逆向案例、20+ 模板，并将经验提炼为 Skills；对内容团队和设计自动化非常直观。
- **潜在风险**：效果与特定模型版本绑定；大量示例不等于系统评测，素材授权与生成内容合规需单独审查。
- **适合人群**：AI 视觉设计、营销内容、提示词工程、需要构建图像生成流水线的团队。
- **值得关注程度**：**★★★★★**。热度和实用性都强，但应把它当作素材与方法库，而不是稳定 API 契约。

### 2. openai/codex

- **主要用途**：运行在终端及开发环境中的轻量级编程 Agent，用于理解代码、编辑文件、执行命令与协作开发。
- **技术栈**：Rust 为主，Apache-2.0 License。
- **近期增长**：日榜约 **+1,183 Star**，周榜约 **+10,571 Star**；相对日增约 **1.0%**。API 当前 118,086 Star、17,996 Fork；较上期快照 Fork 约 **+155**。
- **活跃度与口径**：近 7 天提交 **≥100**、新 Issue 973、新 PR 352，均为本期最高梯队；提交数受 100 条上限截断。
- **爆发原因**：终端 Agent、MCP、Skills 和企业级权限治理持续成为开发者焦点，项目迭代密度极高。
- **亮点**：成熟的沙箱与审批边界、工具调用、会话与执行模型；适合研究 Agent 在真实代码库中的安全落地。
- **潜在风险**：Issue 总量大、功能快速演进，配置和兼容性可能频繁变化；使用外部工具时仍需最小权限和人工复核。
- **适合人群**：软件工程师、DevOps、代码审查与研发效能团队、Agent 平台开发者。
- **值得关注程度**：**★★★★★**。增长不是短时爆发，而是高活跃度支撑的持续热门。

### 3. basecamp/omarchy

- **主要用途**：面向开发者的高度主张式 Linux/Arch 桌面环境与配置集合。
- **技术栈**：Shell 为主；MIT License。
- **近期增长**：日榜约 **+1,080 Star**，周榜约 **+3,934 Star**；相对日增约 **3.6%**。API 当前 31,232 Star、3,179 Fork；较上期快照 Fork 约 **+121**。
- **活跃度与口径**：近 7 天 59 次提交、新 Issue 294、新 PR 483，社区参与非常活跃。
- **爆发原因**：开发者对可复现、开箱即用且审美统一的 Linux 工作站需求上升，也受开发者社区品牌效应带动。
- **亮点**：一体化体验、配置即代码、社区贡献速度快。
- **潜在风险**：强观点配置意味着迁移成本；Shell 安装脚本涉及系统级改动，升级前应审查脚本并备份。
- **适合人群**：Arch Linux 用户、希望快速搭建一致开发环境的个人或小团队。
- **值得关注程度**：**★★★★☆**。适合参考环境工程，不宜未经评估直接套到生产工作站。

- **主要用途**：给编码 Agent 添加“懒惰资深开发者”式约束，优先复用原生能力、减少过度设计和代码量。
- **技术栈**：JavaScript/npm 与 Agent Skill；MIT License。

- **值得关注程度**：**★★★☆☆**。值得做对照实验，不应将“代码更少”直接等同于“质量更高”。

### 6. AgriciDaniel/claude-obsidian

- **主要用途**：为 Obsidian 与 Claude Code 构建本地优先的第二大脑，把来源材料转成带引用、可连接的 Markdown 知识图谱。
- **技术栈**：Python、Markdown/JSON、Agent Skills 与 Claude Code 插件；MIT License。
- **近期增长**：日榜约 **+810 Star**，周榜数据缺失；相对日增约 **6.9%**。API 当前 12,699 Star、1,380 Fork；24h Fork 增量缺失。
- **活跃度与口径**：近 7 天 10 次提交、新 Issue 2、新 PR 4，仍在持续迭代。
- **爆发原因**：个人知识管理从“自动摘要”转向“保留来源、可追溯证据与本地所有权”，契合近期 Agent Memory 热点。
- **亮点**：普通文件格式、内容寻址的原始资料、claim/source ledger、单写入者事务设计，降低知识库被并发 Agent 写坏的风险。
- **潜在风险**：仍依赖用户正确配置 Agent 和网络出口；知识图谱质量受来源与抽取规则影响，不能替代备份和人工事实核验。
- **适合人群**：研究人员、知识工作者、Obsidian 用户、需要本地知识沉淀的研发团队。
- **值得关注程度**：**★★★★☆**。方法论完整，适合借鉴到团队级工程知识库。

1. **Agent 能力正在“包管理化”**：`andrej-karpathy-skills`、`ponytail` 与 `claude-plugins-community` 说明，开发者希望把行为规范、领域知识和工具集成封装成可安装组件。

## 最值得深入研究的 3 个项目

### 1. apache/maka

**理由**：不是又一个聊天界面，而是把模型消息、工具结果、权限决定和终止事件视作可恢复的执行事实。对于企业代码审查、Agent 审计、重放与事故复盘，这种追加式日志和统一 Runtime Host 很有参考价值；同时它有极高的近期提交与 PR 活跃度。

**建议验证**：权限决定是否可结构化查询；日志是否防篡改、可导出；敏感工具输出如何脱敏；分支与重放是否保持确定性；macOS 之外的支持路线。

### 2. anthropics/claude-plugins-community

**理由**：插件市场会放大 Agent 的分发效率，也会放大供应链风险。该项目的相对日增最高，适合作为研究插件清单、版本治理、权限声明、来源验证和企业准入流程的入口。

**建议验证**：插件审核标准、更新与撤回机制、权限透明度、恶意提示或依赖检测，以及组织内白名单和锁版本策略。

### 3. openai/codex

**理由**：周增 Star 与工程活跃度同时领先，且其沙箱、审批、MCP 与执行模型和代码审查场景直接相关。对比 Codex 与 Maka 的权限、日志、工具协议和企业身份边界，可以得到比单看功能更有价值的架构结论。

**建议验证**：MCP 服务权限隔离、命令审批粒度、会话上下文截断后的证据保留、自动化运行的失败恢复，以及团队审查策略如何编码为 Skills。
